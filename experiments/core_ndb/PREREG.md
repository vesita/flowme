## 1. 唯一要守住的形式（本实验核心，不改）

**NDB 的读写只在核编码阶段完成，且与「当前挂了哪些卡」无关。**

理由（照抄 §4 的论证）：若由**各卡**写入共享记忆 ⇒ 加一张卡会改变记忆内容 ⇒ 改变其它卡的读
⇒ 破坏中心不变量「加卡后老卡 pred/exact 逐位不变」（§15/§17 的 30/30）。

配套两条既有硬约束沿用：

- **表按输入 `reset`**，绝不跨请求残留（`mention_ndb` 的现有约束）；
- **键沿用 `mention_ndb` 的 token n-gram 哈希机制**（不另造键）。

阶段 2 才允许训练；阶段 1 **不训练**，门控一律保持初始化值（除判据明确要求的「非零门控对照」）。

## 2. 管线定义（本地实现，`experiments/core_ndb/`，不改 `src/`）

| 件 | 定法 |
|---|---|
| 键 | 借 `MentionNDB._keys` / `MentionNDB._ensure_flat` 两个方法（同一份代码，不复制）；`levels=(1,2)`、`slots=(8192,4096)`、`max_table_gb=0.25`（与 `ndb_semantic` / `ndb_ngram` 的默认逐字一致） |
| 表 | `_tab_cnt[B, Σslots, D]`、`_tab_tot[B, Σslots]`；`D` = 核隐维（128）。故意不注册 buffer：no_grad 数据统计量、不进 state_dict（沿用 `mention_ndb`） |
| 写在哪一步 | **核编码之后、任何卡运行之前**：每次 `predict()` 先对输入按句切段（输入侧常量 `chunk=64`、`max_len=128`，**不取自挂载卡的 spec**），逐段核编码并**只写不读**；写完关写，卡片阶段表**冻结** |
| 写的值 | 逐位置 `w = σ(write_gate(h)) · clamp(write_scale, min=0)`，`cnt[slot] += w·h`、`tot[slot] += w`；用 one-hot × `bmm` 聚合（无 atomics）；`mask=0` 的 padding 不写 |
| 读在哪一步 | 每段核编码之后（仍在核编码阶段，卡片解码之前）：`g = σ(read_gate([h, feat, w_t])) · clamp(read_scale, 0, 1)`，`out = h + mask · g · mass · (v − h)`，其中 `v` = 该位置 n-gram 槽内已写字向量的覆盖归一加权和，`mass = Σ_li α_li·covered_li`，`α = softmax(level_weight)` |
| 门控零初始化 | 总闸 `write_scale` / `read_scale` 是 **零初始化的标量 Parameter** ⇒ 起点贡献**恰为 0**；门控线性层的 bias 沿用 `mention_ndb` 的口径（write `+1` ⇒ σ≈0.73；read `−2` ⇒ σ≈0.12），权重零初始化（stage 2 的可训点） |
| 反面控制 | `card_write` 开关：卡解码出锚点后，把 `(提及起点, 该卡判的类)` 写进**同一张共享表**，值 = 该位置核隐 + 类原型 one-hot（`e_{class_id mod D}`），权重走同一个写门控。这是**故意做错的设计**，只为证明 G1 的约束不是空话 |

**为什么预编码切段必须是输入侧常量**：若核级写的切段/窗口取自挂载卡的 spec，挂 1 张卡 vs 挂 4 张卡
会产生不同的核级写入序列 ⇒ G1 从构造上就不可能成立。故 `PRE_CHUNK=64 / PRE_MAX_LEN=128` 是常量。

## 3. 测量口径（跑前写死）

- **文本集**：`experiments/core_keep/cache/person_6000.pkl` 按缓存顺序取**前 16 条 `spans` 非空**的样本
  的 `text`（不重排、不过滤长度）。缓存是只读复用（不写别的实验目录）。
- **卡集合**：`checkpoints/cards/` 的 4 张老卡 `person / pronoun / relation / sentiment`。
- **逐样本哈希**：`r = engine.predict(text, tasks=[card])` → 递归剥掉 `display` / `color` 两个键 →
  `json.dumps(obj, sort_keys=True, ensure_ascii=False)` → `sha256().hexdigest()`。
- **逐卡汇总**：该卡 16 条样本哈希按序拼接（`\n` 分隔）再 sha256。
  ⇒ 判据比较的是**逐卡汇总摘要**，同时记录逐条哈希列表以便定位第一条差异。
- **条件**（同一引擎切换开关，除 G1 的单卡引擎外）：

| 代号 | 记忆 | write_scale | read_scale | 卡写共享表 |
|---|---|---|---|---|
| `S0` 基线 | **关**（不预编码、不读，编码器直通） | — | — | 关 |
| `S1` 零门控 | 开 | 0 | 0 | 关 |
| `S2` 门控开（非空对照） | 开 | 1 | 1 | 关 |
| `S2r` 只读开 | 开 | 0 | 1 | 关 |
| `S3` 反面控制 | 开 | 1 | 1 | **开** |

- **前提 R0（可比性）**：同一条件连跑两遍，16×4 条哈希必须全等（ROCm 上若连跑都不复现，
  逐位判据无意义，G0/G1 一律记「未验证」而不是「通过」）。
- **单卡引擎**：`CoreNDBEngine(auto_attach=False)` 只 `attach` 那一张卡；与 4 卡引擎同 base、同常量。

## 4. 判据（门槛写死，跑完只填数字）

| # | 判据 | 门槛 |
|---|---|---|
| **R0** | 同条件重复跑，逐条哈希列表全等 | 16×4 全等（否则判据不可比） |
| **G0** | `S1`（零初始化门控）vs `S0`（完全不接记忆）：4 张卡的锚点序列逐位相同 | 4/4 卡的逐卡 sha256 相等 |
| **G1** | 与挂了哪些卡无关：4 卡引擎 `tasks=[c]` vs 只挂 `c` 的单卡引擎 `tasks=[c]`，同一张卡逐位不变 | 4/4 卡 sha256 相等（`S2` 门控开时判；`S1` 下同样复测作为附加） |
| **G2a** | 非空测试（判别力）：`S2` vs `S0` 记忆**确实改变了输出** | 每张卡 ≥1 条样本哈希不同（记录条数与结构变化条数） |
| **G2a′** | 空表对照：`S2r`（只读开、写关 ⇒ 表恒空）vs `S0` 必须仍逐位相同 | 4/4 卡 sha256 相等（证明「开读」本身不产生变化，变化只能来自写进去的内容） |
| **G2b** | 反面控制：`S3`（某张卡写共享表）vs `S2`，**老卡输出被改变** | person 之外 3 张卡各 ≥1 条样本哈希不同（记录被改变的锚点数） |

⇒ **G0 + G1 + G2a/G2a′/G2b 一起构成「门禁 + 判别力」**：只报 G0/G1 而没做 G2，视为**未验证**。
若 G2a 没差异，先判「文本集/键覆盖不产变化」，**不许**回头改门槛来凑通过。

附加观测（不设门槛，只记录）：`S0/S1/S2` 的单条 `predict` 平均耗时（预编码的额外代价）、
`stats()` 里的 `w_sum`（写入总权重，`S1` 必须恰为 0）、`delta_l1`（读带来的 doc_memory 改变量，`S1` 必须恰为 0）。
