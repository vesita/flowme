# PREREG_SCALE —— H7：卡片化的**第三条目标**（降显存 / 按需加载 ⇒ 等效提升参数量）

**本文件在跑之前写死；判据不因结果调整。**

## 0. 要回答什么

用户 2026-10-12 强调：卡片化的目标之一是**降低训练与推理的显存需求**，靠**动态加载卡片**等效提升参数量
（已写进设计真相源 [`MEME_FRAMEWORK.md §1.1`](../../MEME_FRAMEWORK.md)）。

**现有实测已把"天真版本"否掉**（数字的家：`PROJECT_STATE.md §6.2` / `L3_PLAN.md §12.7–§12.9、§19.1`）：

| 侧 | 已有读数 | 空白 |
|---|---|---|
| **训练** | 逐卡训练**省得极少**（峰值由**激活**主导）、且质量代价极大；**梯度检查点**才是真杠杆 | "在质量非劣门下的**可训参数量上界**"没测过 |
| **推理** | 顺序装载（=动态加载的离线等价）**保真逐位相同**、**驻留对 N 完全平坦**；★ **r7 也报了峰值**：顺序 424.9 MiB vs 整体图 426.5 MiB（N=4）⇒ **峰值几乎不降**；`等效参数量÷驻留` 只升到 **+23.8%**（N=4，fp32） | **峰值构成**随 batch/序列的**扫描**没做过；"在什么区间里才值"没定过 |

⇒ 本试验把第三条目标变成**账**：**主判据是参数量上界，不是 EM**。

## 1. 四个子问题（分级；先零训练）

| # | 问题 | 为什么必须问 |
|---|---|---|
| **Q0** | ~~推理侧动态加载的峰值~~ **已由 `L3_PLAN §19.1`（r7）回答**：驻留对 N 平坦、**峰值几乎不变**（顺序 424.9 vs 整体图 426.5 MiB）、params/MiB 只 +23.8% | 本项只做**复核**（换到当前 `model_zh_en` 栈上重测一次），不重复 r7 的结论 |
| **Q1** ★ | **峰值构成扫描**：同模型扫 `micro-batch × 序列长度`，实测"**激活 / (参数+优化器状态)**"比 | r7 只给了一个点（激活 ~89.7 / 驻留 99.7 MiB）⇒ 找出**"激活 ≪ 参数"的区间**才是这条目标能不能兑现的关键 |
| **Q2** ★ | **可训参数量上界**：`J 联合` / `P 逐卡` / `J+GC 联合+梯度检查点` 三条路径，各自在**质量非劣门**下能训的最大总参数量 | 这就是第三条目标的**主指标** |
| **Q3** | **等效倍率**：Q1 区间内，"卡片化能装的总参数 ÷ 单体同峰值能装"的倍率 | r7 的 +23.8% 是"同参数量加卡"的口径；换到"同峰值放大卡"口径要重测 |

## 2. 判据（写死）

| # | 判据 | 门槛 |
|---|---|---|
| **S1 质量非劣** | 每个规模点的质量 ≥ 基线 − **2pp** | 不过的点**不计入**"可训上界" |
| **S2 实测** | 上界至少 **3 个递增规模点**实测；外推只作附注并标"**外推**" | 必做（本项目的教训：外推当实测会骗人） |
| **S3 三件套** | 每个点报：**最大可训参数量** / **峰值显存** / **每步墙钟**（同构探针） | 必报 |
| **S4 双口径显存** | 显存同时用 `torch.cuda.max_memory_allocated()` **与**进程级峰值（cgroup / `rocm-smi`）两口径 | 必报（防"探针自己制造画像"） |
| **S5 Δ_min** | 质量差用配对 `2×SE_paired`；`\|Δ\| < Δ_min` 只许写"该口径下未测出差异" | 与 `methodology/measurement.md §3` 一致 |
| **失败出口** | 若**任意**配置下激活占比都 >80%（即"激活 ≪ 参数"在本机不可达）⇒ **如实写"第三条在 8G 上不可兑现"**，并给出所需硬件门槛 | **先写死这条出口**（这条负面结论本身很有价值） |

## 3. 分阶段（先便宜后贵）

- **Stage 0（零训练，~30 min）**：Q0 + Q1 —— 用现成 ckpt 测推理峰值；用真实训练步的**短跑（50 步）**测峰值构成。
- **Stage 1（~3–4 h）**：Q2 —— 3 个递增规模点 × 2 seed，只判"质量非劣 + 显存 + 墙钟"。
- **Stage 2（可选）**：Q3。

## 4. 边界与前置

- 本机 **8G / RX 6600**；结论**不外推**到别的硬件（要外推须另跑）。
- Q2 的"规模点"要改 `d` / 深度 ⇒ **先确认与 `MEME_FRAMEWORK §5.1`（卡内结构）不冲突**，并保证每点与基线同数据同调度。
- 与 H2（生成目标）、H6（结构化中间表示）**正交**：那两条优化**质量**，本轴优化**规模/显存**。

## 5. 交付形态

- 一份**显存账表**：三条路径 × 规模点 × {峰值、可训参数量、墙钟、质量、质量差±SE}；
- 一句话判词：**第三条目标在本机"可兑现 / 只能兑现到 X 倍 / 不可兑现"**（三选一，不许含糊）；
- ★ 同时给**每步墙钟**——否则"能训更大"会变成"慢到不能用"。
