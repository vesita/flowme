# H7 Stage 0：这台 8G 卡的显存都花在哪 —— **评测吃 5.9 GB，训练只吃 1.2 GB**

**一句话**：显存黑洞是"整批评测"，不是训练。把评测分块调小（`--eval-chunk`，默认已改成 64）立刻省约 4.5 GB。

## 读数

| 阶段 | 峰值 | 规律 |
|---|---|---|
| 模型（9.34M 参数） | 36 MiB | — |
| 训练一步 bs=8 / 16 / 32 | 408 / 661 / 1162 MiB | 线性：`≈ 155 + 32×batch` MiB ⇒ bs=32 时激活占 ~87% |
| **评测（2245 条，chunk=256）** | **5924 MiB** | 线性：`≈ 14 + 23×chunk` MiB（chunk=16 ⇒ 383 MiB） |
| 生成评测（greedy，n=20） | 210–260 MiB | — |

评测峰值是 bs=32 训练峰值的 5 倍。根源是 logits 张量形状 `(batch, 长度, 词表)`。
结果与 chunk 无关（已核：`chunk=64` 与 `16` 的 char / exact 逐位相同，CE 差 2e-09）。

## 对「卡片化第三条目标」的含义

- 参数只占训练峰值的 3%。**要让"按需加载卡"真正抬升参数量，前提是"参数远大于激活"** ——
  也就是更大的 d / 深度配更小的 micro-batch 加梯度累积；当前默认配置下达不到。
- 与 r7 一致：按需加载省**驻留**，不省**峰值**。
- 所以顺序是：先把评测分块降下来（免费省 ~4.5 GB），再谈加卡。
