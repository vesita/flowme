## 1. 做了什么

```
句子 x ──文本入卡 T_in ──▶ 模因 m_T [16,128] ─┐
                                              ├─▶ 共享文本出卡 Out ──▶ 逐字还原 x
同一句渲染成图 ──图片入卡 V_in ──▶ 模因 m_I [16,128] ─┘
L = CE(Out(T_in(x))) + CE(Out(V_in(render x))) + λ · D,  D = 1 − (1/16)Σ_p cos(m_T[p], m_I[p])
```

- **三张卡**（都从零初始化）：文本入 **1.98M** · 图片入 **1.02M** · 共享文本出 **2.63M** = **5.63M 参数**。
- **图片卡 = DETR 式**（CNN 主干 → 2 层 encoder → 16 个可学 query 的 decoder）；**文本卡同构** ⇒ 模态差异只在前端。
- **臂**：λ ∈ {0（对照）· 0.5（主）· 2.0} × seed ∈ {1234, 5678} = **6 run**，每 run **10000 步**、每 1000 步 held-out 快照。
- **数据**：`clean_v3/{wikipedia_cn,c4_zh}.txt` 各前 40 MB → 合格句（8–60 字、≥6 汉字、逐字可还原）→ 去重（剔 17125）→
  固定种子 shuffle → **train 20000 / held-out 2000**（70.1 万合格句里取）。
- **渲染**：Noto Sans CJK Regular（`b76b0433203017ca…`）24px、每行 ≤24 字、≤3 行、画布 **128×584** 灰度。

## 4. λ 阶梯：本试验最有信息量的一条

**剂量-反应关系（2 seed 一致）**：

1. **读图能力 ← λ**：图片路字准 67.9/24.2%（λ=0）→ **80.9/82.0%**（λ=0.5）→ 81.3/81.3%（λ=2.0）；
   置零消融增益同步从 **+53.7/+4.3pp** 升到 **+72…+74pp**（⇒ 图片路模因确实在承载内容，且 λ>0 时更稳、两 seed 一致）。
   ⇒ **λ=0 时图片路的读图能力对 seed 极不稳定**（67.9% vs 24.2%），λ>0 两 seed 收敛到同一水平。
2. **池化判别力 ← 反比于 λ**：Δ 从 **+0.2800 / +0.1331**（λ=0，两个 seed 都过 M1′ 且过 **M8 长度匹配**）塌到
   **+0.0020 / +0.0008**（λ>0，连 `Δ≥0.01` 的绝对下限都过不了）。
   原因看表 B2：λ>0 时**同内容余弦 = 0.9987–0.9996**、随机配对 = 0.9968–0.9989 ⇒
   **所有样本的池化模因几乎指向同一个方向**（分化度 0.19→0.10）。
   ⇒ 这是**表征坍缩（collapse）**，不是"两个模态不一致"。
3. **线性/CKA 对齐 ← 与 λ 无关，一直很高**：CKA Δ = +0.51…+0.76（对随机行置换零分布）、
   线性映射后 Δ = +0.77…+0.87 ⇒ **两个模态的模因始终落在同一个线性子空间里**；
   λ 改变的是**原始表征是否保留逐样本结构**，不是"是否共享空间"。
4. **逐槽对应关系在任何臂都没有建立**：M3（逐槽置换掉幅）6/6 不过；λ=0 的逐槽 Δ 本来就小（+0.038/+0.053）
   且**置换后不降反略升**（+0.0477）⇒ λ=0 的相似性来自**池化/线性结构**，不是槽序号对应。

**为什么"作废"是判据缺陷、不是测量失败**（复核 P1-8 在**跑前**就预告了这条通道）：

- M2′ 的定义是「**同模态·异内容**必须比**跨模态·同内容**低 ≥2SE」—— 它把**内容差**与**模态偏移**两个变量绑在一次比较里。
  λ=0 的实测：同模态异内容 cos = **0.4823 / 0.4464**，而跨模态同内容 cos = **0.2356 / −0.0297**
  ⇒ 文本-文本（异句）本来就比 文本-图片（同句）更像 ⇒ M2′ 判"无区分度"。
- 但**度量显然有区分度**：同一张跨模态矩阵的**行中心化 AUROC = 0.9850 / 0.7787**（零分布 0.5）⇒
  同内容配对的分数显著高于随机配对。**M2′ 的失败是它的基线选错（跨模态 vs 同模态的几何偏移未控），不是数据没信号。**
- 这与本项目已记录的三次"判据本身出错"同型（`AGENTS.md` §2：机会级/捷径级混写、模型侧尺度当数据侧尺度、位置依赖标签沿用不变性判据）
  ⇒ **按纪律：判据错 ≠ 数据错**，故本报告给出预注册判词（档 0b）**并同时**给出诊断，不改判据去救结果。

**另一条前置事实：6/6 run 未饱和** ⇒ 即便没有 M2′ 问题，顺序上也会落在 **档 4（未饱和 ⇒ 只报方向）**。

## 7. 诚实缺口与边界

1. **全部未饱和**（10000 步上限截断，无一个 run 触发收敛判据）⇒ 表 A/B 的所有数字**只是方向**，不是"平台读数"（R35）。
2. **没有 T vs M 对照**（模因直传 vs 文本中介）⇒ 本试验**不能**判 `§10.1` 的存续条件（PREREG §0 已写死）。
3. **共享输出卡本身就是耦合**：两条路的模因都必须被同一个出口解码 ⇒ "自然锚定"准确说是"**仅靠共享出口压力**下的锚定"。
4. **16 槽不是信息瓶颈**（订正 7 实测）：`16×128` fp32 = 65536 bits vs 每句 ≈420 bits ⇒ **84×**；"装不下表面"没被守住。
5. **语料只用两文件前 9.4% / 13.7%**（文件头偏置）⇒ 不可外推为"整个中文库"。
6. **V1 测的是"读图"**（同句渲染成图），不是"画面的语义接地"。
7. **M8 的负样本数随句长桶缩小**（平均 36.7 个伙伴）⇒ 它的 SE 比随机配对口径大，是**更保守**的门。
8. **独立复核**由**另一个模型**的只读单元完成（mimo-v2.6-flash ×2 会话），共抓出 **3 条 P0**（渲染裁切 / M3 口径 / 抽样二义）
   与 **4 条判词逻辑 bug**（G-read 不逐臂 / 地板门空接 / 正控作废未实现 / 无完备性门）⇒ **全部在出读数前修掉并留痕**（订正 4–10）。
   ★ 复核同时预告了 **M2′ 假失败**与**欠训误判**两条通道 —— 本试验**两条都真实发生了**。
9. **内容探针（跑后，`86b`）**：句长 R² = **0.946–0.992**（两路都几乎完美线性编码句长）；
   **首字 top-1 = 图片路 17.5–36.1%**（众数基线 **4.75%**，即 3.7–7.6×）⇒ **模因确实承载内容、不只是句长**；
   末字探针**退化**（test 集末字 100% 是「。」，因切句保留句末标点）⇒ **无效，已标注**。
