# REPORT_SEEDSTAB —— 诊断①：图片路"平台 / 逃出"的来源

> 规格与判据的唯一真相源 = [`PREREG_SEEDSTAB.md`](PREREG_SEEDSTAB.md)（**跑前写死**）。
> 本文件报**读数与判词**。运行日期 2026-10-11 上午；detr 主档形状；held-out 2000 句。

## 0. 一句话结论

> **H1（图片卡自身到不了）✅ 决定性成立 + H3（只是慢）✅ 成立 + H2（文本路拖累）❌ 且方向相反。**
>
> - **只图片路**（无文本路、无跨模态项）：**3/3 个 seed 都在 ~5000 步触发收敛判据停住，字准V = 22.45 / 22.49 / 23.67%**
>   （**极差仅 1.22pp**）⇒ 图片卡**自己**解不了这个任务，它稳定收敛在 ~23% 的平台。
> - **joint + infonce λ_nce=0.1 · s5678 · 20000 步**：10000 步 32.6% → **14000 步 49.2%**（起飞）→ **20000 步 70.8%**
>   ⇒ 同一个 seed 只是**逃出得晚**，不是学不会。
> - ⇒ **"图片路 seed 不稳"的机制 = 图片卡自身收敛在 ~23% 平台；能否"逃出"取决于它能否借到文本路的信号，
>   而借到的时机随机性极大（s1234 ~5000–6000 步、s5678 ~14000 步）。没有跨模态信号就永远逃不出。**
> - ★ 一处一致性检查：主档 **λ=0**（无显式对齐项）的 s5678 停在 **24.2%**，与"只图片路平台"（22.5–23.7%）**几乎重合**
>   ⇒ 它当时**根本没逃出**，只是停在自己的独训平台上；而它的 s1234 逃出了（67.9%）—— 靠的是共享出口带来的**隐式**耦合。

## 2. 判词（PREREG §3 的三条，逐条）

| 假设 | 判据 | 结果 |
|---|---|---|
| **H1 图片卡自身** | ① 出现"部分 seed 仍卡在 ≤30%" | ✅ **成立（3/3 都 ≤30%，且极差 1.2pp）** |
| **H2 与文本路共适应（原表述：竞争/拖累）** | ① 三 seed 都 ≥50% 且极差 ≤10pp | ❌ **不成立** —— 且**方向相反**：文本路的存在是**逃出的必要条件**（去掉它，三个 seed 全部锁死在 ~23%） |
| **H3 只是慢** | ② 20000 步内越过 50% | ✅ **成立**（14000 步 49.2% → 15000 步 52.4%） |

★ **H2 的方向订正（旧新都报）**：预注册里的 H2 写的是"共享出口先被文本路塑形 ⇒ **拖累**图片卡"。
实测显示文本路**帮助**图片卡（跨模态项 = 把已训好的文本卡当**老师**，给图片卡一个"够得着且可解码"的目标）
⇒ 准确表述应为「**H2′：文本路是逃出平台的手段（跨模态蒸馏），不是障碍**」。
（这是我这一系列第 4 次把判据/框架的方向写偏；前三次：M3 口径、P3 漏文本路、M2′ 基线选错。）

## 3. 这对"锚定 v0 / 冻结 IO / 解冻 IO"意味着什么

1. **锚定的上游必须先把图片路弄到可用**：图片路**靠自己到不了**（~23% 平台，3 seed 一致）。
   ⇒ 若现在锚定，冻进去的图片通道只能还原约 1/4 的字 ⇒ **只能锚定文本路，或先修图片路**。
2. **"逃出"要靠信号，不能靠运气**：joint 里逃出时机差异很大（5000 vs 14000 步）。
   ⇒ 要稳定，就得**主动给老师信号**（更强的对齐/蒸馏、或分阶段：**先训好文本路 → 以它为目标训图片路**）。
   这正是用户 §31「分阶段」直觉的**可操作形态**。
3. ★ **对 `§4.1` 第③段（解冻 IO）的一条注意事项**：**解冻必须带耦合项** ——
   否则按臂① 的结果，图片路会在没有老师信号时**退回 ~23% 平台**。
4. **跨模态相似度判据本身不受影响**：这些 run 的 Δ池化 在 20000 步内稳定在 +0.62…+0.67（s5678），
   与 10000 步的同配置（+0.6705）一致 ⇒ 锚定判据的口径是稳的，**不稳的是图片路的可训性**。

## 4. 诚实缺口

1. 臂① 是**收敛判据停下的平台**，不是"证明的最优"（CE_V 仍在缓慢下降）；
2. 臂① n=3、臂② n=1；步数 5000/20000 都**不代表饱和**；
3. 单一语料 / 单字体 / 单 MV / detr 单档；**没有**"给图片卡加容量/加分辨率"的对照臂
   ⇒ **不能**断言平台是"CNN 容量"造成的还是"渲染分辨率"造成的（只知它**不是**由文本路竞争造成的）；
4. 本诊断**不改**任何既有判据（M1′/M8/M3/Q1–Q4），也**不产出**新的模因版本。
