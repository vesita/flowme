# 预注册：reply_pick 失败诊断 —— 冻结基座是不是元凶

## 已实测的失败
`train_task_card.py --card reply_pick`（**冻结基座** + 新头，12 epoch / 1800 步，batch 64，2 层）：
```
cls_acc 0.1844（机会水平 1/5 = 0.20）  span_hit 0.0160  bg_fp 0.7228
exact_match 0.0517  slice_precision 0.0064  slice_recall 0.0060
```
`cls_acc` 贴机会水平、`span_hit` 近 0、`bg_fp` 72% ⇒ **判定为「没学会」**，不是"差一点"。
注意：数据集本身已核验无误（负例分档、位置分布 {1:1282,2:1259,3:1252,4:1307} 已打散、
切片用 0-based 半开与数据契约一致）。

## 假设
同一模式在 negation 卡上已实测过：**冻结基座 0.6383 vs 联合训练 0.9667**（dev-notes/12 §12.5）。
选择任务的输入是「问句 + 4 条候选」（max_len 128），远离基座受训过的 64 / 120 窗口，
且要求"比较候选"这种基座从未被训练过的能力 ⇒ **冻结基座可能根本不含该任务所需的表征**。

## 本臂
`training/train_multitask.py --tasks reply_pick --seed 42 --epochs 16`（**联合训练，基座可训**），
其余超参尽量与失败臂对齐（batch 64；注意联合脚本的 steps/epoch 由数据量决定，如实报差异）。

## 判据（跑前写死）
- **P1**：`exact_match` **≥ 0.60**（可用的选择卡应明显高于 person 的 0.32）。
- **P2**：`bg_fp` **≤ 10%**（失败臂是 72.3%）。
- **P3**：**锚点完全命中率 ≥ 95%**（锚点要喂下游组合算子）。
- **P4**：报**按候选位置的准确率**（max−min ≤ 10pt）与盲猜基线 **20%**，确认不是位置偏置。
- 判定：
  - P1 过 ⇒ 冻结基座是元凶，选择族的正确训练口径是联合训练；后续按此重训两张卡。
  - **P1 不过 ⇒ 如实判「选择族在当前基座 + 该预算下不成立」**，并给出已排除的原因清单
    （数据已核验 / 位置已打散 / 不是单纯的步数问题），不得为了好看挑口径。
- 单 seed 只作方向；定论需第二 seed。
