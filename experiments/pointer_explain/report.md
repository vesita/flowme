## 1. 结构化记录字段 + 不可得清单 + 适配器只读取数

字段（PREREG §2 写死）：`kind:"pointer"` / `chosen[{cid,card,span,span_text,score,score_provenance,rank,score_rank,eligible}]` /
`candidates[同形 + emission_index,class_name,pos,ineligible_reason]` / `scores_kind` / `ref_map[{unit_id,cls:"content",text,ref,span,out}]` /
`evidence`（既有记录逐字原样）/ `unavailable[]`。**`chosen` 是列表**：一条指针记录每个入选位一条。
**`rank`（选择序）= 位表序（情绪→否定→人称→人物）→ 卡内发射序**（`anchors[0]`，真实入选规则）；**`score_rank`（分数序）= score 降序**，不是入选依据。
`ref_map` 内容宇宙 = **全部候选 span**（个个逐字回溯输入）；另加断言：L1 解释内容 ⊆ chosen。

**不可得字段（留空 + 标"不可得"，不编）**：`chosen.score_original`（原跑未持久化 confidence，只能重放取回 ⇒ 标 `provenance=replay`）×12；
`L2 理由` ×12；`差异事实`（同卡无对照候选）×11；另有 `cards_run/plan`（重放取回）、
**negation 入选切片的 `pos`**（`pipeline.type_pos`→`None`，`card_flow.type_of` 给「否」∉ 官方 `POS_TYPES={名,动,形}`）×6 条记录 ⇒ 不入受约束槽。

**适配器只读取数**：输入 = `gen_dispatch/results_all.json` 的 `pointer_examples` 12 条（`card_flow/results_real.json` 实测**指针记录 0 条**）；
额外只读两样 —— `pipeline.propose`（CPU 重放拿候选 + confidence）、`pipeline.execute`（拿 `cards_run`），
与既有 `evidence/text/terminal/plan_step_id` 逐字对账后才进记录；`src/`、`experiments/{explain_card,gen_dispatch,card_flow}/` 一字未改。

**判定：B —— 指针输出只能给机械层、给不出理由**（R0=12/12>0 ∧ R1=0 ∧ R2=0 ∧ R3 漏 0 ∧ R4 崩，但 **R6=1.0 ≥ 2/3**，阈值跑前写死）。

**机制（实测）**：L1 是"重算一遍"而非"生成一句话"——候选/序/分数全是数据，重算是纯函数，所以可核对到 0 不一致；L2 的四条路各自死在**不同**的谓词上：
类名字面死在 `rule_a`（`积极/愤怒` 是实义词，必须进槽不许当字面）、因果字面死在 `word_face`（`因为` 要求逐字出现在输入）、
差异字面死在 `rule_a`（`比/高` 不是形式词）、纯复述 `「X」。` **C1 全过 12/12 却 C2 全败 0/12**（不含任何"为什么是它而不是候选 2"的差异事实）。
**反例最硬的一条**：唯一可构造的 A2 差异句，其事实本身在记录里重算为**假**（0.9963 < 0.9994）——
分数差一个候选就反号，**把分数写进理由等于编**。这与 `skeleton_leak`（选择对最小对不敏感）和 `counterfactual`（结构扰动弱于随机字符）两个既有警告同向。
