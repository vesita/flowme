# P19 训练附录·澄清 2（写于 **R2 启动之前**，mtime 见文件）

## 0. 本条写之前新测到的事实（实测，改变了 R2 的配方）

**`eval_S` 的文本 100% 落在重训用的训练集里**（实测，`logs/` 里的重叠检查输出）：

| 检查 | 结果 |
|---|---|
| `build_negation_dataset(8000, DEFAULT_SEED=20240927)`（R1/R2 的训练数据） 与 `eval_S` 文本集合交集 | **600/600 = 1.0000**（s42 与 s43 都是） |
| `build_negation_dataset(6000, DEFAULT_SEED)` 与 `capability_map/cache/negation_ordered_s*.pkl` | **集合完全相同**（`set == set` 实测 True） |
| 旧卡 `compose_ops/artifacts/cards/negation.pt`（来自 `arm_neg5_seed42`，`task_samples.negation = 6000`） | 其训练数据 = 同一个 6000 集合 ⇒ **eval_S 同样在它训练数据里** |

⇒ **这个 benchmark 对所有卡（旧卡、现成卡、新训卡）都是 in-sample 口径**；本单元**不改口径**（沿用 P15/P16 同一批 eval 文件），
但必须如实标注：**F1 的 M_cls 是「与既有卡同口径的在线指标」，不是泛化指标**（泛化另见 `s6_holdout.py` 披露项）。

## 1. 因此 R2 配方再改一次（**在 R2 启动之前**；判据一字未改）

| | PREREG_TRAIN §2 原写 | 澄清 1 改成 | **本条（最终）** |
|---|---|---|---|
| R2 | `samples 32000 / epochs 16 / steps 300`（4800 步） | `samples 32000 / epochs 40 / steps 150`（6000 步） | **`samples 8000 / epochs 80 / steps 150`（12000 步）** |

- **为什么放弃「4 倍数据」**：上表实测 eval_S ⊂ 训练集；把数据从 8000 扩到 32000 而**步数不变** ⇒ 每条 eval 样本被看到的次数掉到 1/4，
  而 F1 恰好量的就是这些样本 ⇒ **这个自变量会同时改变「见过 eval 样本多少次」，归因不干净**。
- **R2 最终定义（单变量）**：**数据、头规格、lr、batch 全与 R1 逐字相同**，只把训练步数 **6000 → 12000**（`--epochs 80`）。
  意图 = 排除「没训够」这一条（R1 结束时 loss 仍在降，余错是漏检 9/9 + 误报 6/1，属欠拟合形态）。
- **诚实标注**：这是**在看到 R1 结果之后的第二次配方修订**，两次都落盘在 R2 启动之前、都写明理由；
  **F0–F5 判据、≥.98 门槛、选卡规则（只用训练 seed 42 的卡）、停止规则全部一字未改**。

## 2. 停止规则（不再变）

R2（训练 seed 42 的卡）在 eval s42/s43 上 M_cls 仍有一 < .98 ⇒ **F1 不达标 ⇒ 判「无法修复」**，
**不再加配方、不再改步数、不再换优化器**；报告里如实写 R1/R2 全部数字与 in-sample 口径这一限制。
