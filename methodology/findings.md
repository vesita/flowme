## A. 加卡 / 联合训练

### 温启动联合（从已收敛的冻结卡出发）不伤老卡，老卡反而全面提升
- **为什么**：老卡的增益来自核被重新训练，而不是头续训 —— `J3`（四老头 `requires_grad` 全 False、一步没训）老卡仍 **+12.09 / +11.78pt**。
- **怎么用**：补一张新卡走「核可训 + 老头冻结」的温启动联合（J3 口径），不要为了"保护老卡"而绕开改核。
- **证据**：多 seed 实测（2 seed）＋ `dev-notes/15:601`、`dev-notes/15:619-623`；代价表 `dev-notes/15:645-647`。
- **边界/反例**：**前提是温启动**。同配方下"从随机初始化一起训"是另一回事（见下条）；本结论只测到 3 步加卡、5~7 卡规模。

### 老卡增益的主效应是"又一轮联合训练"本身，与加了哪张卡关系不大
- **为什么**：增益集中在第 1 步（sentiment +12.41 / +11.81），而"单独只加一张卡"的对照同样 **+11.5~12.3pt**；后两步只是高位震荡，核在第 1 步就已经不再"窄"。
- **怎么用**：**不要**为"攒够几张卡再联合训"而等待 —— 加一张卡时顺手做一轮温启动联合即可拿到主要收益。
- **证据**：多 seed 实测（3 步 × 2 seed）＋ `dev-notes/15:765`、`dev-notes/15:768`。
- **边界/反例**：这是"增量"的读法；**不表示**多卡联合无价值（见"多任务只不窄化"条）。

### 伤老卡的真凶是"从头联合"，不是"改核"（从头联合 −8~−16pt）
- **为什么**：同配方、同数据、同 1344 步、**只差初始化** —— 随机初始化下 sentiment **−8.38 / −11.13pt**、relation **−16.53 / −4.59pt**；温启动下同两格为 **+12.28 / +11.75** 与 **+2.92 / +2.78**。
- **怎么用**：凡是看到"联合训练伤老卡"的旧结论，先查它的初始化口径；`dev-notes/12`/早期实验的"改核伤老卡"要在**温启动**口径下重判。
- **证据**：多 seed 实测（2 seed，受控对照）＋ `dev-notes/15:615-623`。
- **边界/反例**：只差"初始化"一个变量，其余全同；不适用于"随机初始化本来就该用"的冷启动场景。

### 蒸馏 / replay 在温启动联合下是负资产
- **为什么**：λ 阶梯（s42）λ = 0/1/4/16 ⇒ sentiment Δ **+12.28 / +8.81 / +5.97 / +3.63pt**、negation **0.9800 / 0.9650 / 0.9333 / 0.9033** —— 它把老卡往**基线**拉，而基线本就低于联合训练能达到的水平。
- **怎么用**：不要为"保护老卡"加 KD/replay；温启动联合本身已是增益来源。
- **证据**：单次实测（**λ 阶梯只有 s42**）＋ `dev-notes/15:633-637`；"从头"分支的 `J1c` vs N5 两 seed 不同号 `dev-notes/15:637-639`。
- **边界/反例**：单 seed，强度上限就是单次实测；原文明确记了这条遗留。

### 核漂移随加卡步数**减速累积**（不是线性、更不是爆炸）
- **为什么**：每步相对位移稳定在 0.10~0.11，但**方向与既有漂移不共线** ⇒ 累积距离次线性。
- **怎么用**：把 `‖core−base‖F/‖base‖F` 当常规监控量；看到"逐卡 +0.21 GB / +0.03 s·step⁻¹ 线性增长"属正常，不是失控。
- **证据**：多 seed 实测（两 seed 同号且几乎相同）＋ `dev-notes/15:749-751`；代价线性化 `dev-notes/15:755-757`。
- **边界/反例**：只测到 3 步；`person` 贴地板、`idiom` 自身带宽 6.17pt ⇒ 这两卡的 P1 证据含金量低（`dev-notes/15:774-776`）。

### 三步连加 30/30 不退化 ⇒ 加卡流程可反复用
- **为什么**：P1「超过**各自**噪声带」的违例数 = 0（**逐卡用各自带宽，未用统一阈值**）；新卡四格全部 ≥ 单独温启动联合的 90%（101% / 100% / 95.7% / 100%）。
- **怎么用**：连续加卡可按「每步温启动 + 老头冻结 + step-0 逐位门禁」直接推进。
- **证据**：多 seed 实测（3 步 × 2 seed）＋ `dev-notes/15:742-744`。
- **边界/反例**：**双侧读法不过** —— 违规格全是"提升超带"（sentiment 六步全超），无一格下降超带（`dev-notes/15:759`）；只有 3 步，`ownership` 没有第 4 步观察。

## B. 通用性 / 表示上限

### 多任务联合训练的价值是"不把核训窄"，**不是**"让核更通用"
- **为什么**：C3/C5 相对**未训练的 B0** 全落在 δ 内（idiom δ = 7.67pt）⇒ 在该分辨率下**未测出**通用性提升；而单任务核把通用性训掉的效应**显著超过**噪声尺度。
- **怎么用**：**别指望"多补几张卡"换来能力上限提升**；要提升上限只能动表示本身。
- **证据**：多 seed 实测（2 seed；C1x5 仅 s42）＋ `dev-notes/15:699-703`、`dev-notes/15:716`；方案侧的引用 `dev-notes/16:23`。
- **边界/反例**：这是"落在 δ 内 = 没测出差异"，**不是**"证明多任务无通用性收益"；原文明确写了"卡数与数据量仍未完全解耦"的遗留（`dev-notes/15:722-725`）。

### 单任务训核把通用性训掉：迁移掉 6.7~22.7pt，关键变量是漂移的**方向**而非大小
- **为什么**：C1 相对 B0 **−12.17 / −6.67pt**、C1x5 **−22.67pt**；而 C1 与 C5 的核漂移量几乎相同（0.1110 vs 0.1087）迁移却差 **12.8pt** ⇒ "核动了多少"解释不了任何事。
- **怎么用**：判断"核被拽走没有"要看**迁移 hold-out 上的净变化**，不要看 `‖Δ核‖`。
- **证据**：多 seed 实测（部分单 seed：C1x5 只有 s42）＋ `dev-notes/15:692-703`。
- **边界/反例**：hold-out 只有 2 个且**都属 tagging 族**，selection 族无证据（`dev-notes/15:724`）。

### 能力边界：4/5 能力**冻结核就够**，只有 negation 需要改核
- **为什么**：冻结核 + 头在 pronoun/sentiment/relation/person 上 ≥ 联合训练；只有 negation 的 cls 0.887/0.877 vs 联合 1.000/0.987。
- **怎么用**：这四张能力按「冻结核 + 按模块挂载」直接加卡，零损伤已证到**逐位**；把 negation 当"核级更新"的唯一靶子。
- **证据**：多 seed 实测（2 seed，`align_all_ok = True`）＋ `dev-notes/15:307-314`、`dev-notes/15:356-358`。
- **边界/反例**：筛查指标 `达成率=(旁路−冻结)/(联合−冻结)` 的"联合=上限"假定被实测推翻（5 个里 4 个分母 ≤ 0）⇒ P1 形式判定是**证据不足**（`dev-notes/15:291-305`）。

### 便宜的先验筛查（线性探针）判不了"加卡要不要动核"
- **为什么**：探针对**绝对水平**排序很稳（ρ = +0.90 / +1.00），对**旁路增量**排序是**反的**（ρ = −0.90 / −0.90）—— 因为"探针分数高"与"分母小"是同一件事的两个投影，不是独立信息。
- **怎么用**：要判断"某能力能否加在冻结核上"，**直接测该任务的冻结-联合差**（成本就是训一次），不要靠探针。
- **证据**：实测（n=5，post-hoc ρ）＋ `dev-notes/15:328-336`、`dev-notes/15:359-361`。
- **边界/反例**：n=5 时 ρ 很粗，原文只记"有方向性信号，不足以当筛查用"（`dev-notes/15:349-353`）。

## C. 元决策与输出侧不变量（**均为否证**）

### 模型判不了"输入是什么类型" ⇒ 输入类型由调用方显式声明
- **为什么**：分布内 **0.9167** → 对抗集 **0.2978**（掉 62pt，且**低于**多数类基线 0.60）；21 个阈值里没有一个能让 P1∧P2∧P3 同时成立。
- **怎么用**：`type` / 调用计划在**接口层**强制由调用方声明，模型侧不做类型判定。
- **证据**：多 seed 实测（2 seed）＋ `dev-notes/15:143-168`；naive 对照构造 `dev-notes/15:151-152`。
- **边界/反例**：只测了 5 类分类头（mean-pool + 零初始化逻辑回归）这一种实现。

### 三次元决策（路由 / 类型 / 拒答）**同病**：分布外全部失效
- **为什么**：路由对抗集 9.19%、输入类型 29.78%、拒答分布外 **~96% 开火**（分布内 ~0% 误报）—— 靠的都是**表面标记**。
- **怎么用**：**元决策一律不交给模型**；由显式规则 / 调用方声明决定"用哪张卡、算不算分布外"。
- **证据**：多 seed 实测（路由/类型 2 seed；拒答为纯推理单次）＋ `dev-notes/15:552-557`。
- **边界/反例**：拒答那条的形式判定是"证据不足"，实质判定是"不成立"，**两处口径必须一起读**（`dev-notes/15:494-496`）。

### 输出侧三条不变量（拒答 / 闭合性 / 可溯源）当前不成立；只有确定性成立
- **为什么**：拒答 = 分布外照样开火（8 档阈值扫描无一能让 5 卡同时过 P1∧P3）；闭合性 = 锚点 12 键、组合产物丢来源；可溯源 = `predict` 顶层参数全缺。确定性 = 6786 样本跑两遍逐样本 sha256 **0 不一致**。
- **怎么用**：任何新输出卡必须把这三条**写进代码并加门禁**，不能指望输出头自己在分布外闭嘴。
- **证据**：单次实测（纯推理，未训练）＋ `dev-notes/15:471-545`；清单引用 `dev-notes/16:1230-1235`。
- **边界/反例**：**不要**读成"这三条做不到" —— 原文只说"当前不成立 / 未实现"，没有否证可能性。

### 选择族（`reply_pick` / `cloze_fill`）与盲猜不可区分 ⇒ 这条路径不可用
- **为什么**：`reply_pick` 20%（≈盲猜）、`cloze_fill` 19%；加上 A/B 两族在"换说法"子集上都 ≈50% ⇒ **四次独立测量指向同一堵墙**（原文限定：这是**核冻结**条件下的观测，见下条）。
- **怎么用**：不能靠"从候选里挑最合适的回复"产出回复；拼接式生成的数据必须改成"从原文/上游输出里抽片段"。
- **证据**：多 seed 实测（多实验交叉）＋ `dev-notes/16:679-681`、`dev-notes/16:25`。
- **边界/反例**：**必须与"冻结核"那条连读** —— 同一批测量在核可训后离开 50%（下条）。

### 冻结核是所有语义等价测量 ≈50% 的原因；核可训后 49.5 → 59.4 / 63.2
- **为什么**：唯一变量 = 核是否可训（同数据、同步数、同 mean-pool、同 seed）⇒ `heldout_pair` 49.52/51.04 → **59.36/63.20**（Δ/SE +6.96 / +8.60），`shifted_pos` 92.56/92.48 → **99.60**；2×2 交互表里**只有「核可训 ∧ 标签为真」离开 50%**。
- **怎么用**：遇到"语义等价判不了"这类结论，先查**核是否冻结**；温启动联合本来就是"让核参与训练"的机制。
- **证据**：配对实测（同 seed、同批 1250 条配对差；4 条门禁全过；2 seed）＋ `dev-notes/16:730-749`。
- **边界/反例**：**59~63% 距可用仍远**，这是「**必要条件的证据**」不是解决；只重测了 mean-pool 臂 A；机制归因强度只到"中"（缺"只让核学 select、不给老任务"那一档）—— `dev-notes/16:751-766`。

## D. 记忆（NDB）的层级

### 核级 NDB 走"身份绑定"这条路**判负**，比卡级低 46pt
- **为什么**：身份 id 由**解码器的查询态**算出，核没有指针头 ⇒ 搬到核级后解码器失去能消费的身份信号，person 掉回已知 36% 基线。
- **怎么用**：**记忆留在卡级**；长输入漏标用「卡级记忆 + 分段策略」修，不靠核级。
- **证据**：多 seed 实测（四次训练完成，两 seed 同号）＋ `dev-notes/16:456-473`。
- **边界/反例**：C 臂是「核级**替代**卡级」，不是「核级 + 卡级」⇒ 它**只**证明"对身份绑定而言正确层级是卡"，**没有**测"核级作为表示连续性"有没有用（`dev-notes/16:467-470`）。

### 卡级 NDB 把 `repeat_mention_acc` 从 36% 做到 83%，但当前没有一张上线卡在用
- **为什么**：卡级 L 臂 0.8266 / 0.8307 vs 核级 C 臂 0.3627 / 0.3572；而 `dev-notes/17` P4 实测**当前 4 张挂卡全是 `ndb=False`**。
- **怎么用**：先把**已验证有效**的卡级 NDB 打开，再谈往上层搬记忆。
- **证据**：多 seed 实测（2 seed）＋ `dev-notes/16:476-480`。
- **边界/反例**：代价口径见 `dev-notes/11:18`（+264 参数 / +34% 步时 / +30MB，3 seed）；开启前先确认 reset 作用域（`dev-notes/17:136-140`）。
