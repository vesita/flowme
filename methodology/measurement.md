# measurement —— 测量准绳：量怎么取、口径怎么对、代理量的陷阱

> 每条四行：**为什么 / 怎么用 / 证据 / 边界**。证据强度与引用缩写见 [`README.md`](./README.md)。
> 全局红线：**「没测出差异」不许写成「没有效果」** —— 本文件每条都按原文口径措辞。

---

## 1. 逐卡噪声带：**禁止用统一阈值**

### 每张卡判"退化没有"要用**它自己的**噪声带：pronoun 2.83 / relation 1.39 / sentiment 0.41 / person 0.33 pt
- **为什么**：4 卡同配置同数据**仅换 seed**（42 vs 43）就差这么多 ⇒ **噪声带是分卡不同的**，最大可达 ~2.8pt；统一 2pt 阈值会同时"放过 pronoun 的退化"与"冤枉 sentiment 的提升"。
- **怎么用**：写判据时逐卡列出带宽；报告里写「**是否超出该卡自己的噪声带**」，不写一个统一阈值；优先用**多 seed 配对**。
- **证据**：多 seed 实测（2 seed 仅换 seed 的配对差）＋ `dev-notes/12:494-499`；判据实例 `dev-notes/15:100`；执行实例 `dev-notes/15:742`（"逐卡用各自带宽，未用统一阈值"）。
- **边界/反例**：带宽只覆盖**这一台机器、这一份数据、这个步数**；`idiom` 自身两 seed 就差 6.17pt、`person` 贴地板 ⇒ 这两格的证据含金量低（`dev-notes/15:774-776`）。

## 2. δ 的算法

### δ = max(2pt, 该判据所用集合上两 seed 的极差)，**逐集合各算、不共用**
- **为什么**：2pt 是**下限**（防极差恰好为 0 时判据形同虚设）；极差是**该集合真实噪声**的直接读数，共用一个 δ 会把噪声大的集合判松、噪声小的判紧。
- **怎么用**：每开一个新判据先算 δ 并写进 PREREG；在 hold-out 上用 **B0（base 核）两个头 seed 的 exact 极差**（核恒定 ⇒ 极差量的是纯头训练噪声），同一 δ 用于该 hold-out 的所有比较，**不逐臂调**。
- **证据**：规范（跑前写死，多实验一致）＋ `experiments/core_generalize/REPORT.md:69`、`experiments/value_card/PREREG.md:112`、`experiments/anchored_select/PREREG.md:60`；实例 `dev-notes/15:688`（idiom δ = 7.67pt、ownership δ = 2.00pt 被下限兜住）。
- **边界/反例**：δ 被下限钉住时，**判据的实际分辨率就是 2pt**，比真实噪声粗 ⇒ 见下条。

## 3. 分辨率 vs 效应量

### 过线余量低于该样本量的分辨率 ⇒ 「字面通过」但**判别力不足**，诚实判定是「证据不足」
- **为什么**：n=600 的单 seed 分辨率约 **±3.6pt**；当 δ 被 2pt 下限钉住而实测余量只有 +0.5pt 时，**"过线"里没有任何信息**。
- **怎么用**：下结论前先算 `余量 / SE`；把门槛写成「**余量 > 2×SE**」，或先扩容对抗集再判。
- **证据**：单次实测（含自我更正留痕）＋ `dev-notes/16:642-645`。
- **边界/反例**：**不要**反过来把"余量大"当成机制证据 —— 余量只说明可分辨，不说明原因（同文件 §5.6 的机制归因只给到"中"，`dev-notes/16:751-766`）。

## 4. 「逐位一致」的口径

### 加卡门禁的「逐位」必须写明是 **pred/exact 逐位**，不是 logits 逐位
- **为什么**：实测 30 组起点门禁里 **4/30 只有 logits 字节摘要不同**（都是上一步刚训的新卡），pred/exact 仍逐位 ⇒ **ROCm 前向有 ~1e-6 级跨进程非确定性**。
- **怎么用**：门禁比 `engine.predict` 的逐样本 sha256 / pred / exact；**logits 只做量级对账（如 1e-6 内 allclose）**，不拿它当等价判据。live 编码 vs 缓存的差异要单独报（max|Δ| = 3.144e-06）。
- **证据**：多 seed 实测（2 seed × 6 步 × 4 卡）＋ `dev-notes/15:753-757`；`experiments/select_semantic_joint/REPORT.md:25`。
- **边界/反例**：**logits 逐位相同**在同进程同批下是能拿到的（自检用），但**跨进程**不要承诺；把"逐位"写成 logits 逐位会让门禁出现假失败。

## 5. step-0 门禁要**实测 sha256**，不许声明

### 温启动联合的 step-0 必须实测「与不接本任务配置逐卡逐样本 sha256 相同」，不许靠代码审阅声明
- **为什么**：step-0 是"之后任何变化都可归因于训练"的唯一前提；声明不带证据 ⇒ 后面整条归因链都悬空。
- **怎么用**：每开一档新配置先跑 R4/G0 类门禁，把 sha256 原值写进 REPORT；**跨步/跨档起点门禁要成组比较并报 PASS 数**。
- **证据**：多 seed 实测（两 seed）＋ `experiments/select_semantic_joint/REPORT.md:83`、`experiments/core_update_probe/REPORT.md:20`、`dev-notes/16:739`、`dev-notes/15:753-754`（链上 6 步 30 组比较全 PASS、7 次 `SELFTEST_init` Δ=0.000e+00）。
- **边界/反例**：sha256 只对**同一 JSON 序列化口径**有意义（`sort_keys=True`、`ensure_ascii=False`，见 `experiments/core_ndb/PREREG.md:48-49`）；换序列化方式哈希必变，不算回归。

## 6. 探针同构

### 计时 / 显存 / 梯度探针必须与真实负载同构，并用「逐步 / 单跑 / unit 三处咬合」自证
- **为什么**：不同构的探针会报出**真实场景里不存在的量**；报出的量与要下的结论不同口径，结论就是假的。
- **怎么用**：探针复用主臂的前向与数据路径（**只读 import、不另写前向**）；跑完报三个独立口径的互证 —— 逐步累计 vs 单跑 vs 整个 unit 墙钟，差异 <5% 才算咬合；梯度/更新探针还要与主臂逐步 loss 对账。
- **证据**：多点实测 ＋ `dev-notes/16:770-771`（457.7s vs 476.5s = 4.0%；unit 32min9.5s vs 32.00min）、`experiments/select_semantic_joint/REPORT.md:31`、`experiments/core_grad_probe/REPORT.md:7`（对账 Δ≤3.8e-07）、`experiments/core_update_probe/REPORT.md:13`（`both` 臂与主臂真实 `opt.step()` 逐位相同）、`experiments/ndb_recheck/REPORT.md:49`（空壳检验两次逐位复现训练 `AB_METRICS`）。
- **边界/反例**：咬合只证明"**报出的是同一个程序**"，不证明探针**答对了问题** —— 见下条与 [`experiment-design.md`](./experiment-design.md) 的捷径检查。

## 7. 空结果 / 空测试的归因力

### 空结果能不能当结论，取决于**协变量是否到位**：先证明「门真的开了、对照真的能测出差别」
- **为什么**：同一个"没测到收益"，可能是**机制无收益**，也可能只是**门没开 / eval 节奏不同 / 检查本身是空的** —— 三者在数据上长得一模一样。
- **怎么用**：下"无收益"结论前先补齐三件协变量证据：① **非空测试**（强制打开机制，检查必须真能测出干扰）；② **协变量登记**（eval 节奏、并跑负载这类会改轨迹的量要记下来并复跑验证）；③ **判别力核算**（余量 vs 分辨率）。三条缺一 ⇒ 只能写「证据不足」。
- **证据**：实测（三次不同实验）＋ `experiments/core_ndb/RESULTS.md:95-98`（400 步时 `read_scale=0.0024`、相对扰动 4e-7 ⇒ **"门没开"而不是"记忆无益"**，遂单列 `--lr-gate`，门槛一字未动）、`experiments/core_branch/REPORT.md:68`（0.005 差 = 训练中途评估扰动轨迹，**eval 节奏是协变量**，非分支引入）、`experiments/additivity/REPORT.md:46-47`（强制开闸后不同样本数 410/600… ⇒ **一致性检查不是空检查**）、`dev-notes/16:642-645`（字面通过但判别力不足）。
- **边界/反例**：协变量补齐**之后**仍无差异，才可以写"该口径下未测出差异"；**依旧不许写成"没有效果"** —— 前者是测量结论，后者是机制结论。

## 8. 证据口径与措辞

### 单 seed 只允许报「下降超过已实测噪声带」这类结论；定论只用**多 seed 配对**
- **为什么**：单 seed 分不开"效应"与"轨道差"；本项目已有两处反例 —— 双 seed 极差只有 2 点算出、余量仅 0.0075。
- **怎么用**：写结论时标注强度；只跑了一个 seed 就写"超出噪声带 X pt"，不写"可靠提升/可靠退化"。
- **证据**：规范＋实测 ＋ `dev-notes/12:387-388`、`dev-notes/12:292`、`experiments/ndb_recheck/REPORT.md:61`。
- **边界/反例**：配对差即使只有 2 seed，也比独立两跑强（同 seed、同批 eval 样本）；**配对 SE 要报"未算"而不是拿独立 SE 顶替**（`dev-notes/16:764-766`）。

### 报出的量必须与要下的结论**同口径**：损失占比 ≠ 梯度占比 ≠ 更新占比
- **为什么**：`train = 100%` 反证了"select 信号被淹没"的读法；"老任务占 0.99999"是**损失值占比**，拿它去设计"给老任务降权"就是拿错口径的代理量驱动配方改动。
- **怎么用**：先写下"我要下的结论是什么"，再挑**能推出该结论的那个量**（要判"谁在塑造参数"就看方向与净改变量，见本文件末尾迁移正文 §11）；不同口径的数各报各的，不互相替代。
- **证据**：多点实测 ＋ `dev-notes/16:776-778`、`dev-notes/16:808-831`（AdamW 更新口径实测）、`dev-notes/16` §11.4（迁移正文末尾）。
- **边界/反例**：原始梯度范数**不是没用** —— 它回答"传进来多少"，只是不回答"改变了多少"。

## 9. OOD / 代理探针的交叉验证

### 一个 OOD 集不足以判定「是不是捷径」，探针结论必须**多载体交叉**
- **为什么**：同一能力换一套 OOD 载体，结论会翻面 —— sentiment 在 `probe_units` 上 **+14pt（成立）**、在 `compose60` 上 **−36.0/−35.4pt（语体捷径）**，两 seed 同号。
- **怎么用**：写"某能力已具备 / 有捷径"之前，至少跑两套构造不同的 OOD 载体；两套结论相反时如实写"两套相反"，不选边。
- **证据**：多 seed 实测（2 seed）＋ `dev-notes/15:316-326`。
- **边界/反例**：多载体交叉仍**不等于**机制解释 —— `dev-notes/15:328-337` 说明探针对"绝对水平"排序稳、对"增量"排序反，代理量本身就是死结。

## 11. 测量纪律：Adam 下怎么判断「哪个损失在塑造共享参数」

### 11.1 一条代数事实（不是发现，是一行推导）

Adam 更新逐坐标做 `m̂/(√v̂+ε)`。**从空状态出发的第一步**（`m=(1−β₁)g`、`v=(1−β₂)g²`）：

```
m̂_i/√v̂_i = (1−β₁)/sqrt(1−β₂) · g_i/|g_i| = 常数 · sign(g_i)      （g_i ≠ 0）
```

⇒ **每个非零坐标贡献同样大小（只差正负）、零坐标贡献 0**，于是两个梯度源的总范数之比是：

```
‖m/√v‖_sel / ‖m/√v‖_old = sqrt(nnz_sel / nnz_old)
```

实测吻合（`experiments/core_update_probe/`）：**0.973377768027 vs 0.973377768033（~0.2%）**。

**文献状态（分层，别混）**：

| 层 | 状态 |
|---|---|
| Adam 第一步 = sign-SGD（只剩正负号） | ✅ **标准** —— Balles & Hennig《[Dissecting Adam: The Sign, Magnitude and Variance of Stochastic Gradients](https://export.arxiv.org/pdf/1705.07774)》就是拆这三样 |
| Adam 对梯度整体缩放不变 | ✅ 标准 |
| 逐坐标归一化 ⇒ 更新范数随"活跃坐标数"增长 | ✅ 概念上常见 |
| **「两个梯度源的 `‖m/√v‖` 比 = sqrt(nnz 比)」这个具体命题** | ⚠️ **未见到被单独提出的论文**；但它**不需要**论文 —— 把第一步写开就得到 |

⇒ **这不是"新结论"；价值全在下一条纪律。**

### 11.2 纪律（四条，按对本项目的实用性排序）

**① 不许用 `‖g‖` 或 `‖m/√v‖` 判「哪个损失在主导」。**
在 Adam 下，**更新范数由「支持集大小」决定，不由「任务重要性」决定**。
⇒ 要判主导只能看**方向与净改变量**：`cos(Δθ_both, Δθ_i)`、以及该源被抹掉后的相对改变 `rel`。

**② 「调 λ 平衡任务」在 Adam 下比直觉弱得多。**
缩放不变 + clip/Adam 两层归一化 ⇒ 把一个 loss 乘常数，对**方向**近乎无效、对**量级**常被重新归一化掉。
⇒ **杠杆在方向/几何（投影、正交化、按参数子集分治），不在权重。**
（多任务文献里针对同一直觉的对照设置见《[Challenging Common Assumptions in Multi-task Learning](https://ar5iv.labs.arxiv.org/html/2311.04698v3)》中的 "Equal weighting using Adam" vs "with scalings"。）

**③ 有效步长 ≈ `lr · sqrt(nnz_active)`。**
⇒ **活跃坐标越多，总步长越大**；这解释了高维稠密参数（如 embedding）为何需要更小的 lr。

**④ 本项目推论：改「共享参数集合 / 方向 / 联合方式」，而不是给某个任务降权。**
（对应可动的设计：让 select 只塑造指定的层；或改交替而非同批；而不是调 λ。）

### 11.3 本条的实测依据（数字在 §5.6，此处只记结论）

- 原始范数比 **74×~3081×**（「被淹没」）vs 更新口径 **≈1×**（「同量级」）
  ⇒ **两个数都不是"谁重要"的答案**；
- 唯一稳定的判据是**方向**：`cos(both, old)` = **0.970 / 0.996 / 1.000** ⇒ **方向由老任务主导**；
- `select` 的**净改变量随训练单调衰减**（`rel` 0.24 → 0.09 → 0.0095）。

### 11.4 为什么值得单独写

**它挡住了一个具体错误动作**：若照"原始梯度被淹没"去**给老任务降权**，
就是**拿一个在 Adam 下不成立的代理量去驱动配方改动** —— 且按 ② 该改动可能近乎无效、还会扰乱已成立的不变量。
⇒ 与全局纪律一致：**别用代理量替代目标量；报出的量必须与要下的结论同口径。**
