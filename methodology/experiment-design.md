# experiment-design —— 实验设计准绳：判据、捷径检查、订正留痕、归因

> 四行格式与引用缩写见 [`README.md`](./README.md)。
> 这里的每条**都是被某次真实失败逼出来的**，"证据"栏会同时给出**规范出处**与**踩坑出处**。

## 1. 数据有效性（捷径检查）

### 任何朴素规则在**训练集**上 ≥90% ⇒ 该轮数据**无效**，如实报，不改判据迁就
- **为什么**：标签若能被一条零训练的表层规则判出，模型学到的就不是任务，是构造痕迹 —— 这已**三次**直接杀死一轮数据。
- **怎么用**：开跑前把"朴素规则"**逐条写死**（逐字子串 / 类别是否规范名 / 是否词表词 / 是否含标点 / 长度 / 候选在输入中的位置 / 类别名字符串集合，每条取 `max(规则, 规则取反)` 的最优方向）；**真值源重实现单列**，不作判据但必须报出。
- **证据**：规范（跑前写死）＋三次实测 ＋ `experiments/gen_data_loop/PREREG.md:150`、`experiments/select_rerank/PREREG.md:64`、`dev-notes/16:1031`。
  实测四例：`anchored_select` train/test 朴素规则 **1.00**（卡 0.60~0.69 连这条平凡规则都没学会）`dev-notes/16:609-613`；
  `value_card` 朴素规则 train/test **1.0000**、adv 0.0000 `experiments/value_card/REPORT.md:37`、`:47`；
  `select_rerank` S 臂逐字 **1.0000**（N 臂 0.5000 ⇒ `clean_train_rule_ge_90 = false`）`experiments/select_rerank/REPORT.md:23`；
  `gen_data_loop` 提案臂 train `lex_member` **0.797**、natural `lex_member` **0.765** `experiments/gen_data_loop/PREREG_PHASE2.md:25` 与 `data/stats.json`。
- **边界/反例**：**只卡训练集** —— 对抗集上朴素规则塌到 ≈0.5 是设计目标，不是违规；"真值源的重实现"不是捷径（否则本项目任何规则标注的数据集都不可能过）。

### 结果表**每一格都必须并列 `max_naive`**，并写出「卡 − max_naive」
- **为什么**：只报"卡过线"而不报"免费规则多少"，会掩盖"卡输给一条词表规则"这个死法（`anchored_select` 卡 0.69 vs 免费 1.00）。
- **怎么用**：主表每格并列该集的 `max_naive`（规则名 + 读数）与差值；**卡低于该集 `max_naive` 就如实写「未超过免费规则」**，不许因为另一条判据过了就淡化。评测脚本**独立复算**朴素规则与 `stats.json` 对账，不一致直接退出。
- **证据**：规范（PREREG 硬要求，跑前追加）＋ `experiments/gen_data_loop/PREREG_PHASE2.md:115-130`；实例 `dev-notes/16:1072-1075`（P 臂 natural 卡 0.705/0.715 vs `lex_member` 0.765 ⇒ 结论只能写"相对多数类、相对注入式可用"）。
- **边界/反例**：`max_naive` **按集各算**，不跨集共用（natural 的规则与 test 的规则可以不同）。

### 随机标签对照**必做、真执行**；若随机标签臂也过判据 ⇒ 判据恒真、整轮作废
- **为什么**：没有随机标签对照，判据可能对"标签内容"不敏感 —— 分不清模型是学了任务还是学了数据形状。
- **怎么用**：shuf 臂用**同配方**重训（标签整体 randperm），报告里并列；同时保留**空洞对照**（打乱标签 / 随机特征）核对机会水平。
- **证据**：规范＋实测 ＋ `experiments/gen_data_loop/PREREG_PHASE2.md:113`（V-bonus）、`experiments/value_card/REPORT.md:34-45`（shuf 臂同配方）、`dev-notes/15:162`（空洞对照 0.164/0.118、0.224/0.164 vs 机会水平 0.20）、`dev-notes/16:958`。
- **边界/反例**：随机标签臂**过线只说明判据失效**，不说明数据无效 —— 两种结论要分开写。

## 2. 判据的写法与订正

### 判据错 ≠ 数据错：前者**透明订正 + 留痕 + 两个数字都报**，后者判**数据无效**
- **为什么**：把"判据口径写错"当成"数据塌缩"（或反过来）会导致完全不同的处置 —— 前者该改判据并留痕，后者该废数据重造。
- **怎么用**：先回答"失败的是**判据**还是**数据**"，再动手：
  **判据错** ⇒ 订正写进 PREREG、**注明理由与时间**、**原判据 ❌ 与新判据 ✅ 两个数字都报**，**不得只报新判据**；
  **数据错** ⇒ 判该轮数据无效、重造，不迁就判据。
- **证据**：实测（两次对照的自我更正）＋ `dev-notes/16:1038-1058`（D6 → D6′：distinct 0.238 vs 注入臂 1.0 惩罚了让路成立的性质；订正 21:19 CST **早于首训 21:25**）；反例 `dev-notes/16:1057`（A 族 / 价值卡那两次是**数据错**）。
- **边界/反例**：订正**必须在看到结论性数据之前**完成并留时间戳；跑完再改判据 = 事后调参，一律不算。

### 凡"不许变差"类判据，**跑前写清单侧还是双侧**
- **为什么**：写 `|Δ| ≤ band` 是在暗中要求"**也不许变好**" —— `core_keep` 派活时这么写，结果 sentiment/relation 的**提升**反而被判违规。
- **怎么用**：写 `Δ ≥ −band`（单侧，只罚退化）；若确实要双侧，就明确写双侧并接受"提升也违规"。**错误在派活措辞时就要认**，执行方按字面实现不算错。
- **证据**：实测（判据订正留痕）＋ `dev-notes/15:559-569`；后果实例 `dev-notes/15:591-593`、`dev-notes/15:762`（双侧读法违规格全是"提升超带"）。
- **边界/反例**：两种读法要**并列报**，且**以字面读法为准**；补出来的"本意读法"证据地位低于字面读法。

### 预注册落盘必须**早于首训**；落盘后只许往 RESULTS 追加数字，**不许回头改阈值**
- **为什么**：判据在看到数据之后再改，任何"过线"都失去意义。
- **怎么用**：PREREG 写死落盘时间，REPORT 里同时给出"落盘时间 < 首训时间"的证据；跑中唯一允许补写的机器文件（如 `bands.json`）要把**公式先写死、只留数值后填**。
- **证据**：规范（多实验一致执行）＋ `experiments/core_keep/PREREG.md:3-4`、`experiments/core_generalize/PREREG.md:3`、`experiments/cumulative_add/PREREG.md:3-5`、`experiments/out_invariants/PREREG.md:3`。
- **边界/反例**：**判据可以订正**（见上条），但订正要留痕、要两个数字都报、要在看到结论性数据之前 —— "不许改"指的是**不许为过线而改**。

## 3. 门禁与自检

### 空测试自检**三条缺一条结论作废**；并配一条**非空测试**证明检查真有判别力
- **为什么**：只有"没测到差异"而没有"检查真能测出差异"，空测试是空的。
- **怎么用**：每跑必打印 ① 生效后的可训参数量（冻结实况逐个数字）② 零初值 = 冻结基线（`max|Δ| = 0.000e+00`）③ 训后机制真在干活（关闸/开闸的指标差）；再加**强制打开机制**的敏感性对照，报出"不同样本数"。
- **证据**：规范＋实测 ＋ `experiments/additivity/PREREG.md:44`、`experiments/capability_map/PREREG.md:85`、`experiments/core_branch/PREREG.md:58`；非空测试实例 `experiments/additivity/REPORT.md:46-47`（强制开闸后不同样本 410/600、2369/3200…）、`experiments/core_ndb/PREREG.md:74`（G2a 每卡 ≥1 条哈希不同）。
- **边界/反例**：空测试通过**只说明管道没坏**，不说明结论成立；它不能替代判据本身。

### 「要求初始化时无副作用」的门禁，必须同时回答「**它之后怎么被学起来**」
- **为什么**：读写门控都零初始化 ⇒ 梯度死锁（读贡献为 0、写拿不到梯度），实测 `write=+1.00000(g=+0.000e+00)`、8 个 epoch 尺度精确为 0 ⇒ **看起来"机制无收益"，实际是"门没开"**。
- **怎么用**：设计零副作用起点时同步给出可学路径（记满不读 / 投影 / 单列 `--lr-gate`）；发现"没收益"先量门控的实际值与梯度，再下结论。**改实现不许动门槛**，且要重跑并逐位复算诊断数与 sha256。
- **证据**：实测 ＋ `dev-notes/16:428-435`、`experiments/core_ndb/RESULTS.md:95-101`（400 步 `read_scale=0.0024`、相对扰动 4e-7 ⇒ "门没开"而非"记忆无益"；改在任何 P1/P2/P3 评测之前，门槛一个字没动）。
- **边界/反例**：step-0 输出贡献**仍必须恰为 0**（零副作用这条不能放松）；放松它换可学性 = 换了另一个问题。

## 4. 归因

### 归因靠「**只差一个变量**」的受控对照；混合变量的结论一律降级
- **为什么**：同配方、同数据、同 1344 步、**只差初始化**，才把"改核伤老卡"的真凶定位成"从头联合"；不控变量的对比只能说"相关"。
- **怎么用**：写结论前先列出"这个对照到底哪几个量不同"；三个可观测量都大动时（如参数 ×11.3、步时 ×134、显存 ×24）要**证明变的确实只有目标变量**（例如冻核跑同一循环 ⇒ 打分头 `torch.equal = True`）；分不开就写"归因 = 中/低"，并列出**唯一能把归因推到"强"的那档实验**。
- **证据**：多 seed 实测 ＋ `dev-notes/15:615-623`（真凶对照）、`dev-notes/16:768-770`（自变量核查）、`dev-notes/16:772-775`（置信度分级：R0/R1/R2 = 强、机制归因 = 中）。
- **边界/反例**：**受控对照也不等于机制** —— 它排除了竞争解释，但没证明因果路径；本项目"增益来自核参与 select"至今只到"中"，缺口是"只让核学 select、不给老任务"那一档（`dev-notes/16:773`、`dev-notes/16:835`）。

### 测"能力"时必须把**不同的机制分开报**，否则结论归因不到问题在哪一层
- **为什么**：A 族（共享编码 + 发射锚点）与 B 族（候选独立编码 + 重排头）是两种不同绑定方式；A 失败**不等于** B 会失败，把两者的数字混在一张表里，"能力不存在"就无从判起。
- **怎么用**：每个实验先标清自己属于哪一族；**只有过线时才可归因**，不过线时必须补同族对照，否则如实写"归因混淆"。
- **证据**：实测（含结论被推翻的两次自我更正）＋ `dev-notes/16:593-596`；`dev-notes/16:715-720`（"四次实测都指向表示层"被推翻）、`dev-notes/16:745-749`（墙在"核冻着"，不在表示）。
- **边界/反例**：机制分开**不等于**可以挑有利的那族报 —— 两族都要报，判定按预注册字面给。

### 静默截断必须用「逐样本实际编码」的守卫抓，**断言比未截断的 `text` 抓不到**
- **为什么**：卡声明 `max_len=96` 而 tokenizer 静默截断 ⇒ 超长样本的「候选：」被切掉、**标签随之失效**；而构建期断言比的是未截断文本，全部通过。
- **怎么用**：训练前逐样本实际 encode 并断言未被截断，**报出丢弃条数**；不要用"构建期断言通过"替代。
- **证据**：实测风险登记 ＋ `dev-notes/16:601-608`、`dev-notes/17:481-513`（P9 无标点超长段静默截断、尾部不可标注）；执行实例 `experiments/select_rerank/REPORT.md:21`（截断守卫，ctx/cand 丢弃 **0**）。
- **边界/反例**：截断本身**允许存在**（要报丢弃数），不允许的是"标签失效却不报"。

### 语料「文件顺序」会把代码/英文排在前面 ⇒ **不许按顺序取前 N 个文件当"中文语料"**
- **为什么**：`corpus.resolve_corpus_files()` 是 **fail-closed**（没文件就报错），但它**只保证"有文件"、不保证"是中文自然句"**；而返回顺序里 `code_alpaca_dialogue.txt`（首 3 行汉字数 **0 / 0 / 0**）排在最前，`gsm8k_cot_dialogue.txt` 汉字占比仅 **5.9%** ⇒ **按顺序取前 N 个文件的下游会静默吃到代码与英文**。
- **怎么用**：① 取语料时**显式按语言/性质过滤**（如汉字占比阈值），**不许依赖文件顺序**；② 每个划分**报出语言构成**；③ **抽样打印真句看一眼** —— 本次就是靠这一步发现的。
- **证据**：实测（2026-10-07，`uv run python` + `corpus.resolve_corpus_files()`）：**18 个** `*_dialogue.txt` / 11,484,611 行；按 汉字占比 ≥50% 过滤后 **16** 个 / 11,231,795 行（丢 2 个文件 / 252,816 行 = **2.2%**）。逐文件构成见 `dev-notes/19-语料清单与语言构成（防文件顺序陷阱）.md`；`fs[:3]` = `code_alpaca_dialogue.txt`（首 3 行汉字数 **0/0/0**）/ `coig_code_dialogue.txt` / `coig_cqia_dialogue.txt`。
- **边界/反例**：语料整体**主要是中文对话**（多数文件 74%~86%）⇒ 问题**不在"语料是代码"**，而在**"取法按顺序"**。

### 端到端"零幻觉"的**弱版本（逐字子串）会给出虚假安全感** ⇒ 必须升级为「内容回溯到**被筛为有效的候选**」
- **为什么**：字符串包含检查**可以完全通过而输出毫无意义** —— 本次实测 **20/20 全通过校验**（片段确实是输入的逐字子串），但输出**全部语义错误**，且 **0 条拒答**。
- **怎么用**：把"零幻觉"从**子串检查**升级为**结构检查**（`dev-notes/16` §7.7 / §7.9 的 G2 / G3：内容单元必须回溯到**被筛为有效的候选**，并**留存引用映射**）。
- **证据**：实测（2026-10-07，`dialogue.respond(type_='plain')` + sentiment/negation 卡，真实语料抽 20 句）：**20/20 `kind=text`、无一条 `reject`**。典型输出 —— `total_price = 0.0` → 「你这句话里的『**ric**』表达了积极」；`# Example usage` → 「『**xample**』表达了积极；并且有否定成分『#』」；`def __str__(self):` → 「『**f __str__(**』表达了积极」。
- **边界/反例**：这不是"卡太弱"单独造成的 —— **同样的片段在形式上完全合规**。所以**判据本身必须换**：只换卡、不改判据，同类错误仍会漏。
