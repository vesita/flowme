# methodology —— DTSeek 的结论 / 规律 / 准绳

> 面向**未来的维护者**：这个项目已经**确证了什么**、做测量时**必须守什么**、哪些坑**已经踩过**。
> 这里**不放实验流水账** —— 流水账在 `dev-notes/` 与 `experiments/*/REPORT.md`，本目录只写**条目 + 指针**。

## 0. 硬规矩（写之前先读）

1. **每条必须可追溯**：给出 `文件:行` 或实验产物路径。找不到出处的**不许写**（宁可少一条）。
2. **一个事实只有一个家**：长段落**不搬家**，这里只写「一句可当规则用的陈述 + 指针」。
   **唯一例外**：`dev-notes/16` §11「测量纪律」原本就是为跨文档写的，其正文已整体迁到
   [`measurement.md`](./measurement.md) 末尾的「迁移正文」，`dev-notes/16` 原位置只留 2 行指针。
3. **必须标注证据强度**，且：
   > **「没测出差异」≠「没有效果」。** 凡原文写的是「落在 δ 内」「低于分辨率」「证据不足」，
   > 本目录**照抄这个口径**，不许改写成「没有作用 / 无效」。

## 1. 证据强度分级

| 标签 | 含义 |
|---|---|
| **多 seed 实测** | ≥2 个 seed 同号（或同结论），且结论不依赖单个 seed |
| **配对实测** | 同 seed、同一批 eval 样本上的配对差（比独立二项 SE 更紧） |
| **单次实测** | 单跑 / 单 seed，只能当方向或"超出噪声"级别的证据 |
| **文档事实** | 读代码 + 只读探针得到，带 `文件:行`（见 `dev-notes/17` 的三级证据标注） |
| **推断** | 由实测或代码推出，**本次没有直接测** |
| **规范** | 跑前写死的纪律 / PREREG 条款，**本身不是测量结果**；条目里会写清"被哪次实测逼出来" |

## 2. 条目格式

每条一个小节，四行：

```
### <一句陈述（要能当规则用）>
- **为什么**：<机制/原因，一两句>
- **怎么用**：<具体动作，可执行>
- **证据**：<强度>＋<出处 file:line / 产物路径>
- **边界/反例**：<什么时候不适用>
```

## 4. 引用缩写（本目录统一使用）

`文件:行` 里的短名对应关系：

| 缩写 | 实际路径 |
|---|---|
| `dev-notes/12:495` | `dev-notes/12-下一阶段方案：基座通用性、容量体检与卡片自动决策.md` 第 495 行 |
| `dev-notes/15:100` | `dev-notes/15-模块组合架构：能力可加性是这条路的判据.md` 第 100 行 |
| `dev-notes/16:992` | `dev-notes/16-语言输出卡：生成型输出、证据锚点与显式调度（方案框架）.md` 第 992 行 |
| `dev-notes/17:9` | `dev-notes/17-模块运行机理.md` 第 9 行 |

其余路径（`experiments/...`、`.gitignore`）一律写全相对路径。
**行号以本目录创建时的仓库状态为准**；被改动后请以 `grep` 重新定位，不要照抄。

## 5. 维护方式

- 新增条目：**先找到 `文件:行`**，再按格式写；找不到出处 → 写进报告的「未纳入」，不写进本目录。
- 与原文冲突时：**原文为准**，本目录只负责"可检索"，不负责"最新裁决"。
- 本目录**只描述已发生的事实与已写死的纪律**，不写路线图、不写"以后要做什么"。
