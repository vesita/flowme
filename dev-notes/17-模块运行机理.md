## 1. 认知核 `src/dtseek/encoder/nano_doc_encoder.py`

### 1.1 运行过程

1. 输入是 `input_ids [B, L]`（字符 token id）+ 可选 `attention_mask [B, L]`；输出 `doc_memory [B, L, D]`【事实 `nano_doc_encoder.py:236-243`】。
2. token 与字符 **1:1**：`len(ids) == len(text)`，逐字符 decode 0 处不一致【实测 P5】—— 所以 `doc_memory` 的第 i 行就是原文第 i 个字符。
3. `d = hidden_dim`（默认 128）、层数 `num_layers`（默认 3）、头数 `num_heads`（默认 4）【事实 `:211-214, :223-227`】。
4. 当前产物实测：`d=128 / 3 层 / 4 头 / head_dim=32 / SwiGLU hidden=384 / 全模型 1.6885M 参数`【实测 P15】。
5. `max_len` 是构造参数（代码默认 512，`:212`），**真正生效的上限由产物 `encoder_kwargs` 决定**，当前 ckpt 是 **128**【事实 `artifacts.py:58-63`；实测 P1】。
6. 超长输入在本模块**不切也不截**：`L > max_len` 直接 `raise ValueError`，报错文案点名让调用方用 segmenter【事实 `:244-247`】。
7. **切段责任在调用方**：`MultiTaskEngine.predict` 用 `split_with_global_offsets` 切，再按 `spec.max_len` tokenize【事实 `engine.py:253-259, :152`】。
8. 引擎路径**永远走不到**那个 `ValueError`：`tokenizer.encode(..., max_length=spec.max_len)` 先把输入截到 ≤128，而 `spec.max_len` 被强制在 8..128【事实 `engine.py:152` + `plugin.py:207-208`；实测 P9】。
9. 前向顺序：embedding → 每层 `RMSNorm → 注意力 → 残差 → RMSNorm → SwiGLU → 残差` → 末尾 `RMSNorm`【事实 `:195-197, :260-263`】。
10. 注意力是**双向**的（`is_causal=False`），带 RoPE + QK-Norm + SDPA【事实 `:171-178, :163-169`】。
11. RoPE 的 cos/sin 表按当前实际 `L` 切片使用，表长就是 `max_len`【事实 `:252-253`；实测 `rope_cos (128, 32)`】。
12. 推理侧加载后 `eval()` 且 `requires_grad_(False)` —— 基座永远冻结【事实 `artifacts.py:65-67`；实测 P15 `requires_grad 全 False = True`】。

### 1.2 什么时候失效 / 退化

1. **绕过 tokenizer 直调** + `L > max_len` → 抛 `ValueError`，有测试守卫（`tests/test_nano_doc_encoder.py:82-88`：「超长应抛错而不是静默截断」）【事实】。
2. **引擎路径的超长是静默的**：`encode` 内部 `ids[:max_length]` 截断【事实 `/home/vesita/coding/my/nano-char-tokenizer/src/nano_char_tokenizer/__init__.py:31`】。实测 300 字无标点段：sentiment 只编码前 64 字、person 只编码前 120 字，**尾部 236 / 180 个字符在指针可达范围之外、永远标不到**【实测 P9】。
3. 静默截断还制造**坐标口径错位**：引擎用 `L = len(segment_text)`（300）钳制指针、归一化位置也除以 300，而指针 logits 长度只有 64/120【事实 `engine.py:155, :192-193, :225-226`；实测 P9】。
4. `attention_mask=None` 时 padding 位会参与注意力（`attn_mask` 直接为 `None`）【事实 `:255-258`】；引擎恒传 mask（`engine.py:154, :176`），所以这条只在裸调用时成立。
5. `encoder_kwargs` 与权重形状不符 → `load_state_dict` 抛错（fail-closed）【事实 `artifacts.py:64`】。
6. `max_len` 的位置表是硬上限，超过它没有 RoPE 可切 → 上限被产物锁死，卡的 `max_len` 再大也没用【推断：由 `:232-234` 的定长 buffer 与 `plugin.py:207-208` 的 8..128 校验共同推出】。

## 2. 切片发射解码器 `src/dtseek/decoder/robust_ar_model.py`

### 2.1 运行过程

1. query 序列**初始**是可学参数 `bos_query [1, 1, D]`（「开始发射第 1 个切片」）【事实 `:22`；engine 侧 `engine.py:167` clone，训练侧 `runtime.py:135` expand】。
2. 每步**追加一个 token**：`feedback_proj([上一步隐状态, 类别嵌入, 位置投射])`，其中位置是归一化的 `[start, end]`【事实 `:54-67, :29-35`】。
3. 推理时喂的类别/位置是**模型自己上一步的预测**【事实 `engine.py:222-227`】；训练时喂的是**真值**（教师强制）【事实 `runtime.py:161-167`】。
4. 每步发射 **四组**：`cls_logits [B, C]`、`start_logits [B, L]`、`end_logits [B, L]`、`action_logits [B, 2]`，外带 `last_hidden [B, 1, D]`【事实 `:106-111`】。
5. 起止是双指针点积：`Linear(last_h)` 与 `doc_memory` 逐位点积再除 `sqrt(D)`【事实 `:94-98`】。
6. `doc_mask` 之外的位置在指针 logits 上填 `-1e4`，padding 不会被指到【事实 `:100-102`；engine 传 mask：`engine.py:176`】。
7. 每步按当前 `step_len` 重算下三角因果掩码 —— query 只能回顾已发射的历史【事实 `:80, :82-87`】。
8. `action_head` 是 2 分类 `0=<eos> / 1=<cont>`，**不是 token**；本模块没有 eos 符号【事实 `:52, :104`】。
9. **终止发生在 engine 而非本模块**，四条出口：类别 0 → break（`engine.py:187-188`）；重复区间 → break（`engine.py:195-196`）；`action==0` → break（`engine.py:219-220`）；`for step in range(spec.max_steps)` 跑完自然结束（`engine.py:175`）。
10. `max_steps` 的定义是「**单个句段**最多发射几个切片」，成对任务必须为偶数【事实 `plugin.py:115-116, :209-210`】。
11. 「一条输出多个切片」= 同一段内循环：`q_seq` 每轮长 1，直到上面四条出口之一；锚点数 ≤ `max_steps`【事实 `engine.py:175-228`】。
12. 实测（同一句 42 字）：sentiment 1 步就 `action=0` 收束、relation 2 步出 2 个锚点、person 跑到第 5 步因**重复区间 (11,11)** 停机但只留 4 个锚点【实测 P7】。
13. query 长度实测逐轮 `1 → 2 → 3 → 4 → 5`【实测 P7】。
14. 成对任务的 `pair_index/pair_side` 是 engine **在全部锚点上按全局序号硬贴**的（`i//2`），本模块不知道配对【事实 `engine.py:272-275`】。

### 2.2 什么时候失效 / 退化

1. **训练/推理口径差（exposure bias）**：训练喂真值、推理喂自己的预测【事实 `runtime.py:161-167` vs `engine.py:222-227`；「误差会累积」是【推断】】。
2. **重复区间即停**：模型一旦重复发射同一 `(s0,e0)`，本轮后面的真实切片全部丢弃【事实 `engine.py:195-196`；实测 P7 第 5 步即此】。
3. **背景句只靠第 0 步收束**：第 0 步 `cls==0` 就 break，段内一个锚点都没有【事实 `engine.py:187-188`】。
4. **`max_steps` 是召回上限**：默认 `annotate_all=False` 时超出部分被数据集静默截断（`spans[:max_steps]`，`runtime.py:65`）；`annotate_all=True` 时改成响亮抛错（`runtime.py:59-64`，person 卡就是 True：`builtin/person/__init__.py:52`）。
5. **成对任务的奇数发射没有运行期防护**：engine 照贴 `pair_index`，会产出「半个词对」；奇偶只在评估里作为 `pair_odd` 报出来【事实 `engine.py:272-275` vs `runtime.py:334-338`】。
6. **指针长度与段文本长度可以不等**：段被 tokenizer 截断时，指针只能覆盖前缀，engine 的 `min(L-1, ...)` 钳制救不回来（见 §1.2 第 2、3 条）【事实 `engine.py:192-193`】。
7. `hidden_dim` / `num_classes` 由 ckpt 的 `decoder_kwargs` + spec 快照重建，与代码声明不一致会在 `check_ckpt_specs` 被拦下【事实 `artifacts.py:109-117` + `plugin.py:389-436`】。

## 3. 提及检索记忆 `src/dtseek/decoder/mention_ndb.py`

### 3.1 运行过程

1. **键**：提及起始位置 `p` 处、**向前**取 n-gram（`tokens[p:p+n]`）的多项式滚动哈希再 `% slots`，级数 `(1, 2)`（首字 / 双字前缀）【事实 `:237-252`】。
2. 键在**文档级只算一次**并缓存成 `_flat [B, L, nlev]`，缓存按 `input_ids` 的**对象身份**作废【事实 `:254-269`】。
3. **值**：`_tab_cnt [B, Σslots, C]`（加权计数）+ `_tab_tot [B, Σslots]`（加权总量），全部零初始化【事实 `:132-133, :208-209`】。
4. **写**：`w = σ(write_gate(h)) · valid`，只在 `label > 0 且 valid > 0.5` 时加到 `(扁平槽, label)` 上，用两次 `index_add_` 落表【事实 `:287-313`】。
5. **读**：`p = (1-g)·softmax(cls) + g·p_ng` 再取 log；`g = σ(read_gate([h, 检索特征, 写门控值])) · covered`【事实 `:346-370`】。
6. **读发生在解码循环的哪一步**：`forward_step` 之后、`argmax` 之前 —— 本步的分类结果受记忆影响【事实 `engine.py:181-184`；训练 `runtime.py:144-146`；首步评估 `runtime.py:231-233`】。
7. **写发生在哪一步**：engine 是**锚点落表之后**（读→判类→区间→去重→append→**写**→看 action）【事实 `engine.py:211-217`】；训练是**算完 loss 之后**【事实 `runtime.py:156-159`】；rollout 是取完 argmax 之后【事实 `runtime.py:397-400`】。
8. 读在写之前 ⇒ 本步答案不会喂给自己，表里只有**更早**提及的绑定【事实 `runtime.py:143-146` 注释 + 上面两处顺序；实测 P3 的梯度隔离】。
9. **reset 粒度**：训练每 batch（`runtime.py:133`）、验证每 batch（`runtime.py:224`）、每次 `_rollout`（`runtime.py:386`）、**推理每个 (卡, 段) 一次、batch=1**（`engine.py:170-173`）。
10. **表不是参数也不是 buffer**：「故意不注册成 buffer」，`no_grad`、不进优化器、不进 state_dict【事实 `:131-133`；实测 P2/P3：`requires_grad=False / grad_fn=None / named_buffers=[] / state_dict 只有 5 个门控张量`】。
11. **可学习的只有三组门控**：`write_gate`、`read_gate`（各是 Linear 的 weight+bias）、`level_weight`（两级混合的 softmax 权重）【事实 `:153-159`；实测 P2】。
12. 门控初值：`write_gate.bias=1`（σ≈0.73，先平均地写）、`read_gate.bias=-2`（σ≈0.12，先轻信）、`level_weight` 全 0（两级均权）【事实 `:154-159`；实测 P2】。
13. 表大小：`batch × (C+1) × Σslots × 4B`；当前配置 batch=1 时 442368 B（0.0004 GB）【事实 `:193-198`；实测 P2】。

#### 三条硬约束与「代码里怎么强制的」

14. **硬约束 1「不碰全局指针」**：`read_attention` 整段在 `torch.no_grad()` 里构造 one-hot 并 detach，读路径只把 `start_logits` 当权重用【事实 `:456-474`】。
    强制点：`tests/test_mention_ndb.py:119-144` 断言 `start_logits` 数值不变、`dec.start_ptr.weight.grad is None`、`cls_head.weight.grad is not None`；实测反向后 `start_logits.grad is None` 而 `cls_logits.grad / read_gate.weight.grad / write_gate.weight.grad` 都有值【实测 P3】。
15. **硬约束 2「表有硬上限」**：`reset()` 里按 `max_table_gb` 拦，超了抛 `ValueError`【事实 `:200-207`】，测试 `tests/test_mention_ndb.py:51-56`。
    ⚠ **docstring 说「构造 / 每次 reset 都拦截」，但 `__init__`（`:98-159`）没有任何检查** —— 见 §6 发现 F1【实测 P3】。
16. **硬约束 3「表是 no_grad 的数据统计量」**：写入整段包在 `torch.no_grad()` 里（`:289`），读侧诊断统计也包 `no_grad`（`:358`），表是普通叶子张量（实测 P3）；梯度到 `write_gate` 的唯一路径是「把写门控值同时喂进读门控输入」（`:349-350`），实测 `write_gate.weight.grad is not None`【实测 P3】。
17. **写要显式开启**：`write()` 在 `write_enabled()` 外直接 `return None`【事实 `:221-228, :287-288`】；docstring 说「验证 / 探针绝不包」，但实测有反例 —— 见 §6 发现 F2。

### 3.2 什么时候失效 / 退化

1. **槽为空 → 门控强制归零**：`g = g · covered`，未覆盖位置检索分布恒 0，只能退回分类头【事实 `:347-352`】。
2. **读注意力必须是硬的**：软注意力会把权重摊到有键的旧位置，把「新人物」误判成已有 id；docstring 记了实测 0.999 → 0.480【事实 `:442-448`】（该数字本身未在本任务中复测 → 归入 §8）。
3. **键与读位置必须严格同一位置**：±1 都读不中（`tests/test_mention_ndb.py:58-79` 的断言文案）【事实】。
4. **哈希碰撞**：级内 `frac` 未必是分布，靠级内重归一兜底【事实 `:392-393, :423`】。
5. **n-gram 阶数上限 3**（int64 哈希 4 阶会溢出），`levels` 更大直接构造报错【事实 `:77-78, :105-106`】。
6. **表超上限 → reset 抛错**（fail-closed，不是 OOM）【事实 `:200-207`；实测 P3】。
7. **粒度 = 段 ⇒ 记忆不跨段**：长文被按句切开时，每段一张空表 + 每段一个新 query 序列，跨句的「我已见过谁」在句边界清零【事实 `engine.py:167, :170-173`；后果的量级见 `plugin.py:130-132`（切句后漏标 62%）与 `plugin.py:429-431`（整句一致率 16.2% → 0.8%）；「这就是 person 卡在长文上的失效机制」是【推断】】。
8. **当前 4 张挂载卡都没有 NDB**：`extra.ndb` 缺失 → `load_card_ndb` 返回 None → 推理里整个 NDB 分支不执行【实测 P4 `ndb=False`；事实 `engine.py:49-51, :171-182`】。
9. `read()` 在 `reset()` 之前调用会抛 `RuntimeError`【事实 `:335-336`；测试 `tests/test_mention_ndb.py:159`】。

## 4. 引擎推理流程 `src/dtseek/tasks/engine.py`（`predict` / `_run_segment`）

### 4.1 完整顺序（从 `predict(text, tasks)` 到锚点列表）

1. `text.strip()`；空串直接返回 `{"error": "输入为空"}`【事实 `:242-244`】。
2. `chosen = tasks ∩ 已挂载`：**拼错的任务名被静默丢弃**，不报错【事实 `:246`】。
3. 建本次调用私有的 `encode_cache = {}`（作用域只有这次 `predict`）【事实 `:249, :236-240`】。
4. 逐卡算 `limit = max_chunk_len or max(16, spec.max_len - 8)`【事实 `:253`】。
5. 分段：`segment_policy=="window" 且 len(text)≤limit` → 整段一条；否则 `split_with_global_offsets(text, max_chunk_len=limit)`【事实 `:254-259`】。
6. `num_segments` 取所有卡里最大的那个数【事实 `:260`】。
7. 逐段调 `_run_segment(task, seg_text, encode_cache)`【事实 `:263-265`】。
8. 段内 tokenize：`encode(max_length=spec.max_len, padding=True)` → `[1, ≤spec.max_len]` 的 ids 与 mask【事实 `:152-154`】。
9. 编码：键 = `(tuple(input_ids), tuple(attention_mask))`，命中就复用，否则过一次 `doc_encoder`【事实 `:60-71, :160-166`】。实测 4 卡 × 2 段只编码 3 次（三张 64 窗口卡同键、person 120 窗口另算）【实测 P12b】。
10. **`ndb.reset(1, device)` —— 就在 `_run_segment` 里、解码循环之前**，粒度 = **一个 (卡, 段)**【事实 `:170-173`】。
11. 解码循环 `for step in range(spec.max_steps)`【事实 `:175`】：
    `forward_step`（`:176`）→ `ndb.read_attention + read`（`:181-182`，有卡才走）→ softmax + argmax 得 `pred_cls / action`（`:183-185`）→ `cls==0` break（`:187`）→ 起止 argmax 并按段长 `L` 归一（`:190-193`）→ 重复区间 break（`:195`）→ append 锚点（`:199-209`）→ `ndb.write`（`:211-217`）→ `action==0` break（`:219`）→ `get_step_input` 追加 query（`:222-228`）。
12. **全局偏移换算**：`s0 = g0 + local_s0`、`e0 = g0 + local_e0`，`step` 按已累积锚点数重编号【事实 `:263-271`】。
13. `pair_emission` 时按全局序号贴 `pair_index = i//2 + 1` 与 `pair_side`【事实 `:272-275`】。
14. 结果结构：`{"text", "num_segments", "tasks": {卡名: 锚点列表}}`【事实 `:247, :276`】。
15. 呈现：`render` 把 `[s0,e0,color]` 交给 `render_highlight`，按 **0-based 闭区间**画下划线【事实 `:283-284` + `runtime.py:461-469`】。

### 4.2 `ndb.reset` 到底在哪一层

16. 层级是 **`_run_segment` 内部**，不是 `predict`、也不是 batch —— 每个 (任务, 段) 都开一张 `batch=1` 的空表【事实 `:170-173`】。
17. 训练/验证的 reset 层级是 **batch**（`runtime.py:133, :224`），`_rollout` 是**每次调用**（`runtime.py:386`）—— 三处粒度不同，但语义都是「不跨样本/不跨段残留」。
18. 同一 `predict` 里多张卡各用各的 `self.ndbs[task]`，互不共享【事实 `:97, :171`】。

### 4.3 「长文本按句切开」会导致什么

19. **段间状态清零**：query 序列和 NDB 表都只在段内存在，跨段即重来【事实 `:167, :170-173`】。
20. **person 卡的 spec 自己记着代价**：按句切会让 id 每句从 1 重来，「实测切句后漏标 62%、重复提及 id 全错」【事实 `plugin.py:130-132`】。
21. `segment_policy` 的 ckpt 快照漂移会让这件事**静默发生**：快照没有该字段就默认 `sentence`，实测整句一致率 16.2% → 0.8%，因此被列入 fail-closed 校验【事实 `plugin.py:429-431`】。
22. **成对任务的两个成员可能被切进不同段**，`pair_index` 又是按全局序号贴的 → 错配【推断：由 `engine.py:259, :272-275` 推出，本次未构造出复现样本】。
23. **分段器只按标点切、从不合并**：`max_chunk_len` 只决定「单句过长时要不要按逗号二拆」，所以 `window` 卡一旦超过 limit，实际退化成**按句切**【事实 `segmenter.py:11-43`；实测 P8：152 字文本 person 也被切成 13 段】。
24. **无标点长段切不开**：300 字无任何标点 → 只切出 1 段 300 字【实测 P6/P9】，随后被 tokenizer 静默截断（见 §1.2）。
25. 分段结果的 `global_start/global_end` 与原文逐字对齐（实测 4 段全部对齐），偏移换算不会错位【实测 P6】。

## 5. 组合算子 `src/dtseek/tasks/compose.py`

### 5.1 每个算子对 item 列表做什么

1. **`to_items`**：锚点 → `{label, start, end, score}`，默认取 `class_name / s0 / e0 / confidence`；空输入 → 空表【事实 `:69-77`】。
2. **`filter(A, B, ...)`**：保留 **B** 中与**某个 A** 满足位置规则的项；A 或 B 任一为空 → `[]`；输出是 B 的子集【事实 `:130-156`】。
3. **`pair(A, B, rule)`**：对 **A** 的每一项在 B 里挑一个候选并套规则；**输出长度恒等于 `len(A)`**，配不上就原样透传；A 为空 → `[]`【事实 `:183-213`】。
4. **`decide`**：取 `score` 最大者的 `label`（同分靠前优先）；没有锚点 → `default`（默认 `"中性"`）【事实 `:219-223`】。
5. **`flip_rule`**：只造数据 `{"kind":"flip", "apply_to":…, "table":…, "default":…}`，`table` 缺省用 `NEGATED_CLASS`（25 条情绪词映射），`apply_to` 缺省 `("积极",)`，`default` 缺省 `None`【事实 `:162-167, :53-63`；实测 P10 `table 条数 = 25`】。

### 5.2 `pair` 的三个参数各控制什么

6. **`mode`**：决定 A 与 B 怎么算「配得上」——`inside`（B 完整落在 A 内）/ `overlap`（相交）/ `adjacent`（间隔 ≤ window）；未知 mode 抛 `ValueError`【事实 `:116-124`；实测 P10】。
7. **`window`**：只在 `mode="adjacent"` 生效，比较的是**严格间隔** `gap`：相交或相接都算 0【事实 `:80-82, :107-110`】。
8. **`clause`**：`adjacent` 上再加「两区间之间那段原文里没有分句标点」；**需要 `text`**【事实 `:85-92, :107-113`】。
9. `clause=True` 而 `text=None` 时，分句校验被 `if not clause or text is None: return True` **静默跳过**（fail-open）【事实 `:111-112`；实测 P14】。
10. `require` 是文本前置校验（字面闭集或正则），`require_side` 指定校验 A 侧还是 B 侧；`text=None` 时它**永不匹配**（fail-closed）【事实 `:99-104, :146-155`；实测 P13】—— 同一个 `text=None`，一个 fail-open、一个 fail-closed。
11. 候选多于一个时，`best = (gap 最小, score 最高)`【事实 `:205`】。

### 5.3 `flip_rule` 的 `apply_to` 与类别名的关系

12. `apply_to` 与 **`item["label"]`** 比，而 `to_items` 默认把 label 取自锚点的 **`class_name`（规范名）**【事实 `compose.py:69-77` + `engine.py:202-203`】。
13. 所以 `apply_to=("积极",)` 能命中，`apply_to=("积极/喜悦",)`（`display` 名）**永远不匹配** —— sentiment 卡的 `name="积极"` / `label="积极/喜悦"` 是两个字段【事实 `builtin/sentiment/__init__.py:12, :16`；实测 P11；`experiments/out_invariants/closure_trace.py:144-155` 也把它记成「静默失效的旧补丁」】。
14. 查表用的是 **A 项自己的跨度**（`text[start:end+1]`），按**最长命中**优先，查不到落 `rule["default"]`；`default=None` 表示不动【事实 `:170-180, :209-211`】。
15. 翻转要同时满足三件事：有候选配上 + `kind=="flip"` + `A.label ∈ apply_to`【事实 `:207-208`】。
16. 实测一条句子里：`喜欢(2,3) → 愤怒`、`高兴(6,7) → 悲伤`，而词典外的跨度 `(14,15)` 即使邻接也保持 `积极`（查表落 `default=None`）；`mode="inside"` 时三个全不翻【实测 P11】。

### 5.4 什么时候失效 / 退化

17. **`text=None`** → 分句校验失效（fail-open）+ `require` 全部失配（fail-closed）+ 词典查空直接落 `default`【实测 P13/P14】。
18. **`apply_to` 写成 display 名** → 规则静默不生效，不报错【实测 P11】。
19. **上游卡片没输出** → `filter`/`pair` 返回 `[]`，不报错；`decide` 于是返回 `default` —— 组合层把「卡没跑出来」和「真的中性」混成同一个结果【事实 `:143-144, :193-194, :221-223`；「混淆」是【推断】】。
20. **词典只覆盖 `NEGATED_CLASS` 的 25 条**，`default=None` 决定了词典外一律不翻；docstring 明说这是刻意的【事实 `:14-21, :53-63`】。
21. **`TRIGGERS` 与 negation 卡的 `NEG_MARKERS` 必须同源**：实测两组元组逐字相等（11 项）【实测 P10】；改一边不改另一边不会有任何测试报警【推断：`TRIGGERS` 只在 `compose.py:48` 静态定义，无与 `dataset.py` 的一致性断言】。

## 6. 代码与注释 / docstring 相反的发现

**F1（硬约束 2 只做到一半）**
`mention_ndb.py:33` 写「表有硬上限：**构造 / 每次 `reset`** 都按 `max_table_gb` 拦截」，
但 `__init__`（`mention_ndb.py:98-159`）只存 `self.max_table_gb`（`:118`），**没有任何检查**；唯一拦截点是 `reset()`（`:200-207`）。
实测：`max_table_gb=1e-9` 构造通过，`reset(1)` 才抛 `ValueError`【实测 P3】。
影响有限（表只在 `reset` 里分配），但文档声称的「构造时就 fail-closed」不存在。

**F2（「验证 / 探针绝不包写」不成立）**
`mention_ndb.py:40-41` 写「训练循环只把训练 micro-batch 包进去，**验证 / 探针绝不包** —— 否则验证集会写进记忆」。
实际两个反例：
- `scripts/ndb_probe.py:93-94` 在 `write_enabled()` 里写 **真值 label**，而它跑的是 **val 划分**（`scripts/ndb_probe.py:150`：`val = data[:n_val]`）；
- `runtime.py:397-399`：`evaluate_task` 调的 `_rollout` 也包了 `write_enabled()`（写的是**模型自己的预测**，不是真值）。
缓解事实：两处都在 `reset()` 之后逐批开新表（`scripts/ndb_probe.py:63`、`runtime.py:386`），表本身 no_grad、不进 state_dict，
所以**不会跨批/跨轮残留**；但「验证与探针根本不写」这句字面陈述与代码相反。

**F3（解码器 docstring 只描述推理口径）**
`robust_ar_model.py:5` 写「每一步将**上一轮预测的**类别嵌入与位置向量投影回填」，
训练时回填的是**真值**（教师强制，`runtime.py:161-167`）；只有推理才是预测值（`engine.py:222-227`）。
同一句话在训练路径上与代码相反。

**F4（`window` 分段策略的描述与实现不符）**
`plugin.py:130-135` 写 `window` = 「**只在超出 max_len 时才切**，窗口内的多句一起解码」。
实际引擎用的阈值是 `max(16, max_len - 8)`（`engine.py:253`），超阈值时调 `split_with_global_offsets`（`engine.py:259`），
而分段器**只会按标点切、从不按窗口打包**（`segmenter.py:11-43`）—— `max_chunk_len` 只控制「单句过长是否按逗号二拆」。
实测 152 字文本：`person`（`window`, limit=112）照样被切成 13 个按句的段【实测 P8】。
即：`window` 只在「整段 ≤ limit」时等于「整段一次解码」，超过后退化成按句切，没有 112 字滑窗这回事。

**F5（现场变化：旧的「基座只编码一次」曾与代码相反，本轮已被并发改对）**
我第一次读到的 `engine.py`（252 行）里 `predict` 的 docstring 是「基座只编码一次，各卡共享」（旧 `:211`），

### P7 解码循环：逐步 query 长度与停机原因

```

def wrap(self, q_seq, doc_memory, doc_mask=None):
    out = orig(self, q_seq, doc_memory, doc_mask=doc_mask)
    LOG.setdefault(id(self), []).append({'qlen': q_seq.shape[1],
        'cls': int(out['cls_logits'][0].argmax()), 'act': int(out['action_logits'][0].argmax()),
        's': int(out['start_logits'][0].argmax()), 'ee': int(out['end_logits'][0].argmax())})
    return out
```

## 8. 哪些结论是推断（不是实测）

1. **exposure bias 会造成误差累积**：口径差是事实（`runtime.py:161-167` vs `engine.py:222-227`），「累积到什么程度」没测。
2. **person 卡长文退化的机制就是「段间记忆清零」**：`engine.py:170-173` 的 reset 粒度与 `plugin.py:130-132` 的实测数字都是事实，但两者之间的因果归因是我的解释（`plugin.py:130-132` 自己也把原因写成「按句切开」，与我的解释同向）。
3. **成对任务的 pair_index 会在跨段时错配**：由 `engine.py:259` 与 `:272-275` 推出，没有构造出实际错配样本。
4. **`TRIGGERS` 与 `NEG_MARKERS` 缺一致性断言**：实测两者当前相等（P10），「没有测试守卫」是按 grep 结果的判断（`compose.py` 与 `negation/dataset.py` 之间无互相 import / 断言）。
5. **`encoder_kwargs` 与权重形状不符会抛错**：依赖 `torch.load_state_dict` 的默认行为，未实测。
6. **`mention_ndb` docstring 里记的「软读把首次提及从 0.999 打到 0.480」**：只是引用文档，本次未复跑 `scripts/ndb_probe.py`。
7. **「查不到就不翻是刻意设计」**：docstring 的理由（`:14-21`）读起来成立，但没有可执行的验证点，属于设计意图陈述。
8. **截断后 `attention_mask` 之外的 padding 位在指针侧被 `-1e4` 挡住**：代码事实（`robust_ar_model.py:100-102`），但「因此尾部字符绝对不可能被指到」还叠加了 argmax 只在 64/120 长度内这一事实（P9）—— 结论强、但没有端到端跑出「尾部必空」的统计。
