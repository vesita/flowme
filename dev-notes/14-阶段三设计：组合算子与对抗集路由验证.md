# 14-阶段三设计：组合算子与对抗集路由验证

> 状态：**设计，代码未动**。阶段二（加卡 + 基座通用性）完成后进入。

---

## 1. 前提：路由不是难点，「组合」才是（已有实测）

- **E4（dev-notes/12 §10.2）**：在**冻结基座的 mean-pooled 表征**上做**单层逻辑回归**，
  就能以 **98.50%（4 类）/ 98.73%（5 类）** 分开「这段文本来自哪张卡」，
  多数类基线 25%/20%；打乱标签对照 0.23、随机特征对照 0.26（对照有效）。
- **结论**：单独训一张自回归 `dispatcher` 任务卡**没有增量** —— 一个线性探针就够。
- **但 E4 有一个未闭合的疑点**：它是在**各卡自己的训练分布**上测的，而那些样本偏合成/模板化
  （例如 relation 的样本里几乎必有两个成语）。所以 98.9% 可能靠**语体捷径**。
  ⇒ E4 只能否掉「dispatcher 卡有增量」，**不能**证明路由有本事。要证明这一点，必须有**对抗集**。

这也是 dev-notes/08 §6 早就警告的那条：「路由太容易 ⇒ 指标虚高却没有实际价值」。

## 2. 阶段三的三件事

### A. 对抗集（**唯一能证伪路由的工具**）

**构造原则**：每条样本「**表面上像卡 A，实际上属于卡 B**」（或"不属于任何卡"）。
例：
- 一句中文里出现了「我/你」但**真正任务**是判断情绪（代词是干扰）；
- 一句里有两个成语但它们是**同义而非反义**（关系类别由语义判，不由"有两个成语"判）；
- 一句是**普通中性句但含人名**（不该触发 person 卡的实体追踪）；
- 一句含否定词但**情感其实是积极的**（否定卡的干扰）。

**指标**（沿用 dev-notes/08 §5，逐项报，不许合成一个数）：
| 指标 | 含义 |
|---|---|
| `route_acc` | 路由类别正确率 |
| `route_bg_fp` | 无关句子被强行分配任务的比例 |
| `route_macro` | 每类召回的宏平均（防高频任务吃掉长尾） |
| **对抗集准确率** | 唯一硬指标 |

**对照**：同一个对抗集上跑 ①线性探针 ②（若有）dispatcher 卡 ③多数类基线。
**判定**：若线性探针在对抗集上塌到接近多数类 ⇒ 路由确实只是语体捷径，
**阶段三不该在路由上投入**，直接做 B。

### B. 组合算子（增量的真正所在）

按 dev-notes/08 §3 的层次 B，**只做固定几个算子**，不做可学习组合：

| 算子 | 语义 |
|---|---|
| `chain(A, B)` | A 圈出的切片作为 B 的**搜索范围**（把 A 的锚点转成 B 的 `doc_mask`） |
| `filter(A, B)` | B 的结果若落在 A 的锚点之外则丢弃 |
| `pair(A, B)` | 两张卡的结果按位置配对 |

**机制现成**：`feedback_proj` 已经在做「把上一步圈了什么、在哪回填给下一步」，
跨卡组合只是让这个回填**跨卡**发生；且 DTSeek **零文本生成** ⇒ 组合不会引入幻觉
（文本始终只有原文一份，这是本架构相对自回归生成器的结构性优势）。

**验收必须分开报**（dev-notes/08 §5）：
- **上游召回**：A 有没有把该圈的圈出来；
- **条件成功率**：给定 A 圈对了，B 在 A 的范围内做对的概率。

合成一个端到端数字是没用的：`95% × 95% ≈ 90%`，看不出是上游漏了还是下游错了。

### C. 锚点传递（与阶段二的衔接）

阶段二的**选择族卡**（`reply_pick` / `cloze_fill`，dev-notes/13）输出「被选中候选的区间」，
这正是组合算子要消费的锚点。所以：

```
锚点完全命中率（dev-notes/13 §5 P5 ≥95%）
   → chain/filter 的输入质量
   → 条件成功率
```

**这条链路是「回复拆解成简单任务 → 再拼起来」的可行性判据。**
若锚点命中率不足，先修定位，不要急着做算子。

## 3. 风险与红线

1. **误差传播**：链越长越差。**先限死算子集合与最大长度**，不要一上来就做长链。
2. **组合空间爆炸**：N 张卡、长度 L 的序列空间随 L 指数增长，训练数据不可能覆盖。
   ⇒ 只做固定算子；可学习组合（层次 C）必须先有算子级泛化测试。
3. **容量**：E1 显示基座末层有效秩利用率 65.8%（有余量），E2 显示每张卡必须**自带独立头**
   （`TaskSpec` 天然满足）。但每加一张卡，联合训练的算力与显存都在涨
   ⇒ **E5 容量-卡片数曲线**（dev-notes/12 §3）必须在卡数继续涨之前做掉。
4. **单 seed 不可判「加卡是否伤老卡」**：同数据同配置重跑的轨道噪声就有 ~2pt
   （dev-notes/12 §11.2）⇒ 这类结论**一律多 seed 配对**。
5. **本阶段不做**：可学习组合（层次 C）、把 dispatcher 做成任务卡（E4 已否）。

## 5. 组合算子的靶子：**先量问题，再修问题**（2026-09-28 实测）

在实现组合算子之前，先量清「到底要修什么」。用 `MultiTaskEngine`（`checkpoints/cards/` 里的
pronoun/relation/sentiment/person 四张卡）对 8 条样例做单卡推理：

| 输入 | sentiment 单卡输出 | 判定 |
|---|---|---|
| 我并没有很开心。 | 积极/喜悦 `'开心'` conf 0.835 | **类别错** |
| 算不上喜欢。 | 积极/喜悦 `'不上喜欢'` conf 0.393 | **类别错** |
| 不见得多好。 | 积极/喜悦 `'不见'` conf 0.425 | **类别错** |
| 谈不上高兴。 | 悲伤/焦虑 `'不上高兴'` conf 0.788 | 类别对、**定位错**（漏「谈」） |
| 开心不起来。 | 悲伤/焦虑 `'心不起来'` conf 0.772 | 类别对、**定位错**（漏「开」） |
| 不高兴。 | 悲伤/焦虑 `'不高兴'` conf 0.632 | 正确（**词典词条已覆盖**） |
| 我不喜欢这个方案。 | 愤怒/不满 `'不喜欢'` conf 0.686 | 正确（**词典词条已覆盖**） |

三条结论（都改变了实验设计）：

1. **词条覆盖的否定式（不高兴 / 不喜欢）已经答对** —— 拿它们当靶子会得到「组合没增量」的
   **假阴性**（dev-notes/05 §4 早有实测：`不高兴 → 悲伤 0.985`）。
2. **未被词条覆盖的否定表达确实翻车**（8 条里 3 条类别明错）⇒ 靶子有空间，但**必须选对样本**：
   `没有很开心` / `谈不上高兴` / `并不觉得满意` / `算不上喜欢` / `开心不起来`。
3. **还有一个原先没设计的失败模式：定位漂移** —— 锚点会多含或漏掉否定字
   （`谈不上高兴` → `'不上高兴'`、`开心不起来` → `'心不起来'`、`不见得多好` → `'不见'`）。
   ⇒ 组合算子的验收必须**同时看「极性」与「边界」**，只报类别准确率会漏掉一半问题。

**可复现命令**：
```python
from dtseek.tasks.engine import MultiTaskEngine
eng = MultiTaskEngine()
eng.predict("我并没有很开心。", tasks=["sentiment"])
```

## 6. 对抗集实测：**E4 的 98.5% 是语体捷径，被正面证伪**（3 seed）

产物：`experiments/adversarial_routing/`（`adversarial.jsonl` 225 条 = 5 类 × 45；
`probe_results.json`；`probe_e4_style.py`、`run_probe.py`）。
口径：复刻 E4 —— 冻结基座 + mean pooling + 零初始化单层逻辑回归（AdamW lr 0.05，
200 epoch，训练 600/类、测试 200/类），**训练只用原始分布数据，全程未接触对抗集**。

| 指标 | 原始分布 | 对抗集 | 说明 |
|---|---|---|---|
| `route_acc` | **0.9883** | **0.0919** | 下降 **89.6pt** |
| `route_macro` | 0.9883 | 0.1148 | |
| 背景误报 | 0.0000 | 1.0000 | |
| 预测成「表面卡」比例 | — | **0.4685** | 系统性按表面特征作答 |
| **15 条手工确信的已知答案** | — | **0.1556** | 连人工复核样本也答错 |
| 多数类基线 M0 | 0.25 | **0.60** | 对抗集是二值主导，M0 更高 |

- **空洞对照有效**：打乱标签 0.164 / 0.173，随机特征 0.193 / 0.225（5 类机会水平 = 0.20）。
- **判定（按 README §4 跑前写死的规则）**：`adv` 相对 `P0` 下降 > 20pt，且远低于 `M0` ⇒
  **「路由主要靠语体捷径」**。

### 6.1 这条结论的直接后果

1. **阶段三不在路由上投入**：`dispatcher` 不做成任务卡（与 E4 的推论一致，但现在有了**证伪证据**，
   不再是"看起来太容易"的推断）。
2. **更重要的负面教训**：**任何「靠分布内特征线性可分」得出的能力判断都不可信**。
   E4 的 98.5% 与对抗集的 9.2% 是同一件事的两面 —— 前者只是后者在训练分布上的投影。
   ⇒ 以后凡是"XX 特征能分开任务/类别"的结论，**必须配一个对抗集**才算数。
3. **卡片自动决策要走的路**：既然线性探针在对抗输入下崩到 9%，"输入识别 → 选卡"这件事
   本身在**当前基座**上不成立（不是"太容易"，而是"看着容易、实际不会"）。
   所以阶段三的重心只能放在**组合算子**上（固定算子 + 可验证的规则），
   而不是"让模型自己决定用哪张卡"。这与 dev-notes/12 §10.3 的决策一致，但理由更强了。

## 7. 组合算子实测：**增量真实，但预注册主线未达标**（P1 挂）

预注册见 `experiments/compose_ops/preregister.md`（判据跑前冻结，事后未改）；
产物 `compose.py` / `make_dataset.py` / `dataset.json` / `run_eval.py` / `raw_results.json` / `summary.json`。
评测集 **127 条** = 否定式 60 + 对照 57（纯对照 44）+ 压力 10 + 已知答案 12。

| 块 | 单卡基线 | 组合 | 判定 |
|---|---|---|---|
| **否定式 60（4 类口径，P1 主线）** | 26.7% | **75.0%** | P1 要求 ≥80% ⇒ **未达成** |
| 否定式 60（极性口径 = 预注册消融） | 36.7% | 85.0% | **明确不参与判定**（preregister §1） |
| 对照 57（非否定情绪） | 71.9% | 71.9% | P3 达成（Δ 0.0pt） |
| 压力 10（含否定但极性为正） | 30% | **10%** | 规则乱翻 **−20pt**，必须如实报 |
| 已知答案 12 | 41.7% | 41.7% | 先于结论出数 |

- 上游召回 **96.7%**（严格口径 90.0%），条件成功率 75.9%（同口径基线 25.9%）⇒ **P2 达成**。
- **判定**：P1 未达成、P2/P3 达成 ⇒ 按预注册规则**不能宣布「组合有真实增量」**，
  只能写「**增量真实但端到端未达标**」。
- **预注册消融（不参与判定）**：`comp_nocheck` 81.7%、`comp_regex` 85.0%
  ⇒ ⚠️ 去掉「标记须在锚点之外」这条守卫反而**更高**，说明该守卫在否定集上有害；
  这是下一轮该改的地方，但**不能据此改判 P1**。
- **15 条 4 类错误的逐条归因**（复核方独立查）：悲伤↔愤怒族内混淆 6 条；应翻未翻 8 条
  （negation 卡完全漏标 2、标记漂移被守卫挡掉 4、锚点漂移致查表落空 2）；上游召回失败 1 条。
  ⇒ 极性口径下的残错**全部**来自上游单卡（漏标 / 定位漂移），**与算子逻辑无关**。
- **压力集的失败模式值得记下**：规则在 `别提我多高兴了` / `不愧是…` 这类**反语 / 反问**上乱翻。
  这是"固定规则"的固有边界，不是实现 bug。

**结论**：固定组合算子把否定式情绪的端到端从 **26.7% 拉到 75.0%（+48.3pt）**、对照集**不掉点**、
上游召回 96.7%、**回退 0 条**，但**没到预注册的 80% 线**；瓶颈在**上游单卡**，不在算子。
下一步应修上游（或改那条有害守卫）后**按同一判据复测**，而不是调判据。

### 7.1 两套 ckpt 与一条反直觉消融（补）

交付时又跑了第二套配置（B = `arm_neg5_seed42` 拆出的 5 卡一套）：

| 口径 | A 配置 | B 配置 |
|---|---|---|
| 单卡基线 | 26.7% | 40.0% |
| **组合端到端** | **75.0%** | **78.3%** |
| 极性口径（预注册消融） | 36.7 → 85.0% | 58.3 → **96.7%** |
| 判成「积极」 | 63.3 → 15.0% | 41.7 → **3.3%** |
| 回退（基线对→组合错） | **0** | **0** |
| P1（需 ≥80%） | ✗ 差 5.0pt | ✗ 差 1.7pt |

- **两套都不通过 P1**，且 P2/P3 都通过 ⇒ 结论稳。误差恒等式核对：`75.0 = 96.7×75.9 + 3.3×50.0`。
- **⚠️ 反直觉消融：用正则替代 negation 卡反而更好** —— A 配置 **85.0%**（用卡 75.0%）、
  B 配置持平（78.3%）。⇒ **对「修否定式情绪」这件事，那张否定卡相对一条正则没有增量**；
  卡吐出的跨度常漂离真实标记字（`这家书` / `我对` / `满`）。
  这与「否定标记是**闭集词类**」的先验一致：闭集任务上，模型不一定打得过确定性规则。
  **这条直接影响「加卡」的价值判断**：加卡前应先问「一条正则能不能做到」。
- **预注册缺陷（如实记）**：`preregister.md` 冻结了规则与标注口径，但**没写死 ckpt 路径**，
  于是"用哪套权重"是事后选的。已记入 `experiments/compose_ops/results.md` §8。
  下次冻结判据时，**权重路径也要写进去**。
- **方法学边界**：单次前向、单 seed、单评测集、短句口语，不外推到长句/多从句。
