## 1. 指针型 vs 生成型：区别在**发射什么**，不在解码器

两者的解码器**都可以是自回归的**（现有 `RobustARSliceDecoder` 就是 AR 的）。真正的差别是**发射的符号表**：

| | 指针型（extractive） | 生成型（generative） |
|---|---|---|
| 发射什么 | **位置**：`[start, end]` 区间 + 类别 | **字**：词表里的 token 序列 |
| 输出来源 | 必然是输入文本的**子串** | 可以是原文里**没有**的内容 |
| 零幻觉 | **结构性保证**（不可能编造原文没有的） | **没有结构性保证**，需另行核对 |
| 表达力 | 受输入限制；要"回复"就得先有候选 | 能真正回复/改写/总结 |
| 评测 | `exact_match` / `span_hit`（区间对齐） | 生成指标 + 忠实性 + 裁判 |
| 组合与审计 | 区间可高亮、可溯源、可核对 | 需额外带**证据锚点**才能核对 |
| 现有资产 | 全部 9 张卡 + 引擎 + 组合算子 | 无（要新解码器头） |

**中间态（推荐先走这条）——"拼接式生成"**：生成卡发射**若干指针区间**（可从原文、也可从上游卡的输出里取片段），
按顺序拼接成回复。它**仍是指针型**（零幻觉、可高亮），但已经能"输出语言"。
等它跑通，再决定要不要上真正的自由生成。

**分型输出记录**（让两种输出能共存、且下游不必分叉）：

```
指针型: {kind:"span", span:[s,e], class, score, evidence:[...], plan_step_id}
生成型: {kind:"text", text, evidence:[{module_id, span, class}], score, plan_step_id}
```

生成型的 `evidence` **必填**：把"零幻觉"从**结构性保证**降级为**可核对保证** —— 这是自由生成唯一能接受的代价形态。

## 2. 四层框架

### 2.0 决策机：有限 MDP = 手写状态机 + 经验转移

**形式化**：MDP = (S, A, P, R, γ)。分工是这套东西成败的关键 —— **不是全都手写**：

| 成分 | 谁提供 | 说明 |
|---|---|---|
| **S 状态（手写，有限）** | 手写 | `(声明的 type, 信号三态向量 {未查,有,无}, 剩余步)` —— 可执行版见 §2.1 与 §2.2 D1（**|S| = 4860**） |
| **A 动作（手写，有限）** | 手写 | 调某张卡（≈7~11 个）+ 终止三选一 {指针输出, 生成输出, 拒答} |
| **P 转移（不手写）** | **经验估** | `P(s'|s,a)` 来自"卡在这类输入上实际会输出什么"。**手写概率等于把猜测固化** |
| **R 奖励（手写，但必须可自动算）** | 手写 | 组合增益 / evidence 覆盖 / 拒答正确 / 调用成本 |
| **π 策略** | **先手写，后学** | 手写 = 规则表（每状态一个确定动作）；跑通后用估出的 P 做值迭代 ⇒ **表格策略可打印、可审计、可 diff** |

**两条硬约束（都由实测逼出来）**：

1. **状态量必须"算出来"，不能"模型判出来"**。可用信号：卡是否产出切片（二值）、锚点数、
   置信度**硬阈值**化。一旦状态里混进"模型判出的东西"（如"这句是在询问"），
   状态就带上了元决策的不可靠性（路由 9.19% / 类型 29.78%）。
2. **分布外的 P 不可估**（§13：拒答 ~96% 误开火）⇒ **MDP 只在分布内有意义**，
   OOD 必须由"调用方声明 type"那一层**先挡住**，不能指望状态机自己处理。
   同理：**奖励若靠裁判模型，等于又引入一个不可靠元决策**。

**分三阶段（为什么不必一上来就要概率）**：规则策略**不需要 P 就能运行**；P 只在你要**优化**策略时才需要。
所以顺序是 **手写 S/A/π → 跑通 → 估 P → 改 π**。

**这个形式化真正买到的是「可验证」，不是「自主」**：
- 状态有限 ⇒ 能**枚举所有可达状态**，查出**死状态**（没有任何动作能到成功）、**非法动作**、
  以及**拒答是否可达**；
- 确定性策略 ⇒ **计划逐字可复现**（§13 已实测确定性），满足"显式决策"不变量。

### 2.1 决策机规格（可执行、可枚举）

**信号表 —— 四项全部"算出来"，无一项靠模型判**

| 信号 | 取值 | 怎么算 |
|---|---|---|
| `type` | 5 类 | **调用方声明**（§11.1），不是模型判 |
| `info` | 4 位，每位三态 `{未查, 有, 无}` | 每位 = 一个**必需信息位**（如 时间/地点/对象/意图）；"有" = 对应卡产出了切片**且**置信度 ≥ 阈值 |
| `conf` | 3 档 `{低, 中, 高}` | 最近一次调用的置信度**硬阈值**化（阈值取该卡在自己 val 上的分位） |
| `steps` | 3 档 `{0, 1, 2}` | 剩余可调用次数 |

⇒ **|S| = 5 × 3⁴ × 3 × 4 = 4860**（`steps` 取 4 档，见 §2.2 D1），**可完全枚举** —— 每个可达状态都能打印出来人工审。

**动作（有限）**：调用**位→卡映射所声明的卡**（与注册表卡总数无关）+ 终止三选一 `{指针输出, 生成输出, 拒答}`。

**规则策略 v0（手写，不需要转移概率就能跑）**

| 条件 | 动作 |
|---|---|
| `type == unknown` | **拒答**（类型不确定不许猜，§7） |
| 存在 `info` 位 = `未查` 且 `steps > 0` | 调用该位对应的卡 |
| 存在 `info` 位 = `无` | **拒答**（缺必需信息） |
| 全部 `info` = `有` 且 `conf ≥ 中` | **生成输出** |
| 全部 `info` = `有` 且 `conf == 低` | **降级为指针输出**（更严谨） |
| `steps == 0` 且未完成 | **拒答**（不许无限调用） |

**验证点（每条都能一次判定）**

1. **状态数**：枚举真实**可达**状态数并打印，必须 ≤ 4860；
2. **无死状态**：每个可达状态都存在动作序列能到达某个终止动作；
3. **拒答受控**：`type == unknown` 的状态**只**能到拒答；`info` 缺位只能到拒答；
4. **确定性**：同一 `(type, 卡片输出)` 两次运行产出计划**逐字相同**；
5. **闭合**：计划中每个 `Step.input_span` 必须落在原文或上游产出上（可核对）。

### 2.2 规格订正（实现暴露的 6 处缺口，逐条定案）

实现把它跑通了（第一版：全空间 3645、真实可达 77、死状态 0；`pytest 208 passed`），
并如实报出规格里**我没写清**的地方。逐条定案（**对齐后的实测见 §2.3**）：

**D1. 位→卡映射允许非单射；`steps` 上限定为 3。**
单射（4 张不同卡）实测可达 309 态、死状态 0，但**终止只有 `reject`** —— 4 次调用 > 2 步，
生成/指针**永不可达**。⇒ 显式承认**一张卡可服务多个信息位**，并把 `steps` 取 `{0,1,2,3}`：
**|S| = 5 × 3⁴ × 3 × 4 = 4860**，仍可完全枚举。

**D2. 可行动作 = `admissible(s)`，不是全局 A。**
规则表按状态**收窄**动作：只授权调「未查」位对应的卡。
理由：把整个动作集当可行动作时，缺位态可以经"重调 slot → 调 intent"洗成全有，
**验证点 3（拒答受控）当场不成立**（已实测）。这一条是**规格必写项**，不是实现细节。

**D3. 规则行序：把「有缺位 ⇒ 拒答」提到「有未查位 ⇒ 调卡」之前。**
缺位意味着必需信息已确定拿不到，继续调别的卡无意义 ⇒ **拒答要早**。
影响：可达集变小（可接受）；测试里钉住的数字需随之更新并说明。

**D4. `conf` 的初值与转移（采纳实现的补充并写进规格）。**
初值 = `LOW`（初态没有"最近一次调用"，取最保守档）；转移 = 「该位变**有** ⇒ 可能升到 mid/high」、
「变**无** ⇒ 读不到置信度 ⇒ LOW」。
理由：原规格只写了位与 steps 的转移、没写 conf ⇒ conf 恒为 LOW ⇒
**R4（生成输出）永不可达，生成输出变成死路**。

**D5. 必需位按 type 声明（不再对 5 类一刀切）。**

| type | 必需位 |
|---|---|
| `plain` | intent |
| `cloze` | object |
| `candidates` | intent + object |
| `multi_turn` | time + place + object + intent |
| `unknown` | —（直接拒答） |

**D6. 「有」的定义：本层先按卡，且**明标为临时简化**。**
现状"有 = 该卡被调用过且产出切片"⇒ **共卡的位同生共死**，名义 4 位、独立自由度只有 2
（这也是可达态仅 77 的主因）。**按位独立**（时间出了、地点没出）需要卡能声明"我覆盖了哪一位"，
那是**补卡时**才有的契约 ⇒ 现在保留按卡，但**必须在代码注释与文档里写明是临时简化**，
并留 TODO：补卡时改成按位。

**D7. `slot` / `intent` 就是待补卡的注册名契约。**
补卡时必须**逐字同名**；`INFO_BITS` 是唯一改动点。
且"生产注册表暂无这两张卡 ⇒ 全线拒答"是**正确的当前行为**（fail-closed），不是缺陷；
补卡后该测试要改成走成功路径。

**D8. §2.0 与 §2.1 的数字打架：以 §2.1 为准。**
§2.0 那个"6 类 × 3⁶ × 4 档 ≈ 1.7 万"是早一版的估算，**已作废**；可执行版是 §2.1（3645，D1 后 4860）。

**D9. §2.1 里"动作含现有 7 张卡"改为"位→卡映射所声明的卡"** —— 本层只认映射，与注册表总数无关
（注册表实为 9 张，含当前不可用的选择族）。

### 2.4 两项裁决（实现方提出，我定的）

**裁决 1：D3×D5 交叉 —— "缺位"看全 4 位，采纳。**
实现按 D3 字面**看全部 4 位**（更严），并给出等价性证明：**在可达集上与"只看必需位"等价** ——
非必需位与必需位**共卡**（D6），没被调用就永远停在「未查」，不会单独变「无」。**采纳**（更严且等价）。

**裁决 2：注册表门禁要收窄到「该 type 的必需位」。**
现状门禁查**全部 4 位**的卡 ⇒ 只注册 `slot`、还没 `intent` 时，**连只依赖 `object` 的 `cloze` 也拒答**。
这会**堵死增量补卡** —— 而增量补卡正是本框架的核心（§15/§17）。
⇒ **定：门禁按 `REQUIRED_BITS[type]` 收窄**；fail-closed 不变（必需位的卡缺失仍拒答）。
⚠️ **该改动尚未落地**：需给 `registry_problems` 增加 type 入参，并同步
`test_fail_closed_missing_card_refuses`。

### 第一层 · 调度层（显式，不训练）

输入 = 调用方按 §11.1 **声明的** `type`；输出 = **调用计划** `Plan = [Step{module_id, params, input_span}]`。

分三级演进，每级都**可判**、且不破坏已有结论：

| 级 | 谁决定调什么 | 可判据 | 现状 |
|---|---|---|---|
| **1** | **规则表**（type → 计划） | 同一输入计划**逐字可复现** | ✅ 确定性已实测 |
| **2** | **模型提议 + 规则校验**（提议不通过就拒答） | 提议接受率 / 误提议率（对抗集） | 待做，风险可控 |
| **3** | **独立规划器模块** | 对抗集上的调度正确率 + 拒答校准 | 这才是你说的"自主"；**必须过对抗集** |

⇒ **要"自动调度"，就得把规划做成第 3 级的独立模块**，而不是让语言输出卡顺手决定。
第 1 级先跑通端到端，第 2 级是低风险的"半自主"，第 3 级才是真自主。

### 第二层 · 卡片层

- **已有**：`pronoun` `sentiment` `relation` `person` `negation` `idiom` `ownership`（tagging，可用）
- **要补**（按"生成一条回复需要什么"倒推，每张都守现有 `span+class` 契约，因而天然可组合）：

| 新卡 | 作用 | 为什么生成需要它 |
|---|---|---|
| **意图/言语行为** | 这句是在问、在陈述、在请求？ | 决定回复的**形态**（答/确认/追问） |
| **槽位抽取** | 时间/地点/数量/对象 | 决定回复**必须覆盖什么**，也是 evidence 的来源 |
| **安全拒答** | 该不该回、是否越界 | 把拒答出口**显式化**（模型自己不会拒，§13） |
| **事实一致性** | 生成内容与原文是否矛盾 | **生成型的验收组件**：给 evidence 做矛盾检测 |

- **不加**：任何"从候选里挑"的卡（选择族当前不可用，§9）。

### 第三层 · 输出层

按 §1 的 `kind` 分型；统一记录 + `plan_step_id`（可溯源）+ `evidence`（可核对）。
不变量 = 闭合性 / 可溯源 / 拒答 / 忠实性（**前三条当前都不成立，必须显式实现**）。

### 第四层 · 训练路径（沿用基本框架）

1. 冷启动：训核 + 各 tagging 卡头；
2. 补 tagging 新卡（意图/槽位/安全/一致性）：**能只训头就只训头**；
3. 加生成卡：**温启动联合**（核可训、老头冻结），只放开生成头；
4. 数据：对话语料取「上文 → 该回复」对；上游卡的输出作为**附加输入通道**喂进来，
   **不让模型自己去找**（这正是"显式调度"落地的方式）。

## 3. 最小可行落地：单轮对话路径（模板 + 抽取片段）

**目标**：`一句话进 → 一句话出`，**只用现有卡片**，把四层真正串起来。

**为什么是"模板 + 抽取片段"**：现有输出全是指针型 ⇒ **回复的内容词只能来自输入** —— 这正是零幻觉的来源。
句子的**骨架**由一张**有限的、手写的模板表**提供：它是**代码**、不是模型输出 ⇒ 可审、可穷举、可 diff。
这是"拼接式生成"的第一步；跑通后再决定要不要上自由生成。

**四段**：

1. **声明 type**：调用方给（CLI `--type`）。**不声明 ⇒ `unknown` ⇒ 拒答**（不许猜）。
2. **出计划**：`dispatch` 的规则策略。为此给 `dispatch` 的位表加**可注入参数**（默认仍是 `INFO_BITS` 目标表），
   对话层注入一张**映射到现有卡**的表（情绪=`sentiment`、否定=`negation`、人称=`pronoun`、人物=`person`）。
3. **调卡**：`engine.predict(text, tasks=计划里的卡)` —— **只跑计划里的卡**，顺带拿到性能收益
   （全跑 4 张 15.7ms → 只跑 2 张 ~8.6ms；外推到 9 张更明显）。
4. **拼回复**：模板表 + 锚点片段，产出 `{kind:"text", text, evidence:[{card, span, class_name}]}`。

**本轮最小配置**：只支持 `type=plain`，必需位 = 情绪 + 否定。
- 有情绪切片 ⇒ 「你这句话里的『{片段}』表达了{类别}」
- 有否定 ⇒ 「并且有否定成分『{片段}』」
- 必需位有缺 ⇒ **拒答**

**判据（跑前写死；这是确定性路径，不适用"≥2 seed"，改用"逐字可复现"）**：

| # | 判据 | 门槛 |
|---|---|---|
| P1 | 端到端可跑 | 一句话 → 一句回复，无异常 |
| **P2** | **零幻觉（可自动校验）** | 回复里所有**引用片段**必须是输入的**逐字子串** |
| P3 | 计划与回复可复现 | 同一输入两次跑，**逐字相同** |
| P4 | 拒答受控 | `type=unknown` 或必需卡缺失 ⇒ **拒答**，不定输出 |
| P5 | 性能 | 单轮 < 100ms（因为只跑计划里的卡） |

⇒ **P2 是这条路的命门**：它把"零幻觉"降成**一次字符串包含检查**，可进 CI。

### 3.1 规格订正：必需位不能把「检测器判否」当成「缺信息」

**实测暴露的缺陷**（跑 `examples/example_dialogue.py "我今天特别高兴。" --type plain`）：

```
命中卡: sentiment, negation
plan[2]: [type=plain info=[有,无,未查,未查] conf=低 steps=1] ⇒ reject：存在 info 位=无：缺必需信息
```

⇒ **一句没有否定的正常句子永远被拒。** 测试文件自己也把 `"我不认为这是个好主意"` 标成**拒答样例**
（`tests/test_dialogue.py:40-41`，注释写明"情绪有切片、否定没有 ⇒ 必需位有缺 ⇒ 拒答"）；
而成功样例里的 `"今天天气不错"` 之所以能过，是因为它**含"不"字**、negation 被**误触发**成 `有`。
⇒ **5 条测试全过 ≠ 语义正确。**

**根因（是我的规格错，不是实现错）**：三态 `未查/有/无` 把**两件完全不同的事**混成一个值：

| `无` 的两种含义 | 该怎样 |
|---|---|
| ① **检测器判否**（"这句话是否定句吗" → 否） | 这是**有效结论**，应**继续** |
| ② **读不到 / 调用失败** | 这**才**该 fail-closed **拒答** |

我又把 `negation`（**检测类**）放进 `required`，而 required 被理解成"必须为 `有`" ⇒ 没有否定 = 缺证据。
（实现里 `dialogue.py:138` 也写着"无切片 ⇒ LOW（**失败的调用**不许拿旧置信度撑腰）"⇒ 同一个混淆。）

**修正**：给每个位加**种类**，并把 `无` 的两种含义拆开。

| 位的种类 | `无` 的含义 | 规则 |
|---|---|---|
| **抽取类**（时间/地点/对象/人物） | 该信息确实不存在 | `无` ⇒ **拒答**（缺必需信息） |
| **检测类**（否定/情绪/安全） | **判否**，是有效结论 | `无` ⇒ **继续**（记「否」并推进） |
| **调用失败 / 读不到** | 无法判定 | ⇒ **拒答**（与上面两种**必须区分开**） |

⇒ 实现上：`InfoState` 需要**四态**（`未查 / 有 / 无 / 失败`）或等价的"调用是否成功"标志位；
`required` 的语义要改写为"**必须被判定过**"（`未查` ⇒ 调卡），而不是"必须为有"。

**这条的教训**：规格里的 `required` 必须写清是要求**判定**还是要求**取值** ——
否则**检测类卡会被自己的"判否"卡死**。

**干净对照（实测）**：

| 输入 | 结果 |
|---|---|
| `今天天气很好。`（无"不/没"） | **拒答**（"缺必需信息"） |
| `今天天气不错。`（"不错"含"不"） | **回复**『不错』表达了积极；否定成分『今天天』 |

⇒ 系统**开不开口，取决于否定检测器有没有恰好误触发**，而不是有没有话可说。

### 3.2 第二个问题在流水线之外：卡的切片质量

5 个样例的**机械判据全过**（确定性、零幻觉自动断言、8 条拒答入口、只跑计划卡 **2.43×** 提速），
但**语义是空的**：

- `今天天气不错。` ⇒ 把『今天天』标成**否定成分** —— **"不错"里的"不"误触发了否定卡**；
- `他不是好人` ⇒ 情绪片段『他不』、否定片段『他』（"他"不是否定词）。

⇒ **必须说清**：**零幻觉保证的是「可核对」，不是「说得对」**。指针型能保证"引用一定是原文的逐字子串"，
但**引用哪一段、标成什么类，取决于卡的判断质量**。⇒ 不要把 P2 通过误当成"质量可用"。

**瓶颈已经转移**：这一层的机械正确性已经做到，**现在的瓶颈是卡在短句上的切片质量**，
加上 §3.1 的必需位语义。⇒ 下一步该补的是**卡**，不是流水线。

**关于"逐字可复现"的口径（更正一次我自己的错误怀疑）**：P3 原本只测**同进程**两次相同。
我另测**跨进程 5 次**（`今天天气不错。`）⇒ **5/5 完全一致**，**跨进程确定性成立**。
我一度怀疑跨进程不确定，起因是代理的样例用的是**不带句号的** `今天天气不错`，与我的输入**差一个字符**
（`(2,4)`＝"天气不" 对应 6 字串、`(0,2)`＝"今天天" 对应 7 字串，两个切片各自自洽）。
**此前的怀疑不成立，已撤回。**

## 4. 接入核心级 NDB（情节记忆上移到核）

**动机（它修的是一个已实测缺陷）**：现在的 NDB 是**卡级**的，而引擎在**每个 segment 开头 reset**
（`engine.py:148-150`）⇒ **跨句状态在段边界清零**。代码自己的注释就承认了这件事（`engine.py:222-225`）：
「跨句状态（如人物 id）必须在窗口内保持一致，按句切开会让状态在句边界清零」，
目前靠**让 `window` 类卡整段一次性解码**绕过。

**更正（我先前写"核级 NDB 是**唯一**形式"，过强了）**：**卡级私有 NDB 与核级 NDB 不冲突，可以共存**。
真正被禁止的只有一种组合：**共享表 + 由卡写入** —— 因为**加一张卡就会改内容 ⇒ 改别人的读** ⇒
破坏「加卡后老卡 pred/exact 逐位不变」（§15/§17 的 30/30）。

⇒ 提升为一条**通用作用域不变量**（这才是该守的东西，而不是"核级唯一"）：

| 组合 | 安全？ | 为什么 |
|---|---|---|
| **卡级私有表**（现状） | ✅ | 加卡不改别人的表 |
| **核级表**（核写；卡可读） | ✅ | 写入与"挂了哪些卡"**无关** |
| **共享表 + 卡写入** | ❌ | **加卡即改内容 ⇒ 破坏"老卡逐位不变"** |
| 跨请求持久表 | ❌ | 违反 per-input reset 硬约束 |

### 4.1 NDB 作为一种「插件」：四元组 + 适用场景判据

把 NDB 看成 **`(写接口, 读接口, reset 作用域, 挂载层级)`** 四元组 —— **接口一样、层级可换**，
所以它既能挂在核上，也能挂在某张卡上，**互不冲突**。这是"插件"这个说法的确切含义。

**适用场景判据（正向，需同时满足）**：

1. 答案依赖**"本样本内早前建立过的离散绑定"**（person 卡的匿名身份槽是原型）；
2. 该绑定**必须随样本清零** —— 同一字面在不同样本里映射到不同身份 ⇒ 全局表只能学到边缘分布
   （≈均匀）= **等于没学**（这是 NDB 与"参数化记忆"的分界线）；
3. 绑定能**从表层键召回**（键是原文里可稳定定位的特征，如提及起点的 n-gram）；
4. **存在可用的查询分布**（指针/注意力）做聚合 —— ⚠️ **核没有指针头 ⇒ 核级必须另造键/触发**（§4 的缺口）；
5. 它只做**加性修正**（读出的分布与主分布凸混合），**不改主决策的指针**（现有硬约束 + 测试）。

**反向（不适用，同样重要）**：

- 绑定**跨样本通用** ⇒ 那是**参数**该学的，不是情节记忆；
- 键**无法从表层稳定定位**（需要语义推理）⇒ n-gram 键不够；
- **没有查询分布**可聚合；
- 需要**跨请求持久记忆** ⇒ 违反 per-input reset 硬约束。

⇒ 上面这套判据**要在 `experiments/core_ndb/` 里被校准或反驳**（用户要求"顺便分析"）：
实验的 G2 反面控制正好是"共享表 + 卡写入"那条 ❌ 的直接证据，P1 则是条件 1/2/3 的正面检验。

**缺口（如实）**：NDB 现在的读协议依赖**解码器的指针** —— `read_attention(start_logits, mask)`
用 start 指针分布做聚合，而这是**有测试保护的硬约束**（「不碰全局指针」）。
核是纯编码器、**没有指针头** ⇒ 核级 NDB 需要一个**新的键/触发**：
- 要么在核上加 **mention 门控头**（学"这个位置是不是提及起点"）；
- 要么用表层特征做键（仓库已有 lexicon 工具）。

**训练路径（沿用框架）**：核上加头 = §10 边界表里的「核**不具备**该能力」那一行 ⇒
**温启动联合**（核可训、老头冻结）。**并且必须有 step-0 门禁**：
门控**零初始化**（记忆在起点贡献为零）⇒ 老卡 pred/exact **逐位不变**，必须**实测**而非声明。

**范围不变量**：表按**输入** `reset`，**绝不跨请求**残留（沿用 `mention_ndb` 的现有硬约束）。

**与"编码缓存"是两件事，别混**：
- 缓存 = **特征复用**：同一 `input_ids` ⇒ 同一 `doc_memory`，**不改变任何数值**；
- NDB = **情节身份记忆**：键（提及处 n-gram）→ 身份槽，**会改变数值** ⇒ 因此需要门禁 + 温启动。
- 两者正交：缓存不碰 NDB；NDB 的 reset 粒度也不受缓存影响。

**对对话路径的价值**：跨段/跨轮的身份连续性正是对话需要的（"谁在前文提到过"）⇒
核级 NDB **不是支线，它在对话路径的关键路径上**。

### 4.2 核级 NDB 阶段 1 实测 + 两条「改认知」的发现

**阶段 1 判据全过**（R0/G0/G1/G1′/G2a/G2a′/G2b，双口径；原始数字与 sha256 见
`experiments/core_ndb/RESULTS.md` §2 与 `results_phase1.json`）：
零门控与不接记忆**逐位相同**；**与挂了哪些卡无关**（门控开/关两态都成立）；
门控一开则 **16/16 文本全变**（非空测试）；**只读关写仍逐位相同**；
**让一张卡写共享表 ⇒ 另三张卡 12~14/16 条被改变** ⇒ **作用域不变量被实测钉住**。

**发现 1：门禁与可训练性冲突（实现方已修）。**
**读写门控都零初始化 ⇒ 梯度死锁** —— 零门控让读的贡献为零、写拿不到梯度，两边都学不动。
实测证据 `logs/core_ndb/train_p2_aborted_lr3e4.log`：
`write=+1.00000 (g=+0.000e+00) read=+0.00000`（write 门饱和、**梯度恒为 0**）。
修法（采用）：**记满不读 + 投影 + 单列 `--lr-gate=3e-3`**；修后门控在动
（`read=+0.03887 (g=+6.138e-05)`）。
⚠️ **含义**：§4 要求的"零初始化 step-0 门禁"（保证起点零副作用）**与"门控能学"是冲突的**。
**教训**：凡"要求初始化时无副作用"的门禁，都必须同时回答"**它之后怎么被学起来**"。

**发现 2：可能是结构性障碍（待 P1 实测）。**
**核级记忆或许结构上无法跨段复原身份 id** —— 因为 id 由**解码器的查询态**算出，
而核**没有指针头、也不能存卡相关标签**。
⇒ 若成立：**核级 NDB 能提供的是「提及表示的跨段连续性」，不是「身份槽绑定」**；
**身份槽只能由卡级记忆承担。**

### 4.3 综合：为什么"核级与卡级可共存"是对的（有了机制层面的理由）

**它们承载的是两种不同的状态**：

| 记忆层级 | 承载什么 | 为什么**必须**在那一层 |
|---|---|---|
| **卡级（私有）** | **身份槽绑定**（"这个提及是人物1还是人物2"） | id 由该卡的**指针 / 查询态**算出 ⇒ **只有卡能产生它** |
| **核级** | **提及表示的跨段连续性**（"这段提及和前面那段像不像"） | 核在卡**之前**跑、**与挂了哪些卡无关** ⇒ 可加性守得住 |

⇒ **层级不是"哪个更好"，而是"哪类状态该放哪层"** —— 这也正是**核级不能替代卡级**的原因。
⇒ 对"长输入 62% 提及漏标"（`dev-notes/17` F4）而言：**核级负责跨段连续性，卡级负责身份绑定**，
两者各修一半，**不能指望单独任一层修好它**。

**阶段 2 结果（四次训练全部完成）：核级判负，而且差距很大。**

| 臂 / seed | `repeat_mention_acc` | person `exact` | `id_acc` | `first_mention_acc` |
|---|---|---|---|---|
| **C（核级）** s42 / s43 | **0.3627 / 0.3572** | 0.3150 / 0.3217 | 0.7064 / 0.7106 | 0.8755 / 0.8802 |
| **L（卡级）** s42 / s43 | **0.8266 / 0.8307** | 0.3200 / 0.3267 | 0.9290 / 0.9456 | 0.9799 / 0.9993 |
| **C − L** | **−46.4 / −47.4pt** | −0.5 / −0.5pt | **−22.3 / −23.5pt** | **−10.4 / −11.9pt** |

- **P1 不过，而且不是"无收益"而是"大幅更差"**：核级在 `repeat_mention_acc` 上**低 46pt**，两 seed 同号，远超噪声。
- **P2 成立**：两臂老卡 Δ 全部 ≥0（卡级 / 核级都一样）⇒ 差距**不能**用"核级把老卡弄坏"解释。
- **机制（与「发现 2」吻合）**：身份 id 由**解码器的查询态**算出 ⇒ 搬到核级后**解码器失去了能消费的身份信号**，
  person 掉回已知 **36% 基线**（C 的 0.3627 恰在那里）；而**卡级记忆能做到 83%**。
  C 臂的读门也几乎没开（`read=+0.03887`）⇒ 核级那侧的记忆**基本没被用上**。
- ⚠️ **口径要说清**：C 是"**核级替代卡级**"，不是"核级 + 卡级" ⇒ 它证明的是
  "**对身份绑定而言正确层级是卡**"，**不是**"核级记忆一概无用"
  （核级若要有角色，只能是**表示连续性**，那是另一件事，本轮没测）。

**⇒ 判定：核级 NDB（身份绑定这条路）负，且是决定性的。** 记忆应留在卡级；
F4 那条"长输入 62% 漏标"**应由卡级记忆 + 分段策略修**，不靠核级。

**⇒ 一个现成可用的收获（比结论更值钱）**：**卡级 NDB 把 `repeat_mention_acc` 从 36% 做到 83%**，
但 `dev-notes/17` P4 实测 **当前 4 张挂卡全是 `ndb=False`** ⇒
**这个能力已经在代码里、已经验证有效，却没有任何一张上线卡在用。**
⇒ 与其继续往核上搬记忆，**先把已验证的卡级 NDB 用起来**是更划算的一步。

## 5. 投机式对话路径：生成候选 → 指针选择 → 重整

**与经典投机解码同构，但目的不同**：经典是"小模型起草、大模型验证"为了**提速**；
这里是"**生成卡起草、指针卡选择**"为了**可审计 + 可训练**。

| 层 | 角色 | 输出 | 结构性保证 |
|---|---|---|---|
| **候选区**（生成卡 ×N，可并行） | draft | 多个候选片段 / 待选词组 | 无（被选中之前不算数） |
| **选择区**（**指针卡**） | verify | 每个候选的**锚定判定**（有证据支持 / 无） | ✅ **保证在这里** |
| **重整区** | polish | 连词 / 语序 / 标点 | 受约束（见下） |

**为什么它比我先前那个二选一更好**：

- 零幻觉的保证从"**发射边界**"移到"**选择边界**" ⇒ 生成可以自由、便宜、**弱**；
- **可训练性解耦**：难的那半（选择）用**现成机器**（切片发射 + `exact_match` + span 监督），
  需要新机器的另一半（生成）**允许它不精确**；
- **可解释链**：内容 → 被选中的候选 → evidence 锚点 → 原文，全链可核对；
- **顺带解决延迟**：候选**并行**生成 + 一次选择 ⇒ 不是"逐字 30 个串行 pass"。

### 5.1 ⚠️ 必须先面对的风险（实测）

**选择能力正是本项目已知最弱的一环**：`reply_pick` **20.00%**、`cloze_fill` **19.06%**，
**与盲猜不可区分**（§9：诊断是表示问题，候选槽嵌入方案 A 无改善）。

**缓解（关键设计修正）**：把选择做成**逐候选的二分类打标**（"这个候选有证据支持吗"），
**而不是"从候选里选最优"**。前者是 **tagging**（现有卡的长项），后者才是测崩的那个任务。
⇒ 数据可**合成**：取金标准片段 + 注入扰动（换词/反义/矛盾/无关片段），标注 支持/不支持，
**二分类监督便宜且可大量造**。

⇒ **这条风险要先单独验证**（`experiments/anchored_select/`）：**一张卡能否学会锚定候选打标？**
若学不会 ⇒ 投机式路径与 `reply_pick` 同因失败，**不要**再往下建生成卡。

### 5.2 重整区的硬约束（否则保证会漏）

**重整卡不许改内容词**：

- 推荐：重整只发**编辑操作**（插入连词 / 调序 / 标点），**内容 token 上锁**；
- 于是不变量可判：**每个内容词都能回溯到"被选择区判为支持"的候选**；
- 若让重整**自由生成** ⇒ 保证丢失，只能退回"另加一张事实一致性卡"的**弱**保证。

### 5.3 与投机解码的同构，以及它在哪里断裂

**同构 —— 而且这不是我们独有的结构**：多个**并行提议头** + **一步验证**，
在 LLM 里就是 **Medusa / EAGLE** 那一类做法（多头并行起草候选、一次前向统一验证）。
⇒ 这个直觉**落在一条已知可行的方法谱系上**，不是凭空发明。

| 投机解码 | 我们 |
|---|---|
| draft（小、快、**可以弱**） | 生成卡（可以很弱，只要提议像样） |
| target（强、贵） | **指针选择卡**（**一次前向**给全部候选打分 = 并行验证） |
| accept / reject 规则 | 锚定判定（有 evidence 支持 / 无） |
| 拒绝后 resample | **拒答**（我们已有的出口） |

**它买到的那一件事（重点）**：投机解码的深层性质是
「**只要验证可靠，投机就不降低质量**」—— **质量由验证器负责，起草者可以便宜、可以弱**。
⇒ 这正是我们要的**可训练性解耦**：难的那半（选择）用**现成机器**，
需要新机器的另一半（生成）**允许它不精确**。

**两处断裂（必须承认）**：

1. **没有精确性定理**。投机解码的接受/拒绝规则是**可证明地保持目标分布**的；
   我们的验证器是**学出来的**，它的可靠性只能是**经验量**（必须实测），不是定理。
   ⇒ 幻觉仍然可能"**通过验证**"。
2. **验证器未必更强**。投机解码的前提是 target 比 draft 强；而实测显示**选择恰是本项目最弱环**
   （`reply_pick` **20.00%** / `cloze_fill` **19.06%**，与盲猜不可区分）。
   ⇒ 缓解只有一条路：**把验证器要回答的问题变窄** —— 从"哪个候选最好"（需要语义偏好）
   收窄到"**这个候选有证据支持吗**"（锚定二分类 / 打标）；
   并**把投机的单位从"句子"降到"词组"**（用户提的"候选区生成**待选词组**"正是对粒度的那一步修正 ——
   **只有词组级才能做到"部分接受"**，句子级只能整体拒/收）。

**一个顺带的合成**：拒绝之后怎么办？投机解码的答案是"从修正分布重采样"；我们的答案是**拒答**。
这更符合本项目的不变量 —— 而且**必须是显式拒答**：已实测"让模型自己决定要不要拒"
在分布外 **~96% 误开火**（§13）。⇒ **投机式的"验证失败"出口 = 显式拒答**，不是重采样。

### 5.4 框架级同构：卡片是**提议者**，算子是**裁决者**

类比不只适用于对话路径 —— **整个卡片组合式框架**都像投机解码。按框架级对齐：

| 投机解码 | DTSeek 卡片组合框架 |
|---|---|
| 提议者（draft） | **卡片**：各自产出一份"解释"（切片 + 类别），**互不干扰** |
| 接受 / 拒绝规则 | **组合算子**（`flip` `filter` `pair` `decide`）与调度：决定哪份解释**算数** |
| **质量由验证规则负责** | 算子规则是**手写、可审、可 diff** 的 |
| 提议者只影响**接受率** | 卡片只影响"**有没有可用的解释**"，不影响"**算不算数**" |

**最实的一条**：**提议者的质量只决定"能收到多少"，不决定"收到的东西算不算数"**。
⇒ 所以每张卡可以做得**窄而专** —— 一张不行，**不会污染整体**。
这也正是为什么"**加卡不伤老卡**"在本框架里是**中心不变量**：它就是"**提议者彼此隔离**"的保证。

**一处本质分歧（必须说清，否则会推错结论）**：
- 投机解码里，draft 是 target 的**近似**（同一个分布，只是更弱）；
- 我们的卡片是**专才**，不是核的近似 —— 它们做的是**不同的**事。
⇒ 这是**模式上的同构**（提议 → 裁决，**保证在裁决**），**不是机制上的同构**。
当成机制同构会推错：例如误以为"多堆几个生成卡就能逼近大模型" ——
§16 已实测，多任务训练**不会**让核更通用，只让它**不窄化**。

**方向上还要提醒一句**：投机解码保证"**最终输出分布不变**"；"加卡不伤老卡"保证"**旧提议不变**"。
两者不同 —— 加卡**确实会**改变最终答案（`flip` 把否定式组合从 26.7% 提到 **75.0%**）。别混为一谈。

### 5.5 已有的证据：这个"选择区"已被设计过，**一半做了、一半没做**

`dev-notes/13` §9 早就把"选择卡为什么只有 20%"拆成三个方案：

| 方案 | 机制 | 状态 |
|---|---|---|
| **A 候选槽位嵌入** | 候选区间内的 token 加一个可学的"候选编号"嵌入 —— **只改输入构造、一次编码** | **已做 ⇒ 假设被否**（§10.1：2 seed × 2 档 × 2 臂 = 8 组） |
| **B 候选独立编码 + 重排头** | 问句编码一次、**每个候选各编一次**，类别头变成 K 个候选向量上的打分器（**reranker 式**） | **未做** —— §9 注明"最贴合'选择'的语义，也天然支持 K 变大"，且"**若 A 无效 ⇒ 直接上 B**" |
| C 放弃锚点 | 选择只出类别、不出指针 | 不建议（丢了锚点就没法组合） |

⇒ **"指针卡给全部候选打分"落在方案 B 上，而 B 恰好是"已推荐但未做"的那一步。**

⚠️ **机制差别要盯住**：A 与 B 是**两种不同的绑定方式** ——
A 把候选标进**共享输入的构造**（一次编码），B 让**每个候选独立编码**再由重排头打分。
⇒ **A 已否，不等于 B 会否**；反过来，**任何"把候选标进共享输入"的二分类版本仍是 A 的机制**，
很可能同因失败。⇒ 测选择能力时**必须把两种机制分开报**，否则结论归因不到"问题在哪一层"。

**`experiments/anchored_select/` 的实际口径（已核实）**：把上下文与候选**拼成一条文本**
（`原文：{context}｜候选：{candidate}`）喂给一张卡 ⇒ 属于 **A 族（单次共享编码）**，
不是 B 族。所以它的结果**只有在过线时才可归因**（说明差别在**任务形态**：二分类打标 vs 选最优）；
**若不过线则归因混淆**（机制 vs 任务形态分不开），必须再补 B 族对照才能下"能力不存在"的结论。
它有一条好设计：**零训练基线**（"候选是上下文逐字子串 ⇒ 支持"）与针对它的对抗集
（同义改写 / 同词表换位置）。

⚠️ **同一个实验里的静默截断风险（我已挂到 board）**：卡声明 `max_len=96`，而
`dev-notes/17` 探针 **P5 实测 tokenizer 静默截断** ⇒ 超长样本会把「候选：」切掉，
**标签随之失效**；而 `build_data.py:447` 的断言比的是**未截断的 `text`**，抓不到。
⇒ 训练前必须加"逐样本实际编码、断言未被截断"的守卫并报丢弃条数。

**阶段 A 实测（`experiments/anchored_select/results/main_s{42,43}.json`，核冻结、只训头）**：

| 分裂 | n | bin_acc s42/s43 | exact | 多数类 | **朴素规则** | anchor_hit |
|---|---|---|---|---|---|---|
| train | 8000 | 0.6894 / 0.6919 | 0.348 / 0.357 | 0.50 | **1.00** | 1.8% / 2.1% |
| test | 1600 | 0.6162 / 0.5994 | 0.308 / 0.296 | 0.50 | **1.00** | 0.6% / 0.8% |
| **对抗集** | 600 | **0.5250 / 0.5383** | 0.223 / 0.218 | 0.50 | 0.50 | 0.3% / 0.7% |

**三条读法**：

1. **train/test 的标签按构造就等于朴素规则**（正例=逐字片段、负例=保证不在上下文）⇒ 这两分裂**没有信息量**，
   而卡（0.60~0.69）**远低于零参数规则（1.00）** ⇒ 它**连这条平凡规则都没学会**。
2. **唯一有信息量的是对抗集**（规则在那里塌到 0.50），而卡在 **0.525 / 0.538 ≈ 随机**；
   n=600 的二项噪声约 ±2pt ⇒ **这不算学习证据**。
3. **`anchor_hit` 0.3%~2%** ⇒ **锚定发射几乎从不发生**；`exact` 仅 0.22~0.36
   ⇒ **类别头学到一点（0.69 vs 0.50），但锚定完全没接上**。

**⇒ 结论（看到联合臂之后，更正一次我先前的判断）**：

- **打标那一半有信号，但它是「表层捷径」**：test 61.62/59.94 vs **随机标签对照 52.69/51.88**
  ⇒ 真实增益 **+8.9 / +8.1pt**；然而**对抗集只有 +0.50/+1.83pt**，且 `reorder` 规则
  **44.33/43.00 低于随机**（**方向性答错**）⇒ 学到的是**「候选是否逐字含于上下文」这条字符串捷径**，
  不是"有证据支持"的语义判断。
- **锚定那一半在冻结下完全不学**：正例 **607/800、599/800 把起点预测成 0（塌缩）**，双命中仅 **0.75%**。
- **把核放开（联合臂）能把锚点救到 50.75%**，代价是**对抗集塌回 51.50/50.33（<52）**
  ⇒ **核越学会表层规则，对抗集越差**。这是本轮最有价值的一条：
  **"锚定"与"语义判断"可以被分开买到，而当前只买到了前者。**
- 联合臂 **P4 全过**（四老卡 Δ ≥ −各自带宽，两 seed）⇒ 这条路径**不伤老卡**。

⇒ 我先前那句"失败在锚定/绑定，不在任务形态"**要拆成两半**：**打标能学（学的是捷径），锚定在冻结下不学。**
⇒ **"锚定候选打标"仍未解决**，只是**看起来**解决了一半。

⚠️ **我要明确不采纳"能学"这个判定标签**：P1/P2/P3 **按预注册字面确实全过**，但
**δ 被 2pt 下限钉住，而 n=600 的单 seed 分辨率约 ±3.6pt** ⇒ **过线余量（+0.5pt）低于分辨率**
⇒ **字面通过，判别力不足**。（与 §14 我那个 `|Δ| ≤ band` 是同一类"判据方向/尺度写错"。）
**⇒ 诚实判定：证据不足**；修法是**对抗集扩容**，或把门槛写成"余量 > 2×SE"。

**⇒ B 族仍然该做，但预期要调低，且必须先补一个消融**：
做一组「**正负 = 语义等价判定、去掉一切字面相关物**」的消融 —— 若它上面仍有增益，才谈"选择能力存在"；
否则只是**字符串匹配**。（B 族的价值不变：它**不需要发射锚点**，正好绕开本轮唯一确定失败的那一环。）

⇒ 把 P2 按**设计意图**读作 `heldout_pair` 子集 ⇒ **判定落到 ③ 证据不足**（两种读法并列，未硬选）。

**两条正面收获（比判定本身更有用）**：

1. **A 的失败被干净地定位在"锚点发射"**：A 族（共享编码 + 发射锚点，双命中 0.75%）train 只有 **68.9 / 69.2%**；
   B 族**不发射锚点** ⇒ train **100%**、test **94.48%**。
   ⇒ **A 的失败确在锚点环节**，不在"共享编码"本身。
2. **两族共同的天花板 = "换说法"**：A 与 B 在 `heldout_pair` / 对抗集上**都 ≈50%**。

   **当前表示层不支持「换说法后的语义等价判定」** —— 与 §16「上限由表示决定」一致。

逐词（跑后描述性）：A 的 heldout 两极（`出现` 1.00 / `方便` 0.95 ｜ `详细` 0.00 / `上升` 0.00），
D 把系统性偏置拉回 ~0.5（`详细` 0.48 / `上升` 0.44）却**丢掉高分词**（`出现`→0.59 / `稳定`→0.61）。

**⚠️ 证据状态要更正（我先前说"四次实测都指向表示层"，不成立）**：
消融里 **D 过了 Q1** ⇒ **池化确实吞掉了一小部分可利用信号**（否则 D 不可能高于 A，且 Q3/Q5 已排除捷径与容量），
**但只值 5~6pt，且以 25pt 表内记忆为代价**。
⇒ 要判定"墙在表示/池化"，还差**两个条件之一**：
（甲）一种**既保住 `shifted`（≥ A−2.83）又让 2 字之差与上下文交互**的聚合过 Q1 ⇒ 墙在池化；
（乙）**在更强表示下同一四臂仍 ≈50%** ⇒ 墙在表示。
**当前按 PREREG 落 ③。**

**推断**：D 的 Q2 失败提示「**交互 vs 表内记忆**」在**冻结核**上互相挤占
（cross-attn 温度初值 1/√128 跑前定死、未扫 ⇒ 救不救得回 Q2 属**未测**，不得据此补跑刷分）。

### 5.6 决定性对照：**墙不在表示，在「核冻着」**（条件「乙」被推翻）

`experiments/select_semantic_joint/`（唯一变量 = 核是否可训；同数据、同步数、同 mean-pool、同 seed）：

| 臂 | seed | `heldout_pair` | Δ vs 冻结核 | Δ/SE | `shifted_pos` | test |
|---|---|---|---|---|---|---|
| 冻结核 | 42 / 43 | 49.52 / 51.04 | —— | —— | 92.56 / 92.48 | 94.48 |
| **核可训** | 42 / 43 | **59.36 / 63.20** | **+9.84 / +12.16** | **+6.96 / +8.60** | **99.60 / 99.60** | 99.88 / 99.84 |

- **R1 过**（两 seed 同号）；**R2 反向过** —— `shifted` **升到 99.60**，**不是拿表内记忆换**
  （与池化消融 D 臂「25pt 换 5.6pt」正好相反）；
- **R3 的 2×2 交互表是这条结论的关键**：核冻结{真 49.52/51.04 ｜ 随机 51.84/51.60}、
  核可训{真 **59.36/63.20** ｜ 随机 48.24/49.76} ⇒ **只有「核可训 ∧ 标签为真」离开 50%**；

正确说法是：**在「核冻结」这一条件下**，所有语义等价测量都落到 ≈50%；
**一旦核可训**（温启动联合 + 老任务锚定），`heldout` 升到 **59~63%**、`shifted` **99.6%**、`test` **99.9%**。
⇒ **表示是可训的；锁住它的是「冻结核」这个设定**，不是表示本身。
⇒ 这与项目基本框架直接相连：**温启动联合本来就是「让核参与训练」的机制**。

**⚠️ 但不等于"问题解决"（必须一起读）**：

1. **59~63% 距可用仍远**，两 seed 差 **3.84pt ≈ 2.7 SE** ⇒ 这是「**必要条件的证据**」，不是解决；
2. **100 步探跑已 55.12、漂移仅 0.0279 ⇒ 增益未见饱和**；
   步数 / lr / 老任务权重**一律未扫**（跑前定死，不调参刷过）⇒ 下一枪是**新 PREREG** 上扫这三项；
3. **只重测了 mean-pool 臂 A**：「同一四臂」被实例化为「同一臂 A」
   （D 臂因「25pt 换 5.6pt」本不该用）⇒ 严格说**四臂没有全部重跑**；
4. 主臂每步**另加 4 个老任务批次**（J3 口径），**其零梯度等价性已实测**
   （冻核跑 20 步 vs 只跑 select ⇒ 打分头 `torch.equal = True`）⇒ **不是第二变量**，
   但它**锚住**了可训核 ⇒ 本次「更强表示」=「**被老任务锚住的可训核**」；
   **未跑**的一档：只让核学 select、不给老任务（预期代价是 R5，**PREREG 未预注册**）。

**补充（按归因纪律复核后的标注；结论不变）**：

- **Δ 是配对差的保守版**：R1/R2 的 Δ 是**同 seed、同一批 1250 条 eval 样本上的配对差**，
  而报出的 SE 是**独立二项 SE** ⇒ **Δ/SE 是下界**（配对 SE 只会更小，结论只会更强）。**配对 SE 未算。**
- **自变量核查（强化）**：参数量 ×11.3、步时 ×134、显存 ×24 —— **三个可观测量全都大动**，
  不是"两臂一模一样"的**假对照长相**；叠加「冻核跑 joint 循环 vs 只跑 select ⇒ 打分头 `torch.equal = True`」
  ⇒ 变的确实只有 `requires_grad`。
- **探针同构性（强化）**：步时在**真实训练循环内**量的 ⇒ 逐步 0.2543×1800 = **457.7s** vs 单跑 **476.5s**（差 **4.0%**），
  unit 墙 **32min9.5s** vs 4 跑合计 **1919.9s = 32.00min** ⇒ **逐步 / 单跑 / unit 三处咬合（<5%）**。
- **置信度分级**：**R0/R1/R2 = 强**（2 seed + 同批配对 Δ + 4 条门禁全过 + `shifted`/`test` **反向涨**）；
  **机制归因「增益来自核参与 select 任务」= 中** —— 缺「**只让核学 select、不给老任务**」那一档
  （随机标签臂已排除「光有漂移就够」，但**没有分解**「老任务锚定 + 真标签 select」与「纯 select 梯度入核」）。
- **两项未排除**：① 峰值 **+1.88 GB** 里只有 **~27 MB** 能对上（参数 + 梯度 + AdamW 状态），
  余下 ~1.87 GB 归因于反传激活 + 老任务计算图，**未逐层字节对账** ⇒ 按"对不上账即可能有隐藏开销"的纪律，**未排除**；
  ② **梯度 norm 未拆分**（select CE vs 4 老任务对核的梯度谁主导）⇒ 先前的"老任务占 0.99999"是
  **损失值占比、不是梯度占比**，**不得读成"select 信号被淹没"**（train = 100% 是反证）。
- ⇒ **该补的第一件测量 = 梯度 norm 拆分**（比补一档训练便宜得多）。

## 6. 价值观卡与「自我交叉强化」（用户提案）

**提案**：引入**价值观卡**（输出 = 值判断的 `span + 类`，如 得体/冒犯、安全/有害），
并用它**控制学习率**，形成卡间的**交叉强化**闭环。

### 6.1 它为什么有吸引力

- 价值观卡**就是一张普通卡**（span + class）⇒ 用**现成机器**训、**现成判据**测，不引入新契约；
- 它给出**逐样本权重**（而非均匀 loss）：模型自己判为"不妥/存疑"的样本降权 ⇒
  是一种**由模型自身价值判断驱动的课程/重要性加权**，形似 RLHF 的奖励模型但**在架构内部**；
- 控制信号是 **(span, class)** ⇒ **可核对**，比一个标量 reward 可审计得多。

### 6.2 四条风险（必须写在前面）

1. **自强化 / reward hacking**：控制者若判错，就会**放大自己的偏好**（正反馈）。
   本项目已实测卡的**分布外可靠性很差**（路由 9.19% / 类型 29.78% / 拒答 ~96% 误开火）——
   **把不可靠的卡用作"训练控制器"，比用作"输出"危险得多**。
2. **直接冲撞铁律 1**（元决策不交给模型）：**学习率控制是关于训练的元决策**，是所有元决策里最重的一个；
   立这条铁律正是因为**已经测过三次元决策失败**。
3. **非平稳**：控制者自己在被训练 ⇒ 控制规则边训边变 ⇒ **无收敛保证**，
   且**可复现判据被破坏**（同 seed 同数据不再给出同一轨迹）。
4. **判据被破坏**：本项目大量判据依赖"逐位一致"的三重对照，学出来的 LR 控制会让训练路径**不可比**。

### 6.3 把提案改成可测的三阶段（**这才是要纳入规划的东西**）

| 阶段 | 做什么 | 为什么这样切 |
|---|---|---|
| **1** | 价值观卡先做**纯输出卡**：建数据集（train/test/**对抗集**）、训头、测**可靠性与分布外** | 它若不可靠，控制者角色**根本不可能**；最便宜也最决定性 |
| **2** | **有界控制**：只调**逐样本权重**（不是全局 LR），权重**硬界**（如 [0.5, 1.5]）；**控制者在控制期内冻结**；控制信号必须与**外部代理真值**做相关性核对 | 冻结去掉非平稳；硬界防爆炸；外部核对防自说自话 |
| **3** | 只有 1、2 都过，才谈真 RL 环 | —— |

**并且先做一件更便宜的事**：价值观卡先当**审计信号**（标注 + 降权 + 记录），**不闭环**
⇒ 拿到可解释性，却**没有反馈风险**。这条几乎零成本。

### 6.4 判据（跑前写死）—— 核心是 **hacking 探测器**

| # | 判据 | 门槛 |
|---|---|---|
| V1 | 价值观卡**可靠性**（test） | ≥ 多数类 + δ，2 seed 同号 |
| V2 | **对抗集**（同词表换位置 / 同义改写）上不塌回多数类 | ≥ 多数类 + δ |
| V3 | 与**外部代理真值**的相关性（**不是自评**） | 报 Spearman / 一致率 |
| **V4** | **hacking 探测器**：闭环后**目标指标**（任务本身的 exact）与**控制者自身指标**（价值观卡判对率）**分离报告** | 若只涨控制者自己的指标而目标不涨 ⇒ 判**自强化**，未通过 |
| **V5** | **冻结 vs 共适应 vs 无控制** 三臂对照 | 若"共适应 − 冻结"< 0 或落在噪声内 ⇒ 闭环无收益 |
| **V6** | **故意偏置的控制者**必做：注入一个偏置的价值观卡 | 必须观察到环**放大偏置**（证明 V4/V5 不是空话），或 leash 确实挡住了 |

⇒ **V6 是这套东西的判别力来源**：没有它，V1–V5 全都可能是恒真的。

### 6.5「损失评估」的正确定位（用户补充）

提案还有一条：让卡片参与**损失评估**。这里必须分清两件**完全不同**的事。

**(a) 评估"数值损失"是多余的 —— 损失本来就知道。**
我们有精确的 loss；再学一张卡去估计它，除了引入误差**没有任何信息增益**。
⇒ **卡片唯一有意义的用途是评估「损失里没有的维度」**，即**价值维度**（有害 / 不得体 / 不忠实）——
而这恰好是数值损失**无法表达**的东西。
⇒ 正确的说法是：**价值观卡不是"再算一遍 loss"，而是"给 loss 增加一个可判的价值维度"**。

**(b) 两种角色，风险差一个数量级。**

| 角色 | 做什么 | 风险 |
|---|---|---|
| **诊断（安全，先做）** | 一张卡按 `(输入, 预测, 真值)` 输出**错误类别**（类别错 / 跨度错 / 背景误开火 / 价值维度错） | **零反馈风险**，纯离线；直接给出**结构化错误分解** |
| **在环（危险，后做）** | 同一张卡的输出去调**逐样本权重 / loss 各项权重 / 学习率** | 继承 §6.2 全部四条风险 |

**(c) 诊断角色有一条硬判据**：项目**已经有规则可算的错误分解**
（`cls_acc` / `span_hit` / `bg_fp` / `slice_precision`）⇒
**"错误分类卡"必须打败规则分解，否则它没有存在理由** —— 规则就是它的基线，而且规则免费。

**(d) 可复现性其实可以保住**（这条给阶段 2 减负）：闭环**不必**破坏可复现 ——
只要**控制者在阶段内冻结**，它就是 `argmax` 的**确定性函数** ⇒ 同 seed 同数据仍给同一轨迹。
**这正是阶段 2 要求"控制者冻结"的第二个理由**（第一个是去非平稳）。

**(e) 判据补充**

| # | 判据 | 门槛 |
|---|---|---|
| **V7** | 错误分类卡 vs **规则分解** | 必须在至少一个错误类别上**显著优于**规则分解；否则判"无增益"，不做 |
| **V8** | **价值维度必须是 loss 里没有的** | 必须证明该维度**不能由现有 loss / 指标线性推出**，否则它只是数值损失的复述 |

### 6.6 价值观卡阶段 1 实测：**证据不足，不进阶段 2**

| 集合 | n | 主臂 s42 / s43 | 多数类 | **朴素规则** | 随机标签对照 |
|---|---|---|---|---|---|
| train | 8100 | 62.02 / 64.00 | 40.00 | **100.0** | — |
| test | 1500 | 49.13 / 49.93 | 40.00 | **100.0** | 34.20 / 38.67 |
| adversarial | 600 | 36.17 / 35.50 | 33.33 | 0.0 | 32.50 / 13.67 |
| **gold（自然句）** | 120 | 40.00 / 36.67 | 33.33 | 41.67 | — |

- **V1 ✅**（test 49.13 vs 门槛 42.00）；**V2 ✅ 但边缘**（仅超 **+0.84 / +0.17pt**）；
  **V3 ❌**（Spearman **ρ = 0.3223 / 0.2976 < 0.40**；一致率仅 s43 超门槛 0.01pt 勉强过）
  ⇒ **判定 ③：证据不足，`recommend_stage2 = false`**。
- **V-bonus ✅**：随机标签对照塌回多数类（34.20 / 38.67）⇒ **V1 不是恒真**，管线可信。
- 机制：**冒犯类召回塌到 0.125 / 0.075**（120 条只判出 7/5 条）；三类分数**均值排序方向正确**，
  但**类内散布过大** ⇒ ρ≈0.30。

⚠️ **我的补充判断（比"证据不足"更强一点）**：**这个数据集的构造本身产不出可用的价值观卡。**

- train/test 的标签**恰好等于朴素规则**（注入词表词 ⇒ 规则 100%）⇒ 卡（49%）**输给免费的词表规则（100%）**，
  它学到的是**注入痕迹**；
- 唯一测"**自然用法**"的 `gold` 集（手写自然句、均长 12.68 字）与 train/test（注入句、均长 28.8 字）
  **是两个不同分布** ⇒ "test 49%" 与 "gold 40%" **量的不是同一件事**；
- ⇒ **V1 通过 ≠ 价值观卡可用**：它在注入分布上赢多数类，却赢不过词表规则，在自然用法上崩。

⇒ **要价值观卡，必须用「自然用法的标注句」建数据集**；注入式构造只会教会模型认注入。

**阶段 2 因此不开做** —— 这正是 §6.3 计划里写死的结果分支。
好消息是 **V4/V5/V6 的设计已写死在 `PREREG.md`**（hacking 探测器 / 三臂 / 故意偏置控制者含 leash 开关），
将来换数据集重建时可**原样复用**，不必重设计。

## 7. 数据生成模式：卡片提议 → 投机解析块筛选 → 重整成句

**用户给的形状**：① 卡片初步生成 **token / 简单句子 / 指针式分析原始数据**；
② **投机解析块**做**有效性筛选**；③ **重整模块**把 token 碎块**拼接成完整句子**。

### 7.1 关键认识：这是**数据生成器**，不只是推理链路

它攻的正是我们刚踩的坑：`anchored_select` 用**注入式合成**造数据 ⇒ 标签**恰好等于朴素规则（100%）**
⇒ 模型只能学**注入痕迹**。而"让卡片在**真实输入**上自己提议候选、再由筛选器判有效性"生成的数据，
**分布就是部署分布**，且**标签来自另一个来源**。
⇒ 它属于 **rejection sampling / STaR 式自训练**那一族。

### 7.2 必须先定的设计决定：**筛选以「可核对谓词」为主，不以学出来的分数为主**

- 筛选器若是**学出来的分数** ⇒ 重新引入 §5.3 的**断裂 1（无精确性定理）**：幻觉可以"通过验证"；
  与 §6.2 的 reward hacking 是同一个病。
- 筛选器若是**可核对谓词** ⇒ **项目已有的不变量就是免费筛选器**：
  **锚定**（区间必落在原文）、**闭合/可溯源**（每个内容片段可回溯）、**手写算子规则**（可审计）。

⇒ **准则：能用可核对谓词判的，就不许交给学出来的分数**；
必须用学的那部分，先按 §6.4 实测其可靠性与 hacking 探测器。

### 7.3 三种候选按**风险递增**排序，必须按这个顺序做

| 来源 | 可否核对 | 结论 |
|---|---|---|
| **指针式分析原始数据** | ✅ **天生可核对**（内容词必在原文） | **先做这个** —— "筛选"这一步几乎免费 |
| **简单句子** | ⚠️ 需要筛选器真的会判 | 第二步 |
| **token 碎块** | ❌ 最接近自由生成 | 最后做 |

并且**投机单位要降到「词组」而非句子**（§5.3 已确立：**只有词组级才能部分接受**）。

### 7.4 重整模块的硬约束（否则保证从这一环漏掉）

重整**不许改内容词** ⇒ 只发**编辑操作**（插入连词 / 调序 / 标点），**内容 token 上锁**。
于是不变量可判：**每个内容词都能回溯到"被筛为有效"的候选**。
若重整自由生成 ⇒ 保证丢失，只能退回"另加事实一致性卡"的**弱**保证。

### 7.5 自训练环的三条退化守卫（这一族的已知病）

| 病 | 守卫 |
|---|---|
| **分布塌缩 / 模式坍塌**（只吃自己筛出来的） | **保留原始数据下限比例**，并**报多样性指标** |
| **筛选器退化**（接受率 ≈1 或 ≈0 ⇒ 标签无信息） | **报接受率**，要求落在**非退化区间**，否则该轮数据无效 |
| **过拟合自偏好** | **§6.4 V4 的 hacking 探测器**：目标指标与控制者自身指标**分离报告** |

**再加两条我们踩过的**：① **必须验"没有免费捷径"** —— 任何朴素规则在训练集上 ≥90% ⇒ 该轮数据无效；
② **保留一个自然用句的 held-out 集**（`value_card` 的教训：`gold` 与 train/test 是**不同分布** ⇒ 数字不可比）。

### 7.7 重整模块：**结构化指令 + 确定性渲染**

用户格式：`[袋] => [1][2][3]，我们可以[4]试试(5)吗？`（**骨架 + 槽位**）。

**这比"生成表面形式"更强**：重整层的输出从**句子**降为**结构指令**（骨架 id + 槽位指派），
**渲染 = 确定性纯函数** ⇒ **P2 / P3 原样恢复**（逐字包含 + 纯函数可复现），
而**表达力改由骨架表规模提供** —— 不是靠放开字面锁。

**三条硬规则**：

- **规则 0（指派独立于袋序）**：`[1][2][3]` 读出来是"我你喜欢"，句子要"我喜欢你"
  ⇒ **指派 (1,3,2) 独立于袋序**；**指派是重整层唯一的输出**。
- **规则 A（骨架字面只许纯形式词）**：骨架字面**只能是标点 / 形式功能词（们 / 吗 / 和 / 与）+ 词序**；
  **实义词一律进槽**（**实义词 ∩ 骨架字面 = ∅**，**词典谓词可查**）
  ⇒ `试试` 必须进槽，否则骨架就偷偷承载了内容。
- **规则 B（槽位带类型 + 题元）**：名 / 动 / 形 + 施事 / 受事 / 时；**指派必须类型匹配**（谓词，不是模型）。

**例子（同袋多候选 ⇒ 接 §5 投机式）**：
输入 `这次项目复盘，用户说加载太慢，我们下周要修。`；
袋 = `1用户(名·施事) 2加载 3太慢 4我们 5下周 6修 7说`（均**逐字 + span + 题元**）；
骨架 `S1 = [1][7][2][3]，[4][5]要[6]。` ⇒ `用户说加载太慢，我们下周要修。`；
骨架 `S6 = 因为[2][3]，[4][5]要[6]。` ⇒ 同袋的另一个候选。
⇒ **"理解含义"被压成有限分类**（**选骨架 + 填槽 = tagging**，正是 §5.1 说现有卡的长项）。

**买到什么**：

- **P2 / P3 原样恢复**（逐字包含 + 纯函数可复现）；
- **学出来的部分被关进可枚举空间**（骨架数 × 指派数）⇒ 可报**混淆矩阵**、可**预注册**；
- **缺块 / 类型不符 ⇒ fail-closed 拒答**；
- 充要条件变成 **骨架覆盖率**：覆盖不足的出口是**人写新骨架**（过门禁：**老骨架渲染逐字不变**），
  **不是放开字面锁**；**表达力上限 = 骨架表规模**（§3 模板表的推广）。

**两条仍未解决的（都进词面守卫）**：

1. **题元方向 —— P2 对此全盲**：`你说喜欢我` → `我喜欢你` **字符串全过、命题相反**。
   ⇒ 槽位必须带**题元标签**；**指派与块标签冲突 ⇒ 谓词拒答**；
   **无角色标签时 fail-closed 到「只复述、不换方向」的骨架子集**（**不猜**）。
2. **连词 / 情态分两级**：
   - **纯形式**（标点 / 们 / 吗）：**零命题贡献** ⇒ 可自由插；
   - **逻辑词**（因为 / 所以 / 但；要 / 能 / 可以；不 / 没）：**有真值贡献**
     ⇒ 只能由**意图卡声明**或**输入有据**时才可插，否则 `S6` 的"因为"就是**编的因果**。
   ⇒ 词面守卫的覆盖清单扩为：**数字 / 否定 / 情态 / 专名 / 因果-转折连词**。

⇒ **一条总体结论**：这条路把"生成"关进了**可枚举空间**，
所以**结构保证与表达力不再对立** —— 前者由「**指令 + 纯函数渲染**」保证，
后者由「**骨架表规模**」提供。**要更强表达力就写更多骨架，而不是放宽锁。**

### 7.8 结构化输出的收益边界与验收

**成立的部分（结构化输出买到的）**：

1. **自由文本 → 有限符号串决策**：可枚举、可预注册、可进 CI；
2. **监督变密**（这是最实的技术收益）：**整句一个 loss 不知道错在哪**；
   每槽一个标签能把错误定位到"**第 3 槽的施事 / 受事填反了**"；
3. **全链可溯源打通**：句子成分可挂回 `plan_step_id + span`，
   与 §2 第一层的 `Plan = [Step{…}]` **同构**。

**边界（必须划清）**：**槽位指派是对象层判别**（**有谓词、可交模型**）；
**元决策仍归规则表** —— 不因为"结构化"就把元决策放给模型。

**⚠️ 不许诺的部分**：这条容易被读成"**通用理解会变好**"，而**我们已有反证**：
§0 第 3 条（C3 / C5 相对未训练核都在 δ 内）与 §16 的实测 ——
**多任务训练不增强通用性，只让它不窄化，上限由表示决定**。
⇒ 可以许诺的只有「**对齐判别这类任务更准**」（指针卡已有 9 张实测支撑）；
**不可以**许诺「通用理解变好」。

**要证据就必须写死这三条**（缺任一条结论都不能下）：

| # | 判据 | 门槛 |
|---|---|---|
| **S1** | **槽位 / 题元准确率**（test + **对抗集**） | 2 seed 同号；**余量 > 2×SE**（沿用 §5.5 的教训） |
| **S2** | **`整句 loss` vs `槽位监督` 对照臂** | **缺这一臂只能说"换了监督形式"，不能说"更好"** |
| **S3** | **未训句式的迁移对抗集** | 报数字；这是唯一能区分"**学会了填槽**"与"**背下了句式**"的判据 |

**对抗集是必需项、不是可选项** —— 两个实测教训指向同一件事：
`anchored_select`（卡 0.69，**连 1.00 的平凡规则都没学会**，对抗集 **0.525 ≈ 随机**）
与 `value_card`（注入式标签**恰好等于词表规则 100%**）—— **捷径会吃掉结构化标签**。

**代价（必须预先写进判据）**：

- **表达力上限 = 骨架表规模**（这是**设计选择**，不是缺陷）；
- **槽位化会把角色卡的错误显式暴露** ⇒ **初期拒答率会升高** ——
  这条**必须预先写死**，否则将来会被误读成"退化"。

### 7.9 解引用层：结构化输出 → 用户文本，**引用信息必须留存**

用户澄清（这条把整条输出链的性质定下来了）：

> **语义结构化的目的是给模型加约束**；**最终输出一定要解引用**；
> **解引用模块必须保留引用信息**；**使用者可以不知道结构，但解引用模块要能看到原始输出**。

**⇒ 输出链是三段；结构不是用户界面，而是「模型 ↔ 解引用模块」之间的契约**：

```
模型输出：结构化 + 带引用      ← 「语义约束」在这一层强制（schema / 类型 / 题元 / evidence = 谓词）
   ↓ 解引用模块：只做表面形式，且必须保留引用映射
用户看到：自然语言文本          ← 每个内容片段仍可回溯到结构 → 原始 span
```

**这条澄清买到的东西（很重要）**：**结构不必好读** —— 因为**使用者看不到它**。
⇒ 结构可以做到**任意严格、任意冗长**（全骨架 + 全槽位 + 全题元 + 全 provenance），
**而"加约束"的成本为零**：不好看只影响解引用后的文本，不影响结构的信息量。
⇒ 这也回答了"为什么值得结构化"：**约束加在结构上，表达力损失由"骨架表规模"补**（§7.7）。

**四条不变量**：

| # | 不变量 | 强制点 |
|---|---|---|
| **I1** | 模型输出**必须满足 schema**（类型 / 题元 / evidence 齐备） | **谓词校验**；不满足 ⇒ **拒答**（不交给模型判） |
| **I2** | 解引用**只做表面形式**（骨架渲染 + 功能词），**不改内容** | 渲染是**确定性纯函数** |
| **I3** | **解引用必须保留引用映射**：文本每个内容片段 ↦ 结构引用 id ↦ 原始 span | **映射表存进记录**，回溯链**不许断** |
| **I4** | 结构**不是用户接口** | 它只在「模型 ↔ 解引用模块」之间流动 |

**⚠️ 由此得到两道独立的检查（比"末端查一次"强得多）**：

1. **结构侧**：schema + evidence 谓词 ⇒ 挡住「**结构里出现无据命题**」；
2. **解引用侧**：**文本的每个内容单元都必须映射到结构里的某个单元**（用 I3 的映射表判）
   ⇒ 挡住「**渲染时偷偷加内容**」。

⇒ **幻觉只有两条入口，且各有各的谓词**：入口 1 在结构、入口 2 在渲染。
**两道都谓词化 ⇒ 零幻觉从"末端抽查"变成"逐段可判"。**

**这解释了 §7.8 的"代价"为什么可接受**：槽位化会让角色卡的错误**显式暴露**（初期拒答率升高），
但**暴露在结构层**、而非泄漏进用户文本 —— **这正是设计想要的**（fail-closed 挡在结构侧）。
## 8. 可行性判据（跑前写死）

| # | 判据 | 门槛 |
|---|---|---|
| P1 | **不退化**：加生成卡后老卡 pred/exact 相对各自噪声带 | Δ ≥ −band（逐卡，不许统一阈值） |
| P2 | **证据覆盖**：生成内容被 evidence 锚点覆盖的比例 | ≥ 90%，且矛盾率 ≤ 5% |
| P3 | **组合增益**：生成卡 + 上游卡 vs 只用生成卡 | ≥ +15pt（证明"调度其他卡"真有增量） |
| P4 | **拒答校准**：分布外拒答率 / 分布内误拒率 | OOD 拒答 ≥ 80%，误拒 ≤ 5% |
| P5 | **可读性** | 需先定义（人工抽检 ≥ X 分 / 裁判模型） |

≥2 seed；P1 与 P3 是硬门槛，P2/P4 若不过则**如实报"生成型在这套架构下不成立"**。

## 9. 要你定的三件事

1. **生成粒度**：拼接式（先做，复用现有指针架构）／自由生成（新解码器 + 忠实性判据）／两步走。
2. **忠实性怎么判**：人工抽检 / 裁判模型 / 用"事实一致性卡"做可判代理（我推荐第三条，因为它可自动化且能进 CI）。
3. **调度演进到第几级**：只做规则（稳）→ 半自主（提议+校验）→ 独立规划器（真自主，要对抗集验收）。
