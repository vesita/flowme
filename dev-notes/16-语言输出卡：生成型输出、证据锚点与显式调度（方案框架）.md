# 16. 语言输出卡：生成型输出、证据锚点与显式调度（方案框架）

## 0. 从实测来的约束（方案必须长这样）

| 约束 | 实测（都有产物） | 对方案的含义 |
|---|---|---|
| 能力可加 | 温启动联合：老卡 Δ≥0、新卡 0.937~0.982（§15） | 新增生成卡走同一条路：**核可训、老头冻结** |
| 元决策不可靠 | 路由 9.19%、输入类型 29.78%、拒答 ~96% 误开火（§7/§13/§14） | **"该调哪张卡"不能交给模型隐式决定** |
| 多任务不增强通用性 | C3/C5 相对未训练核都在 δ 内（§16） | 别指望"多补卡"换来能力上限；上限由表示决定 |
| 加卡不改窄化 | 三步连加 30/30 不退化、漂移减速（§17） | 补卡是**安全**的，可以放心加 |
| 选择族不可用 | `reply_pick`/`cloze_fill` 与盲猜不可区分（§9） | **不能靠"从候选里挑"来产出回复**，得换数据来源 |
| 输出侧三缺一 | 闭合性 ❌ 可溯源 ❌ 拒答 ❌ 确定性 ✅（§13） | 生成卡必须**显式实现**这三条，不能指望模型 |

## 1. 指针型 vs 生成型：区别在**发射什么**，不在解码器

两者的解码器**都可以是自回归的**（现有 `RobustARSliceDecoder` 就是 AR 的）。真正的差别是**发射的符号表**：

| | 指针型（extractive） | 生成型（generative） |
|---|---|---|
| 发射什么 | **位置**：`[start, end]` 区间 + 类别 | **字**：词表里的 token 序列 |
| 输出来源 | 必然是输入文本的**子串** | 可以是原文里**没有**的内容 |
| 零幻觉 | **结构性保证**（不可能编造原文没有的） | **没有结构性保证**，需另行核对 |
| 表达力 | 受输入限制；要"回复"就得先有候选 | 能真正回复/改写/总结 |
| 评测 | `exact_match` / `span_hit`（区间对齐） | 生成指标 + 忠实性 + 裁判 |
| 组合与审计 | 区间可高亮、可溯源、可核对 | 需额外带**证据锚点**才能核对 |
| 现有资产 | 全部 9 张卡 + 引擎 + 组合算子 | 无（要新解码器头） |

**中间态（推荐先走这条）——"拼接式生成"**：生成卡发射**若干指针区间**（可从原文、也可从上游卡的输出里取片段），
按顺序拼接成回复。它**仍是指针型**（零幻觉、可高亮），但已经能"输出语言"。
等它跑通，再决定要不要上真正的自由生成。

**分型输出记录**（让两种输出能共存、且下游不必分叉）：

```
指针型: {kind:"span", span:[s,e], class, score, evidence:[...], plan_step_id}
生成型: {kind:"text", text, evidence:[{module_id, span, class}], score, plan_step_id}
```

生成型的 `evidence` **必填**：把"零幻觉"从**结构性保证**降级为**可核对保证** —— 这是自由生成唯一能接受的代价形态。

## 2. 四层框架

### 2.0 决策机：有限 MDP = 手写状态机 + 经验转移

**形式化**：MDP = (S, A, P, R, γ)。分工是这套东西成败的关键 —— **不是全都手写**：

| 成分 | 谁提供 | 说明 |
|---|---|---|
| **S 状态（手写，有限）** | 手写 | `(声明的 type, 信号三态向量 {未查,有,无}, 剩余步)`。例：6 类 type × 3^6 信号 × 4 档剩余步 ≈ **1.7 万态** ⇒ **可完全枚举、可打印人工审** |
| **A 动作（手写，有限）** | 手写 | 调某张卡（≈7~11 个）+ 终止三选一 {指针输出, 生成输出, 拒答} |
| **P 转移（不手写）** | **经验估** | `P(s'|s,a)` 来自"卡在这类输入上实际会输出什么"。**手写概率等于把猜测固化** |
| **R 奖励（手写，但必须可自动算）** | 手写 | 组合增益 / evidence 覆盖 / 拒答正确 / 调用成本 |
| **π 策略** | **先手写，后学** | 手写 = 规则表（每状态一个确定动作）；跑通后用估出的 P 做值迭代 ⇒ **表格策略可打印、可审计、可 diff** |

**两条硬约束（都由实测逼出来）**：

1. **状态量必须"算出来"，不能"模型判出来"**。可用信号：卡是否产出切片（二值）、锚点数、
   置信度**硬阈值**化。一旦状态里混进"模型判出的东西"（如"这句是在询问"），
   状态就带上了元决策的不可靠性（路由 9.19% / 类型 29.78%）。
2. **分布外的 P 不可估**（§13：拒答 ~96% 误开火）⇒ **MDP 只在分布内有意义**，
   OOD 必须由"调用方声明 type"那一层**先挡住**，不能指望状态机自己处理。
   同理：**奖励若靠裁判模型，等于又引入一个不可靠元决策**。

**分三阶段（为什么不必一上来就要概率）**：规则策略**不需要 P 就能运行**；P 只在你要**优化**策略时才需要。
所以顺序是 **手写 S/A/π → 跑通 → 估 P → 改 π**。

**这个形式化真正买到的是「可验证」，不是「自主」**：
- 状态有限 ⇒ 能**枚举所有可达状态**，查出**死状态**（没有任何动作能到成功）、**非法动作**、
  以及**拒答是否可达**；
- 确定性策略 ⇒ **计划逐字可复现**（§13 已实测确定性），满足"显式决策"不变量。

### 2.1 决策机规格（可执行、可枚举）

**信号表 —— 四项全部"算出来"，无一项靠模型判**

| 信号 | 取值 | 怎么算 |
|---|---|---|
| `type` | 5 类 | **调用方声明**（§11.1），不是模型判 |
| `info` | 4 位，每位三态 `{未查, 有, 无}` | 每位 = 一个**必需信息位**（如 时间/地点/对象/意图）；"有" = 对应卡产出了切片**且**置信度 ≥ 阈值 |
| `conf` | 3 档 `{低, 中, 高}` | 最近一次调用的置信度**硬阈值**化（阈值取该卡在自己 val 上的分位） |
| `steps` | 3 档 `{0, 1, 2}` | 剩余可调用次数 |

⇒ **|S| ≤ 5 × 3⁴ × 3 × 3 = 3645**，**可完全枚举** —— 每个可达状态都能打印出来人工审。

**动作（有限）**：调用卡 i（现有 7 张 + 待补 4 张）+ 终止三选一 `{指针输出, 生成输出, 拒答}`。

**规则策略 v0（手写，不需要转移概率就能跑）**

| 条件 | 动作 |
|---|---|
| `type == unknown` | **拒答**（类型不确定不许猜，§7） |
| 存在 `info` 位 = `未查` 且 `steps > 0` | 调用该位对应的卡 |
| 存在 `info` 位 = `无` | **拒答**（缺必需信息） |
| 全部 `info` = `有` 且 `conf ≥ 中` | **生成输出** |
| 全部 `info` = `有` 且 `conf == 低` | **降级为指针输出**（更严谨） |
| `steps == 0` 且未完成 | **拒答**（不许无限调用） |

**验证点（每条都能一次判定）**

1. **状态数**：枚举真实**可达**状态数并打印，必须 ≤ 3645；
2. **无死状态**：每个可达状态都存在动作序列能到达某个终止动作；
3. **拒答受控**：`type == unknown` 的状态**只**能到拒答；`info` 缺位只能到拒答；
4. **确定性**：同一 `(type, 卡片输出)` 两次运行产出计划**逐字相同**；
5. **闭合**：计划中每个 `Step.input_span` 必须落在原文或上游产出上（可核对）。

### 第一层 · 调度层（显式，不训练）

输入 = 调用方按 §11.1 **声明的** `type`；输出 = **调用计划** `Plan = [Step{module_id, params, input_span}]`。

分三级演进，每级都**可判**、且不破坏已有结论：

| 级 | 谁决定调什么 | 可判据 | 现状 |
|---|---|---|---|
| **1** | **规则表**（type → 计划） | 同一输入计划**逐字可复现** | ✅ 确定性已实测 |
| **2** | **模型提议 + 规则校验**（提议不通过就拒答） | 提议接受率 / 误提议率（对抗集） | 待做，风险可控 |
| **3** | **独立规划器模块** | 对抗集上的调度正确率 + 拒答校准 | 这才是你说的"自主"；**必须过对抗集** |

⇒ **要"自动调度"，就得把规划做成第 3 级的独立模块**，而不是让语言输出卡顺手决定。
第 1 级先跑通端到端，第 2 级是低风险的"半自主"，第 3 级才是真自主。

### 第二层 · 卡片层

- **已有**：`pronoun` `sentiment` `relation` `person` `negation` `idiom` `ownership`（tagging，可用）
- **要补**（按"生成一条回复需要什么"倒推，每张都守现有 `span+class` 契约，因而天然可组合）：

| 新卡 | 作用 | 为什么生成需要它 |
|---|---|---|
| **意图/言语行为** | 这句是在问、在陈述、在请求？ | 决定回复的**形态**（答/确认/追问） |
| **槽位抽取** | 时间/地点/数量/对象 | 决定回复**必须覆盖什么**，也是 evidence 的来源 |
| **安全拒答** | 该不该回、是否越界 | 把拒答出口**显式化**（模型自己不会拒，§13） |
| **事实一致性** | 生成内容与原文是否矛盾 | **生成型的验收组件**：给 evidence 做矛盾检测 |

- **不加**：任何"从候选里挑"的卡（选择族当前不可用，§9）。

### 第三层 · 输出层

按 §1 的 `kind` 分型；统一记录 + `plan_step_id`（可溯源）+ `evidence`（可核对）。
不变量 = 闭合性 / 可溯源 / 拒答 / 忠实性（**前三条当前都不成立，必须显式实现**）。

### 第四层 · 训练路径（沿用基本框架）

1. 冷启动：训核 + 各 tagging 卡头；
2. 补 tagging 新卡（意图/槽位/安全/一致性）：**能只训头就只训头**；
3. 加生成卡：**温启动联合**（核可训、老头冻结），只放开生成头；
4. 数据：对话语料取「上文 → 该回复」对；上游卡的输出作为**附加输入通道**喂进来，
   **不让模型自己去找**（这正是"显式调度"落地的方式）。

## 3. 可行性判据（跑前写死）

| # | 判据 | 门槛 |
|---|---|---|
| P1 | **不退化**：加生成卡后老卡 pred/exact 相对各自噪声带 | Δ ≥ −band（逐卡，不许统一阈值） |
| P2 | **证据覆盖**：生成内容被 evidence 锚点覆盖的比例 | ≥ 90%，且矛盾率 ≤ 5% |
| P3 | **组合增益**：生成卡 + 上游卡 vs 只用生成卡 | ≥ +15pt（证明"调度其他卡"真有增量） |
| P4 | **拒答校准**：分布外拒答率 / 分布内误拒率 | OOD 拒答 ≥ 80%，误拒 ≤ 5% |
| P5 | **可读性** | 需先定义（人工抽检 ≥ X 分 / 裁判模型） |

≥2 seed；P1 与 P3 是硬门槛，P2/P4 若不过则**如实报"生成型在这套架构下不成立"**。

## 4. 要你定的三件事

1. **生成粒度**：拼接式（先做，复用现有指针架构）／自由生成（新解码器 + 忠实性判据）／两步走。
2. **忠实性怎么判**：人工抽检 / 裁判模型 / 用"事实一致性卡"做可判代理（我推荐第三条，因为它可自动化且能进 CI）。
3. **调度演进到第几级**：只做规则（稳）→ 半自主（提议+校验）→ 独立规划器（真自主，要对抗集验收）。

## 5. 已知阻塞（不能装作没有）

- `reply_pick` / `cloze_fill` 不可用 ⇒ **"从候选里挑最合适的回复"这条现成路径走不通**，
  拼接式生成的数据必须改成"从原文/上游输出里抽片段"。
- 输出侧三条不变量（闭合性/可溯源/拒答）**当前都不成立**，生成卡必须把它们**写进代码并加门禁**，
  否则会重复"分布外照样开火"（§13）那类失败。
- **前 3 步之前先做一件小事**：把引擎锚点的类别名统一为**规范名**（现在展示名 `积极/喜悦`
  与规范名 `积极` 两处来源，靠 `norm()` 补丁维持）—— 否则生成卡消费上游锚点时会踩同一个坑。
