## 1. 为什么它是里程碑（不是又一个实验）

- 框架契约：**卡与卡只通过模因张量 `[n,d]` 通信**；卡内必须 `[n,d] → [n,d]`（形状保持）。
- ⇒ **接口固定时，每张卡是一个可单独优化的函数** —— 这正是 **T1** 的含义
  （`I(M;Y|X)=0`：中介不产生信息 ⇒ 价值在"计算"）⇒ 每张卡承载一段**计算** ⇒ 原则上可被单独优化。
- ⇒ **"能单独训练一张卡" = 框架从"一个端到端模型"变成"一组可插拔单元"的分水岭。**
- 现状：**这一步从未做过** —— 至今全部实验都是**整套端到端训练**，门 B 只是**事后消融**（`retrain-without`），
  不是【独立训练单卡】。

## 2. 三层验收（每层判据写死，不许含糊）

| 层 | 做法 | 判据 |
|---|---|---|
| **L1 冻结其它卡，单卡训练**（block-coordinate）| 冻 **输入卡 / 输出卡**，只训 **目标卡** | 目标卡 EM **≥ 随机初始化**（**能学到**）且 **与端到端差 ≤ 5pp** |
| **L2 交替训练** | 冻 C 训 A → 冻 A 训 C → 轮换（**≥2 轮**）| 交替训练 EM **≥ 端到端 − 2pp** |
| **L3 可移植性** | **在模型 1 上训的目标卡，插进模型 2**（不同 seed / 不同任务桶）| **跨模型插卡后 EM 掉 ≤ 10pp** ← ★ **"卡片化"的验收线** |

**读法**：L1 只证明"在该固定接口 / 固定上游分布下这块能学"；**L2（交替）与 L3（跨模型）才是"可插拔"的真考验**。

---

## 3. 已知风险（必须正面写）

**目标卡看到的是"上游卡的输出分布"。** 冻结上游训练 ⇒ 目标卡只能在【该固定分布】上学到映射 ⇒
**上游一改就可能作废（off-distribution）**。

这与 **R26（模型读表层不读结构）**、**R16（消融口径：必须 `retrain-without`）**、
以及 **非破坏性干预**那一族是**同一个问题**：拿到的是某个分布上的读数，不是结构本身。
⇒ **L1 的成功必须带这个限定**（"在冻结上游分布下可训" ≠ "可插拔"）；**L2（交替）与 L3（跨模型）才是真考验**。

## 7. 接口层与版本控制（设计，未验证）

> **状态：设计规格，不是已完成的实验。** 文献结论只引自已入库的
> `experiments/lit_survey/module_composition.md`（Branch-Train-Merge `2208.03306` · Sparse Upcycling `2212.05055` ·
> SCAN `1711.00350` / COGS `2010.05465` · Git Re-Basin `2209.04836` · SCAFFOLD），**不重新论证**。

### 7.1 类比与定位

```
输入卡 + 输出卡 = 接口定义（ABI）
模因 [n,d]      = 该接口上的数据格式（wire format）
中间卡（目标卡）= 实现（可替换、可独立升级）
⇒ 换 ABI ⇒ 实现作废；ABI 不变 ⇒ 实现可独立升级
```

### 7.2 版本定义（**写成可算的形式**）

```
模因版本 MV = hash(输入卡参数 + 输出卡参数 + 模因形状/接口契约)
卡片系列版本 = (MV, 该 MV 下已验证的目标卡集合)
⇒ 换 MV ⇒ 与新卡不可混用；MV 相同 ⇒ 目标卡可混用/可独立升级
```

### 7.3 三条判据（**每条都要能跑**）

| # | 要证什么 | 判据 |
|---|---|---|
| **I1 接口稳定** | 输入卡固定 ⇒ 不同目标卡产出的模因**可线性对齐** | 用 S26 的第 (iii) 口径（线性映射后余弦）**显著高于** mean-pool 口径，且高于随机配对 |
| **I2 版本可控** | MV 相同 ⇒ 跨模型插卡不掉 | **跨模型插卡后 EM 掉 ≤ 10pp**（= M2-L3） |
| **I3 能力不因冻结受损** | 冻结输入/输出卡时中间卡能逼近端到端 | **≥ 端到端 − 2pp**（= M2-L2） |

### 7.4 ★ 风险（必须正面写）

**若输入卡太弱 ⇒ 模因承载不了信息（T2 容量门槛）⇒ 中间卡再强也没用**
⇒ **"稳定"与"足够强"必须一起验**；I3 就是这条的守门判据（禁止用"接口很稳定但能力很差"来宣告成功）。

### 7.5 与文献判据的对应

**本节的"冻结输入/输出卡" = `module_composition.md` 判据 c 的"共享锚点"的工程实现**；
⇒ **随机初值各训（无共享锚点）应失败**（判据 c 预测）⇒ **这是 I1/I2 的必带对照臂**。

### 7.7 冻结 = 版本化（把用户的等式写成定义）

> **S25 结果待 S28 复核**（S28 独立复核中，含"等算力对照"臂1b 6000 步）。

```
冻结接口（输入卡 + 输出卡）≡ 版本化模因
⇒ 接口不动 ⇒ 模因语义不动 ⇒ 目标卡学到的映射可复用
⇒ 反证（已实测）：臂3b「全随机接口 + 冻结」= 0.12%/0.12% ⇒ 无版本 ⇒ 模因无意义
```

### 7.8 ★ 软冻结 vs 硬版本化

| 强度 | 做法 | 后果 |
|---|---|---|
| **软冻结**（S25 臂2/臂3 的做法）| 训练过程中不动接口卡 | **无跨实验快照 ⇒ MV 仍会漂移** |
| **★ 硬版本化** | **接口卡权重落盘为只读快照 + sha256**；所有实验**引用同一个快照 id** | **MV 稳定 ⇒ 卡可搬运** |

⇒ **结论：S25 的"冻结"是软冻结；要变成可搬运的版本，必须升级为硬版本化。**

### 7.9 快照协议（**可直接照做**）

```
① 接口快照 = 只读文件（输入卡 + 输出卡权重）+ sha256 + 冻结的契约
② 契约内容：d · n 的语义 · mask 约定 · 位置编码方式 · MAXLEN  ← **任一变了就是新 MV**
③ 每个实验报告必须写：MV id = (接口快照 sha256, 契约版本)
④ 换 MV ⇒ 必须重验 L3（跨模型插卡）；MV 相同 ⇒ 卡可直接混用
★ 反例（必须防）：权重一样但契约不一样 ⇒ **假同版本** ⇒ 会静默污染跨实验对比
```
