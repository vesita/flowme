## §3 新方案 / 新猜测（7 条 + 1 条整体方案）

> 每条都写"怎么验"（判据 + 成本 + 若失败说明什么）。所有成本按日志实测的 **2.4 min/run（3000 步、d=128、单卡）** 折算（`logs/19_res.log:42` 等）。

### 【方案 1】先把"泄漏"这个混淆项杀掉：用 add_2d / add_3d / mul_2d 做 2×2 对照，把"会算"与"见过"分开

- **我从哪条原始证据出发**：`logs/28_train.log:12`「(a,b) 数对重叠=16/800 条」（add_3d）＋ **我实测的五桶重合率 100.0% / 98.2% / 69.4% / 49.4% / 2.0%**（§2 C2 表）＋ EM 排序 add_1d 96.62% > mul_2d 82.62% > add_2d 71.88% > sub_2d 61.38% ≫ add_3d 2.50%（`logs/19_res.log:42/410/134/318/226`）。
- **机制/为什么可能有效**：把"数对是否在 train 出现过"变成一个**显式可控的自变量**。构造两个测试子集：`SEEN`（(a,b) ∈ train）与 `UNSEEN`（(a,b) ∉ train），**同一 ckpt、同一套指标**分别算 EM 与数字每步正确率。我实测的重合率说明这个自变量在每个桶里都有足够的两层：add_1d 没有 UNSEEN（100%）、add_3d 几乎没有 SEEN（2%），而 **add_2d / sub_2d / mul_2d 两边各有几百条**——它们就是天然的对照桶。
- **与现有路线的差别**：现有在做什么——按桶报一个总 EM，然后跨桶比较并解释成"进位链难度"。我建议换成——**同一桶内 SEEN vs UNSEEN 配对比较**，桶间比较降级为辅助。
- **怎么验**：① 对 `19_ckpt_add_*_res_seed*` 与 `19_ckpt_mul_2d_res_seed*` 直接用现成 ckpt（**零训练**，纯 eval，CPU，~7s/800 条，见 `logs/28_eval.log:12` 等每行 `7s`）算 SEEN/UNSEEN 的 EM 与数字每步正确率；② 再训一个 add_2d、**只在 train 中删掉 test 用到的数对**（改生成器 used 集合即可），判据：EM 从 ~72% 掉到 ≤10%。**判据写死**：若 SEEN 与 UNSEEN 的差 ≥ 2×SE 且 2 seed 同号，则"高分来自记忆"成立；若差 ≤ 1SE，则"记忆"假设被证伪，高分来自真正的短程外推。**成本：步骤① ~1 分钟 CPU；步骤② 2.4 min × 2 seed**。
- **若失败说明什么**：若 add_2d 在 UNSEEN 上仍有 ~70%，则泄漏不是主因，现有"会浅层算术"的解释站得住 —— 那反而是个**对项目有利**的结论，且它的价值远高于任何新架构。

### 【方案 2】把"残差 + 位置编码 + 迭代"当**一个**决定算子来扫，而不是三个互不相干的实验

- **我从哪条原始证据出发**：`logs/20_pos.log:142-143`「Δ seed=1234: -34.88±1.76pp \| nopos 37.25% → pos 2.38%」「seed=5678: -31.00±1.64pp \| 31.13% → 0.12%」＋ `logs/20_pos.log:149-151`「[Q1] nopos pre …⇒ 不变（≈浮点噪声）… pos pre … ⇒ ★不变性被打破」＋ `logs/15_iter_always.log:128/174`「k=4 EM=1.00% / k=8 EM=0.12%」。
- **机制/为什么可能有效**：日志已经把答案写在脸上了——**残差是"加一个恒等捷径"，位置编码是"给每行一个身份"，迭代是"把位置身份反复喂进同一个函数"**。三者作用于**同一个对象**（h 的行序）。S20 只加了 PE 就把 37.25% 打成 2.38%，说明 `[n,d]` 里的**行序信息是脆弱且关键的**；S15 的 k≥4 崩溃说明**反复施加同一个函数会摧毁行序**（k=8 数字 CE 5.09 nats ≈ 完全丢失输入）。所以正确的问法不是"残差有没有用"，而是"**行序身份是靠什么维持的**"。
- **与现有路线的差别**：现有在做什么——S15 单变量扫 k、S19 单变量扫残差、S20 单变量扫 PE，三个独立结论。我建议换成——**只扫一个变量：PE 的注入位置与方式**（在残差加之前 / 之后 / 加在目标卡输出上 / 用可学习行嵌入替代 sin_pe），固定 res=on、k={1,2}。特别地，**learned row-embedding** 与 **sin_pe** 的对比能直接回答"身份是内容绑定的还是槽位绑定的"。
- **怎么验**：add_3d，res=on，4 种 PE 注入方式 × k∈{1,2} × 2 seed = 16 run ≈ **40 分钟**。**判据**：与 baseline（sin_pe 加在思维卡输入之前，=S19-res 37.25%）配对 Δ ≥ 2×SE 且 2 seed 同号。**若失败说明什么**：若 learned row-embedding 与 sin_pe 无显著差异且 k≥4 仍崩，则"迭代摧毁行序"的机制解释被证伪，迭代崩溃另有原因（比如共享权重下的优化问题），应转去查梯度范数而不是继续改架构。

### 【方案 3】先证明"加法卡+位置编码"是必要的，而不是证明它有用——做**减法消融**

- **我从哪条原始证据出发**：`logs/22_card.log:206-213`（B=0.00%、C=0.12%、D=0.50%、E=0.62%，全部 \|Δ/SE\|≈18–22）＋ `MILESTONES.md:270` 区段引 `stages/08` 的「**恒等中介（思维卡 = Identity）配对 CE=0.3086，每步正确率 89.90% ⇒ 拿到低 CE**」＋ `MEME_FRAMEWORK.md` 同段「输入卡自己就能解题，思维卡可被完全旁路」。
- **机制/为什么可能有效**：项目已有一条**自证不清**的结论：一个 Identity 思维卡就能拿到低 CE。S22 的五臂扫描证明了"π 换成别的不行"（3 个反例都归零），但**没有证明"必须是一个可训练的 attention 块"**——因为最省事的基线（Identity、纯 MLP、纯卷积）在 add_3d 上给的是 0.00–1.25%，而在 add_1d/add_2d 上可能并不差。真正该问的是：**在无泄漏的任务上，一个参数量对齐的普通 Transformer（没有"卡"的概念）能不能超过这套三类卡闭环？**
- **与现有路线的差别**：现有在做什么——所有对照都是"改卡内结构"。我建议换成——**对照整条框架本身**：一个同参数量（~2.5M）的单体 decoder-only Transformer，同数据、同步数、同 seed。
- **怎么验**：add_3d + add_1d（一个无泄漏、一个全记忆），单体 2 层 d=128 ff=512（算一下参数对齐到 2.5M），3000 步 × 2 seed = 4 run ≈ **10 分钟**，外加已完成的 S19-res 作对照。**判据**：单体 EM 与三类卡闭环的配对 Δ；若 \|Δ\| ≤ 1SE 且 2 seed 同号 ⇒ **框架无增量**（这是最重要的"能被证伪"）。**若失败说明什么**：若三类卡显著更好，那"卡片化"终于有了第一个不含混淆项的证据；若单体更好或持平，则整个 M2/M3 里程碑的前提要被重估。

### 【方案 4】把"数字 token 的 loss 权重"当第一变量，而不是把步数/容量当第一变量

- **我从哪条原始证据出发**：`logs/12_answer.log`「★数字CE(样本级)=2.1947±0.0198 n=739 ⇒ 数字每步正确率=11.1%」对「★每步正确率=exp(−CE)=**50.0%**」——**整体 CE 有一半来自模板/格式，数字只有 1/9**；`logs/19_res.log:32-33`（add_3d res）「①数字与算子: n=2843 占比=37.2% CE=0.6286」对「②模板/格式串: n=4000 占比=52.3% CE=0.0068」——**模板 CE 是 0.0068 nats，等于白送**；`logs/13_cap.log:249-250` 显示加 2 倍容量与加 2 倍步数都**不显著甚至变负**。
- **机制/为什么可能有效**：既然模板项已经饱和（占 52.3% 的 token、CE≈0.007），它就是在 loss 里当**常数**存在——不提供梯度，只稀释。而数字项占 37.2%、CE 0.6286，是可学的那部分。S13 已经试过"加大模型 / 加长训练"，都失败；**没试过"改目标"**。S13 日志自己提了这条（`logs/13_cap.log:252`「(a) 换目标形态/损失权重——把数字 token 加权…**使 CE 不被 `#### ` 模板 token 稀释**」）却从未执行。
- **与现有路线的差别**：现有在做什么——S13 扫容量 × 训练量；S15/S19/S20 扫结构。我建议换成——**只改 loss**：对 target 中的数字 token 乘权 w（w ∈ {1, 3, 10}），或在输出层对数字位置单独算 CE。结构、数据、步数一字不动。
- **怎么验**：add_3d（无泄漏）与 add_1d（全记忆）各 3 档 w × 2 seed = 12 run ≈ **30 分钟**。**判据**：数字**每步正确率**（不是整体 CE，因为整体 CE 会被权重改变定义）配对 Δ ≥ 2×SE 且 2 seed 同号。**若失败说明什么**：若加权后数字正确率纹丝不动，则"信息确实在 h 里、只是被稀释"被证伪 ⇒ 瓶颈在**输入卡没有把数字抽出来**（回到探测阶段，而不是继续改 loss）；若 add_1d 大涨而 add_3d 不动，则两个桶的瓶颈不同，是**另一个**重要发现。

### 【方案 5】把 batch 口径 bug 当**一等公民**处理：它是目前唯一被实测证实、却从未被修的框架 bug

- **我从哪条原始证据出发**：`logs/28_eval.log`「[S28-R28] e2e seed=1234: 混长度16条 一致 1/16 \| 等长(prompt_tok=24)16条 一致 **16/16** ⇒ batch 效应来自「右边补 PAD 使生成位置(n0+gen)偏离 lens+gen，PE 随 batch 组成变化」」；`logs/18_literal_out.log`「[CHK] 子集基线 EM：batch=16=**12.75%** vs batch=1=**96.62%**」；`logs/26_full.log`「模因 max\|Δ\|=5.245e-06 … ★有微小 batch 依赖（浮点归约序）」。
- **机制**：mask/PE 的实现让**同一条样本的预测结果依赖于同批次里其它样本的长度**。所有记录的 EM 都退回 batch=1（`logs/22_card.log:36` 等），这在**统计口径**上是合理的，但在**工程**上是掩盖：训练用 batch=32（`logs/19_res.log:5`），推理用 batch=1 ⇒ **训练与推理的位置编码语义不一致**。这可能是 add_3d 学不会的一部分原因——模型在训练时看到的位置分布与推理时不同。
- **与现有路线的差别**：现有在做什么——把 batch>1 判为"口径作废"然后全程用 batch=1。我建议换成——**定位并修掉 PE/mask 的 batch 组成依赖**，然后**重跑 S19 的 add_3d 两个 seed**，看 EM 是否移动。
- **怎么验**：① 用现成 ckpt 做逐位诊断：把同一批样本按不同长度顺序排列，看预测是否变化（零训练，CPU，<5 min）；② 修 `positions = (ids != PAD).cumsum(-1) - 1` 之后重训 add_3d res × 2 seed（**5 分钟**）。**判据**：修复后 `混长度16条 一致` 从 1/16 升到 16/16，且重训 EM 与 batch=1 基线配对 Δ 可测。**若失败说明什么**：若修完 EM 一点不动，则 batch 效应是纯推理期假象，与学习无关——**这条本身就是有价值的负面结论**（省下以后所有相关争论）；若 EM 动了，则此前所有"EM 只用 batch=1"的结论都要在此新口径下重核。

### 【方案 6】直接砍掉 GSM8K + 字符级截断这条线，把文本实验换成"数字位预测"

- **我从哪条原始证据出发**：`logs/11_textgen.log:110`「[S11-SUM] … 截prompt=264/7394(3.6%) 截target=3862/7394(52.2%)」＋ `[GEN] [0] ow many clips did Natalia sell…`（题干被左截，模型看到的是残题）＋ `[EXTRACT] 抽取方式计数 {'取不到': 2129, '####': 88}` ＋ `logs/09c_textgen_journal.txt` `[GEN] [0] 【tt  p      ttttsspsssspppppppppppppp详hottrtt…`（字符汤）＋ `logs/25_single.log:6`「[TOK] WordLevel V=8192」（词表不是 BPE）。
- **机制**：**52.2% 的 target 被截断**意味着模型在一半样本上被要求"续写一个你没有完整看到的目标"；**3.6% 的 prompt 被左截**意味着它在另一部分样本上看不到题干的开始。这两件事叠上字符级 WordLevel 词表，生成质量必然崩——**这不是"架构不会说话"，这是数据管线不允许它说话**。
- **与现有路线的差别**：现有在做什么——M1 用 GSM8K-CoT 当"会说话"的验收线，然后反复从架构侧找原因（S13 容量/步数、S15 残差）。我建议换成——**先用同一个闭环模型在一个不可能被截断的任务上证"会说话"**：`n` 位数字加法，输入 `a op b`（固定 ≤ 20 token），输出**逐位答案**且**每个数字位一个 token**；然后才谈 GSM8K。
- **怎么验**：三档长度 n∈{2,3,4} 位 × 2 seed，3000 步，≈6 run ≈ **15 分钟**。**判据**：训练 loss 必须单调下降（这是"能说话"的最低门槛，S12 就是败在这条）；数字每步正确率 ≥ 2×SE 高于"②最常见答案"地板。**若失败说明什么**：若连固定长度、无截断、纯数字输出的任务都不能把 loss 压下去，那"三类卡闭环"作为一个**能训练的架构**就是有问题的（而不是任务太难）——这会把矛头从"任务/数据"彻底转向"框架本身"。

### 【方案 7】评估口径：按答案分层重算 SE，并把"整体 CE 超地板"从主判据里彻底去掉

- **我从哪条原始证据出发**：`logs/19_res.log:8`「add_1d: … 答案域=0..18(19个) 计数train min/max=188/218 test min/max=31/46」、`:12`「add_3d: … 答案域=200..1998(1799个) …」——**800 条 test 里 add_1d 只有 19 个不同答案、add_3d 只有 1799 个中抽 800**；而所有 Δ 都按"逐 test 样本配对"算 SE（`logs/22_card.log:203`「★配对 Δ = EM(臂) − EM(A)，逐 test 样本配对，门槛 2×SE =」）。另一条：`logs/11_textgen.log:107`「[CRIT] seed=1234: ΔCE(闭环-地板)=**-8.5259±0.0103 显著低** \| ΔEM=**-1.89±0.50pp 不显著**」——**同一个模型，CE 显著赢、EM 显著输**，因为地板（常数预测 9.26 nats）整体 CE 天然不可能赢，而模板 token 把闭环 CE 拉低（模板 CE 只占 9.4%，`MILESTONES.md:59`）。
- **机制**：① 同答案的样本**不独立**，逐样本算 SE 会低估不确定性；用按答案聚类的 bootstrap（cluster bootstrap）重算，很多"Δ/SE=21.8"的结论会掉到 2 以下。② "整体配对 CE" 在 S11 的日志里已经被实测证明是**假指标**（显著赢 = 假，显著输 = 真）。既然 `MILESTONES.md:41` 已经写明"新口径改比数字/算子 token 的 CE"，那就应该把整体 CE 从**主判据**降为**附报**，并在文档里统一。
- **与现有路线的差别**：现有在做什么——门槛是"配对 Δ ≥ 2×SE + 2 seed 同号"，SE 来自逐样本配对。我建议换成——**聚类 bootstrap + 数字/算子 CE 作为唯一主判据**。
- **怎么验**：**零训练**。拿 `logs/19_results.jsonl` / `logs/22_results.jsonl` / `logs/25_results.jsonl` 里已存的 800 维 strict 向量（`logs/28_eval.log:95` 段「两份 strict 向量长度=800/800」说明它存在）重算 cluster-bootstrap SE，重跑所有 Δ/SE。**判据**：看有多少条结论的 \|Δ/SE\| 跌破 2。**若失败说明什么**：若几乎都不变，则现有 SE 是稳的，这条被证伪，且**顺手给全项目买回了一份"统计口径可信"**。

### 【方案 8（整体方案）】如果我从头做这个项目：**先证明会算，再谈卡片化；只在一个无泄漏任务上证伪自己**

- **我从哪条原始证据出发**：`logs/19_res.log:42/410/134/318/226`（四桶 61–97% ↔ add_3d 2.50%）＋ `logs/28_train.log:12`（唯一一次泄漏统计）＋ `logs/12_answer.log`（S12 训练不收敛）＋ `logs/11_textgen.log`（52.2% target 被截）＋ `logs/13_cap.log:249-250`（容量与训练量都不显著）＋ `logs/26_full.log` `[S26-VERDICT] PR 合并=3.1~4.5`（模因只有 3–5 个有效维度）＋ `logs/19_res.log:42`（**2.4 min/run**）。这六条合起来说的是同一件事：**这个项目的对照组太软、任务太容易记、指标太容易被模板买通，而它其实很便宜——便宜到可以在一天内重做全部关键对照。**
- **机制 / 我会怎么做（可执行，不是口号）**：
  1. **只留一个任务**：无泄漏的 n 位加法（两个操作数同位数、答案位数可预测），**输入输出都用数字位 token**（词表 ≈ 20，不用 8192 的 WordLevel，不用中文模板）。理由：`logs/19_res.log:12` 已经告诉我们 add_3d 是唯一 test 数对不与 train 共享的桶；而 `logs/13_cap.log:252` 的 (c) 早已建议"去掉 `####` 前缀"。
  2. **先做架构地板，再做卡片**：一个 2 层 d=128 单体 Transformer，参数对齐 2.5M，同 3000 步。**只有当三类卡闭环在配对 Δ ≥ 2×SE 且 2 seed 同号下超过这个地板，才允许谈"卡"**。理由：`MILESTONES.md` 已承认"关于框架本身的证据一半反对"；那就该有个地板。
  3. **损失目标单一**：只报 **答案严格 EM** 与 **每位数字正确率**；CE 只作附报。理由：`logs/11_textgen.log:107` `[CRIT]` 那一行已经把 CE 判死了。
  4. **对照组是默认项**：每个"我加的模块"都配"删掉它、其余不动"的 retrain-without；每个"我报的数字"都配 **SEEN/UNSEEN 拆分**。理由：`logs/28_train.log:12` 与 `logs/19_res.log:8-16` 的泄漏结构。
  5. **算力分配按证据强度，不按模块数**：`logs/19_res.log:42` 实测 2.4 min/run ⇒ 先跑 **8 个 run 的对照矩阵（20 分钟）**，再决定要不要跑 20 个。
  6. **每个器件只有一个家**：PE 只在输入卡加一次（避免 S20 那种"思维卡要不要加 PE"的分叉）；迭代默认 k=1（`logs/15_iter_always.log:174` k=8=0.12%）。理由：S20 实测 PE 重复注入直接 −34.88pp。
- **与现有路线的差别**：**现有**在做什么——在一个大部分桶有泄漏、目标被截一半、指标是模板 CE 的合成任务上，用 2.4 分钟/次的 run 反复改卡内结构（残差 → 迭代 → PE → 基型 → 锚定 → 单卡训练），并把这些改动的收益当作框架证据。**我建议换成**——先把任务的混淆项清零、先立一个架构地板、先把指标换成唯一答案型指标，**再**问"卡有没有用"。这会砍掉项目当前的 M1/M2 之外的全部里程碑，代价是要承认 S19–S30 的多数结论不可用于框架判断。
- **怎么验（怎么证伪我这条整体方案）**：把它当成一个**竞争假设**去跑：**在同一份 add_3d 数据上，单体 Transformer vs 三类卡闭环，各 2 seed**。**判据写死**：若单体 \|Δ\| ≤ 1SE 且两 seed 同号 ⇒ "卡片化"在最小可判任务上**零增量**；若闭环显著更好（Δ ≥ 2SE、2 seed 同号）⇒ 我的整体方案错了，**卡片化值得继续投入**。**成本：4 个 run ≈ 10 分钟单卡**。
- **若失败说明什么**：若闭环显著更好，那它终于有了一条**经过泄漏控制、指标干净、对照是架构地板**的证据——这是这个项目目前最缺的东西，比再多 t 一张卡的实验都值钱。
